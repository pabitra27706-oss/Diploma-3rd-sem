# Phase 1 — Tasks

Every part: evidence first, smallest correct change, acceptance recorded in
`record.md`. Screenshot the touched pages before and after — the gate checks
paths, not layout.

## 1.1 — Base-path sweep

**Why:** project Pages serves this repo at `/Diploma-3rd-sem/`; a root-relative
path points at `pabitra27706-oss.github.io/assets/…`, which is a 404.

**Steps**
1. `python3 scripts/check_site.py | grep 'root-relative'` — collect the full
   list by file (62 today).
2. Introduce one base-path constant per subsystem (or compute it from
   `location`), and rewrite each reference relative to the page, e.g.
   `../../assets/css/main.css`.
3. Fix `manifest.json`: `start_url: "./"`, `scope: "./"` (or
   `"/Diploma-3rd-sem/"`), icon `src` relative (`assets/pwa/…`).
4. Fix `sw.js`: registration-time scope, precache URLs relative to the SW
   location, `offline.html` fallback relative.
5. Fix every `fetch('/_data/…')` and `fetch('/_quiz-data/…')` to a relative
   path.

**Acceptance**
- `check_site.py --strict` reports 0 root-relative warnings.
- grep for `"(/assets|/_data|/_quiz-data|/manifest.json|/index.html)` returns
  only comments.
- Loading a practice and a quiz page under a simulated subpath resolves every
  asset (verified by the link checker against the repo root).

## 1.2 — PWA shell

**Why:** six 0-byte icons and a root-scoped worker mean install can fail and
offline never engages.

**Steps**
1. Replace six empty icons with real PNGs (192, 512, plus maskable variants);
   verify signature and dimensions, and that `sizes` matches the bytes.
2. Manifest: `id`, `name`, `short_name`, `description`, `lang`, `dir`,
   `display`, `theme_color`/`background_color` from tokens, `categories`.
3. Service worker: precache only existing shell files; versioned cache name;
   `activate` deletes old caches and claims clients; navigation fallback to
   `offline.html`; data requests stale-while-revalidate with a version query.
4. Verify the install criteria by reading the manifest: name, 192 + 512 icons,
   `start_url`, `display` standalone, HTTPS.

**Acceptance**
- Every manifest icon exists, is non-zero, and matches its declared size.
- Precache list ⊆ files that exist (script-checked).
- Offline: load → airplane mode → reload nested page → app shell renders.
- Cache version recorded in the phase record.

## 1.3 — Install and update UX

**Why:** `beforeinstallprompt` appears nowhere, so install is hidden in a menu;
`updatefound`/`controllerchange` appear nowhere, so a fixed bug can never reach
an installed user.

**Steps**
1. Add an "Install app" affordance that appears only when
   `beforeinstallprompt` fires; call `prompt()`, log the choice, hide after
   acceptance.
2. Hide it in `display-mode: standalone`.
3. Detect iOS/Safari (no event) and show the Share → Add to Home Screen steps
   instead.
4. Listen for `updatefound` → `installing.statechange === 'installed'` with an
   active controller, and for `controllerchange`; show a persistent
   "New version available — Reload" banner. Never auto-reload mid-quiz.
5. Show the build/cache version in the About or Professional Hub page instead
   of a hard-coded status.

**Acceptance**
- Code paths exist for Chromium, iOS, and standalone.
- Update banner appears for a deliberately bumped cache version (describe the
  test).
- No reload happens while an attempt is in progress.

## 1.5 — Web presence

**Why:** broken URLs get GitHub's default page; shared links have no preview;
crawlers get no canonical signal (`rel="canonical"`: 0 pages, `og:`: 0).

**Steps**
1. Add root `404.html` (GitHub Pages only honours the root copy).
2. Add `robots.txt` and a `sitemap.xml` **generated by a script** from the real
   file list, committed with a version line.
3. Add per-page `<link rel="canonical">` with the deployed absolute URL.
4. Add Open Graph/Twitter tags with one real screenshot, not a mock-up.
5. Add favicon + `apple-touch-icon`, and the iOS meta tags the app needs.

**Acceptance**
- All new files resolve under the base path.
- Sitemap lists only existing pages; regenerating it twice yields the same file.
- One shared link preview described in the record (manual check).

## 1.6 — Gate becomes strict

**Why:** a green checklist that ignores its own errors teaches people to ignore
CI.

**Steps**
1. Change the workflow to `python3 scripts/check_site.py --strict`.
2. Add `python3 scripts/validate_syllabus.py --strict` and
   `python3 scripts/validate_data.py` (if it exists) to the same job.
3. Delete the "fail on unresolved links if the tree is clean" advisory step and
   the baseline-mode comment.
4. Add a `budgets.txt` summary line to the job summary.

**Acceptance**
- CI green with `--strict` on the phase tip.
- A deliberately broken link fails CI (describe the test, then revert).
- The workflow contains no `continue-on-error` for correctness steps.
