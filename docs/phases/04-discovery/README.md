# Phase 4 — Discovery and sharing

**Status:** 🚧 implementation in progress · **Parts:** 5 · **Depends on:** 2 · **Owner gates:** none

## Goal

Make 55 pages, 992 questions and 872 quiz items findable in one box, make the
best question repeatable, and make a single question shareable in a class group
without an account.

## Why now — the measured evidence

- Search exists only **inside** PYQ and practice; there is no site-wide entry
  point (`search` hits are per-subsystem filters).
- The data already proves repetition: **86 duplicate clusters / 182 records**
  across papers — a student cannot see that today.
- No deep link per question and no `navigator.share`/clipboard use from a
  question view; `?q=` does not exist.
- Unit pages do not show the PYQs for their unit, so the "notes → practice"
  path is manual.
- Data volume is small enough for a client-side index: ~1.6 MB of PYQ JSON in
  total, largest single file 68 KB.

## Scope

- **In:** index generation, search UI, repeated-question explorer, deep links,
  share, unit↔PYQ linking, browse navigation.
- **Out:** spaced repetition (Phase 5), content quality (Phase 2), styling
  system (Phase 9).

## Parts

## Design constraints

- **Zero build:** the index is generated by a script and committed. Regeneration
  is a command, not a bundler.
- **Offline:** the index is precached and versioned; a stale index must not
  break results.
- **Base path:** every result link is relative.
- **No tracking:** queries never leave the device; no analytics on search terms.

## Done means

- `python3 scripts/build_search_index.py` produces a deterministic index;
  running it twice yields identical bytes.
- Search returns grouped results (notes, PYQ, quiz) with a count per group, in
  under 200 ms on a mid-range phone, offline.
- Every result has a working deep link; the target question is highlighted and
  scrolled into view.
- The repeated-question view lists the canonical question with its papers.
- A unit page links its own PYQs and its top topics.
- Share works where the API exists, with a copy-link fallback everywhere.

## Risks

- Indexing 1,800+ records into one file can regress first load; split by subject
  and load lazily (record the measured size).
- Duplicate clusters must be resolved in Phase 2 first, or search shows the same
  question three times.
- Deep links depend on stable ids; Phase 2.4's alias map is the contract.
