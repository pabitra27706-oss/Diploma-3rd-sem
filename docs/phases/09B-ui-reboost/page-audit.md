# Expanded page-by-page UI audit — 2026-11-17

Owner requested a **fuller visual redesign** of PYQ, quiz, practice and other pages, rather than a home-only refresh. This is source analysis plus the ten supplied phone screenshots, **not a render or a promise that source selectors look a particular way in a browser**. The same owner-selected reference is a preliminary unifying direction; clarify the owner's phrase “Only one reference add” before assuming it means one reference across all pages. No functionality, URLs, question content or saved data are to be removed.

## Cross-site causes

1. **Separate component languages.** Home uses `.app-header` and `.stat-card` (`index.html:122,188`); practice uses `.site-header`, `.action-btn`, `.chip`, `.q-card` (`practice/css/index.css:120,470,623`; `practice/css/session.css:389`); quiz uses `.site-header`, `.btn`, `.card`, `.chip` (`quiz/css/common.css:355,522,943,1195`); PYQ has distinct index/select/viewer/answer toolbars and question cards (`pyq/css/index.css:46,119`; `pyq/css/select.css:48,139`; `pyq/css/viewer.css:42`; `pyq/css/answers.css:171,494,591`). This is four families, not one systematic component set. **Proposed response:** shared visual contracts with scoped adapters, not a disruptive global selector rewrite.
2. **Quiz dark header needs investigation.** `quiz/css/common.css:1195–1213` sets a translucent white header and contains a malformed-looking combined selector / `@media` construct around its dark override. The owner's dark quiz screenshot shows a light header. It is a plausible source-level cause, not a confirmed rendered diagnosis. **Proposed response:** validate/fix the theme rule in its reviewed batch, test explicit light/dark/system and ask for before/after images.
3. **Widgets fall between systems.** Section notes generated in `assets/js/section-notes.js:26–57`, mistake queue in `quiz/js/mistakes.js`, and print button in `assets/js/accessibility.js:25–34` have no corresponding shared component styling found by CSS search (only `.section-note-indicator` and print-hide rules); screenshots show the note/queue/print controls looking disconnected. **Proposed response:** style their existing markup in every affected family, retaining save/clear/disabled/print behavior.
4. **Conflicting density and visual effects.** Practice alone specifies a 0.72rem subtitle and blur (`practice/css/index.css:120–168`), gradients, lift/scale and colored shadows (`:190–203,307–310,470–496,640–647`); quiz has separate gradients (`quiz/css/index.css:15–34`); PYQ uses another flatter system (`pyq/css/index.css:46–57,101–117`). **Proposed response:** simplify visual competition, align spacing and typography, maintain meaningful status cues and reduced motion.
5. **Crowded toolbars and overlays.** Home header carries four links plus theme/menu (`index.html:139–171`); practice session and PYQ answers have fixed or sticky controls (`practice/session.html:40–63,302–310`; `pyq/answers.html:167–207`); update panel has its own sticky layout (`assets/css/base.css:107–113`). The owner’s supplied home screenshot shows crowding and update-message overlap pressure. **Proposed response:** test layout together, preserve access to every action, no unsafe hiding of warnings.
6. **Token gate gap includes inline styles.** `pyq/index.html:62` contains an inline `rgba()` fallback; existing inventory counts only stylesheet declaration functions. **Proposed response:** extend checker/tests first across CSS and applicable HTML/JS before alpha migration; do not claim the CSS-only count includes the whole site.
