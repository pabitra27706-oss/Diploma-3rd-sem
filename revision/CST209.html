Big-O upper bound
f(n) = O(g(n)) if there exist c > 0 and n0 such that f(n) <= c*g(n) for all n >= n0
Symbols: f(n) = steps the algorithm performs on input size n, g(n) = comparison function, e.g. n or n log n, c = positive constant factor, n0 = input size from which the bound holds		f(n) is O(g(n)) when some constant c and threshold n0 make f(n) at most c·g(n) for every larger n.p.12: “Asymptotic notations: order (O), Omega, Theta, with examples”draft — unverified
Theta notationAn eventual tight bound with positive lower and upper constants; Theta is not average-case analysis.p.12: “Asymptotic notations: order (O), Omega, Theta, with examples”draft — unverified
Divide and conquerDivide an instance, solve smaller instances and combine; dynamic programming instead reuses overlapping states. The method alone does not determine running time.p.12: “Programming models: divide and conquer, greedy, dynamic programming”draft — unverified

Binary search worst case
worst-case comparisons ~ log2(n) + 1
Symbols: n = number of sorted elements searched, log2(n) = number of times n can be halved		On a sorted random-access array, binary search halves the interval; for n ≥ 1 the worst case uses at most floor(log2(n))+1 midpoint probes. Iteration needs O(1) auxiliary space; recursion O(log n).p.12: “Best, average and worst-case complexity of linear and binary search”draft — unverified
