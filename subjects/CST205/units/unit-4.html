Trees

Definition

A Tree is a non-linear hierarchical data structure consisting of nodes connected by edges. It is a collection of nodes linked together to simulate a hierarchy, with one node designated as the root and zero or more sub-trees hanging from it.

Real-World Examples
  • File System: Root directory → sub-directories → files
  • Organization Chart: CEO → Managers → Employees
  • HTML DOM: html → head/body → elements
  • Decision Tree: Root question → branches → leaf answers
A ← Root (Level 0) / \ B C ← Level 1 / \ / \ D E F G ← Level 2 (Leaves)

Tree Terminology

Node

A fundamental unit of a tree containing data and links to child nodes. Example: A, B, C above.

Root

The topmost node of a tree. Has no parent. There is exactly one root. Example: A.

Leaf (External Node)

A node with no children. Example: D, E, F, G in the diagram above.

Internal Node

A node that has at least one child. Example: A, B, C are internal nodes.

Parent

A node that has one or more children. Example: B is the parent of D and E.

Child

A node directly connected to its parent. Example: D and E are children of B.

Sibling

Nodes that share the same parent. Example: D and E are siblings (both children of B).

Level

Number of edges from root to that node. Root is at level 0. Example: B and C are at level 1.

Height of Node

Number of edges on the longest path from that node down to a leaf. Height of a leaf = 0.

Depth of Node

Number of edges from the root to that node. Root depth = 0. Same as level.

Degree of Node

Number of children a node has. Example: Degree of B = 2 (children D, E).

Edge

A link or connection between a parent node and its child node.

Path

A sequence of nodes where each adjacent pair is connected by an edge. Example: A→B→D.

Subtree

A tree formed by a node and all its descendants. Example: B with D and E is a subtree of A.

Height of Tree

Height of the root node, i.e., the longest path from root to any leaf.

Forest

A collection of disjoint trees. Removing the root creates a forest of subtrees.

Key Properties of a Tree
  • A tree with n nodes has exactly n-1 edges
  • There is exactly one path between any two nodes
  • A tree has exactly one root
  • Every node (except root) has exactly one parent
  • A tree is a connected acyclic graph (no cycles)
Tree Properties Formulas

Number of edges in a tree = n - 1 (where n = number of nodes)

Maximum nodes at level i = 2^i

Maximum nodes in binary tree of height h = 2^(h+1) - 1

Minimum height of binary tree with n nodes = ⌊log₂(n)⌋

Binary Trees

Definition

A Binary Tree is a tree in which each node has at most two children, referred to as the left child and the right child. A node can have 0, 1, or 2 children. It is the most common and widely used type of tree in computer science.

10 ← Root / \ 6 15 ← Level 1 / \ / \ 3 8 12 20 ← Level 2 (Leaves)

Representation of Binary Tree

1. Array Representation

How Array Representation Works

For a binary tree stored in an array (1-indexed):

  • Root is stored at index 1
  • For a node at index i:
    • Left child is at index 2i
    • Right child is at index 2i + 1
    • Parent is at index ⌊i/2⌋
Array Representation Formulas (1-indexed)

Root: index 1

Left child of node at i: 2 × i

Right child of node at i: 2 × i + 1

Parent of node at i: ⌊i / 2⌋

Array Representation Example

Tree: Root=10, Left=6, Right=15, 6's Left=3, 6's Right=8

Index 1 2 3 4 5
Value 10 (Root) 6 (Left of Root) 15 (Right of Root) 3 (Left of 6) 8 (Right of 6)

Verification: Node at i=2 (value=6): Left child = 2×2 = index 4 (value=3) ✓, Right child = 2×2+1 = index 5 (value=8) ✓

When to Use Array Representation
  • Best for: Complete binary trees (no gaps in the array)
  • Wasteful for: Skewed or sparse trees (many null positions wasted)
  • Advantage: O(1) access to parent/child using formula
  • Disadvantage: Fixed size, memory waste for non-complete trees

2. Linked List Representation

Node Structure

Each node in a linked binary tree contains three fields:

  • left: Pointer to left child (NULL if no left child)
  • data: The value stored in the node
  • right: Pointer to right child (NULL if no right child)
Binary Tree Node in C
struct TreeNode {
    int data;
    struct TreeNode* left;   // Pointer to left child
    struct TreeNode* right;  // Pointer to right child
};

// Create a new tree node
struct TreeNode* createNode(int data) {
    struct TreeNode* node = (struct TreeNode*)malloc(sizeof(struct TreeNode));
    node->data  = data;
    node->left  = NULL;
    node->right = NULL;
    return node;
}

// Build the tree from the diagram above
struct TreeNode* buildTree() {
    struct TreeNode* root = createNode(10);
    root->left            = createNode(6);
    root->right           = createNode(15);
    root->left->left      = createNode(3);
    root->left->right     = createNode(8);
    root->right->left     = createNode(12);
    root->right->right    = createNode(20);
    return root;
}

Insertion in Binary Tree

Algorithm: Insert in Level Order
1. If tree is empty, new node becomes root
2. Use a queue for level-order traversal
3. For each node dequeued:
   a. If left child is NULL, insert new node as left child → done
   b. Else, enqueue left child
   c. If right child is NULL, insert new node as right child → done
   d. Else, enqueue right child
4. Continue until insertion is done
C Code: Insert in Binary Tree (Level Order)
#include <stdio.h>
#include <stdlib.h>

struct TreeNode {
    int data;
    struct TreeNode *left, *right;
};

// Queue for level order insertion
struct QNode { struct TreeNode* tnode; struct QNode* next; };
struct QNode *qfront = NULL, *qrear = NULL;

void enqueue(struct TreeNode* t) {
    struct QNode* q = malloc(sizeof(struct QNode));
    q->tnode = t; q->next = NULL;
    if(!qrear) { qfront = qrear = q; return; }
    qrear->next = q; qrear = q;
}

struct TreeNode* dequeue() {
    if(!qfront) return NULL;
    struct QNode* q = qfront;
    struct TreeNode* t = q->tnode;
    qfront = qfront->next;
    if(!qfront) qrear = NULL;
    free(q); return t;
}

struct TreeNode* insert(struct TreeNode* root, int data) {
    struct TreeNode* newNode = malloc(sizeof(struct TreeNode));
    newNode->data = data; newNode->left = newNode->right = NULL;
    if(!root) return newNode;
    enqueue(root);
    while(qfront) {
        struct TreeNode* curr = dequeue();
        if(!curr->left) { curr->left = newNode; return root; }
        else enqueue(curr->left);
        if(!curr->right) { curr->right = newNode; return root; }
        else enqueue(curr->right);
    }
    return root;
}

Deletion in Binary Tree

Algorithm: Delete a Node
1. Find the node to be deleted (target)
2. Find the deepest rightmost node in the tree
3. Copy the data of deepest rightmost node into target node
4. Delete the deepest rightmost node
Steps to find deepest rightmost node:
  - Use level-order traversal (BFS with queue)
  - Last node visited is the deepest rightmost node
C Code: Delete Node from Binary Tree
void deleteDeepest(struct TreeNode* root, struct TreeNode* delNode) {
    // Queue-based BFS to find and remove deepest node
    enqueue(root);
    while(qfront) {
        struct TreeNode* curr = dequeue();
        if(curr == delNode) { curr = NULL; free(delNode); return; }
        if(curr->right) {
            if(curr->right == delNode) { curr->right = NULL; free(delNode); return; }
            else enqueue(curr->right);
        }
        if(curr->left) {
            if(curr->left == delNode) { curr->left = NULL; free(delNode); return; }
            else enqueue(curr->left);
        }
    }
}

struct TreeNode* deleteNode(struct TreeNode* root, int key) {
    if(!root) return NULL;
    if(!root->left && !root->right) {
        if(root->data == key) return NULL;
        return root;
    }
    struct TreeNode* keyNode = NULL;
    struct TreeNode* last = NULL;
    enqueue(root);
    while(qfront) {
        last = dequeue();
        if(last->data == key) keyNode = last;
        if(last->left)  enqueue(last->left);
        if(last->right) enqueue(last->right);
    }
    if(keyNode) {
        keyNode->data = last->data;
        deleteDeepest(root, last);
    }
    return root;
}

Tree Traversals

What is Tree Traversal?

Tree traversal is the process of visiting each node of the tree exactly once in a specific order. Unlike linear data structures (where traversal is straightforward), trees can be traversed in multiple ways.

1 ← Use this tree for all traversal examples / \ 2 3 / \ / \ 4 5 6 7

1. Pre-order Traversal (Root → Left → Right)

Definition

Pre-order traversal visits the root first, then recursively traverses the left subtree, then the right subtree. Order: Root → Left → Right

Algorithm: Pre-order
preorder(node):
1. If node is NULL, return
2. Visit (print) node
3. preorder(node->left)
4. preorder(node->right)
C Code: Pre-order
void preorder(struct TreeNode* node) {
    if(node == NULL) return;
    printf("%d ", node->data);   // Visit root
    preorder(node->left);        // Traverse left
    preorder(node->right);       // Traverse right
}
// Output for example tree: 1 2 4 5 3 6 7
Pre-order Trace
preorder(1):  Print 1 → preorder(2) → preorder(3)
preorder(2):  Print 2 → preorder(4) → preorder(5)
preorder(4):  Print 4 → NULL → NULL
preorder(5):  Print 5 → NULL → NULL
preorder(3):  Print 3 → preorder(6) → preorder(7)
preorder(6):  Print 6 → NULL → NULL
preorder(7):  Print 7 → NULL → NULL

Result: 1 2 4 5 3 6 7
Use of Pre-order
  • Used to copy a tree (process root before children)
  • Used to serialize a tree (store in a file)
  • Used in prefix expression evaluation

2. In-order Traversal (Left → Root → Right)

Definition

In-order traversal first recursively traverses the left subtree, then visits the root, then recursively traverses the right subtree. Order: Left → Root → Right

Algorithm: In-order
inorder(node):
1. If node is NULL, return
2. inorder(node->left)
3. Visit (print) node
4. inorder(node->right)
C Code: In-order
void inorder(struct TreeNode* node) {
    if(node == NULL) return;
    inorder(node->left);         // Traverse left
    printf("%d ", node->data);   // Visit root
    inorder(node->right);        // Traverse right
}
// Output for example tree: 4 2 5 1 6 3 7
In-order Trace
inorder(1):  inorder(2) → Print 1 → inorder(3)
inorder(2):  inorder(4) → Print 2 → inorder(5)
inorder(4):  NULL → Print 4 → NULL
inorder(5):  NULL → Print 5 → NULL
inorder(3):  inorder(6) → Print 3 → inorder(7)
inorder(6):  NULL → Print 6 → NULL
inorder(7):  NULL → Print 7 → NULL

Result: 4 2 5 1 6 3 7
Use of In-order
  • For Binary Search Trees (BST), in-order gives elements in sorted ascending order
  • Used to validate if a binary tree is a BST
  • Used in infix expression printing

3. Post-order Traversal (Left → Right → Root)

Definition

Post-order traversal first recursively traverses the left subtree, then the right subtree, and finally visits the root. Order: Left → Right → Root

Algorithm: Post-order
postorder(node):
1. If node is NULL, return
2. postorder(node->left)
3. postorder(node->right)
4. Visit (print) node
C Code: Post-order
void postorder(struct TreeNode* node) {
    if(node == NULL) return;
    postorder(node->left);       // Traverse left
    postorder(node->right);      // Traverse right
    printf("%d ", node->data);   // Visit root
}
// Output for example tree: 4 5 2 6 7 3 1
Post-order Trace
postorder(1): postorder(2) → postorder(3) → Print 1
postorder(2): postorder(4) → postorder(5) → Print 2
postorder(4): NULL → NULL → Print 4
postorder(5): NULL → NULL → Print 5
postorder(3): postorder(6) → postorder(7) → Print 3
postorder(6): NULL → NULL → Print 6
postorder(7): NULL → NULL → Print 7

Result: 4 5 2 6 7 3 1
Use of Post-order
  • Used to delete a tree (children deleted before parent)
  • Used to evaluate postfix (RPN) expressions
  • Used to compute size/height of tree

4. Level-order Traversal (BFS)

Definition

Level-order traversal visits all nodes at each level from left to right, starting from the root. It uses a queue and is essentially Breadth-First Search (BFS) applied to trees.

Algorithm: Level-order
1. If root is NULL, return
2. Enqueue root
3. While queue is not empty:
   a. Dequeue front node, print it
   b. If it has a left child, enqueue left child
   c. If it has a right child, enqueue right child
4. End
C Code: Level-order Traversal
void levelOrder(struct TreeNode* root) {
    if(!root) return;
    enqueue(root);
    while(qfront) {
        struct TreeNode* curr = dequeue();
        printf("%d ", curr->data);
        if(curr->left)  enqueue(curr->left);
        if(curr->right) enqueue(curr->right);
    }
}
// Output for example tree: 1 2 3 4 5 6 7
Summary of All Traversals
Traversal Order Output (Example Tree) Use Case
Pre-order Root → Left → Right 1 2 4 5 3 6 7 Copy tree, prefix expression
In-order Left → Root → Right 4 2 5 1 6 3 7 BST sorted output, infix expression
Post-order Left → Right → Root 4 5 2 6 7 3 1 Delete tree, postfix expression
Level-order Level by level 1 2 3 4 5 6 7 BFS, shortest path in unweighted tree

Types of Binary Trees

1. Full Binary Tree

Definition

A Full Binary Tree is a binary tree where every node has either 0 or 2 children. No node has exactly 1 child.

1 / \ 2 3 / \ 4 5 Full: Every node has 0 or 2 children ✓
Full Binary Tree Properties

If there are L leaf nodes, then internal nodes = L - 1

Total nodes = 2L - 1

2. Complete Binary Tree

Definition

A Complete Binary Tree is a binary tree where all levels are completely filled except possibly the last level, which is filled from left to right.

1 / \ 2 3 / \ / 4 5 6 Complete: Last level filled left to right ✓
Array Representation Best For

Array representation is most efficient for complete binary trees because there are no gaps in the array — every index from 1 to n is used.

3. Perfect Binary Tree

Definition

A Perfect Binary Tree is a binary tree where all internal nodes have exactly 2 children and all leaves are at the same level.

1 / \ 2 3 / \ / \ 4 5 6 7 Perfect: All leaves at same level, all internals have 2 children ✓
Perfect Binary Tree Properties

Total nodes = 2^(h+1) - 1 (where h = height)

Number of leaves = 2^h

Number of internal nodes = 2^h - 1

4. Balanced Binary Tree

Definition

A Balanced Binary Tree is a binary tree where for every node, the heights of the left and right subtrees differ by at most 1. AVL trees are self-balancing binary search trees.

Balance Factor

Balance Factor = Height(Left Subtree) - Height(Right Subtree)

For balanced tree: Balance Factor ∈ {-1, 0, +1}

If Balance Factor < -1 or > +1, the tree is unbalanced and needs rotation.

5. Degenerate (Skewed) Tree

Definition

A Degenerate or Skewed Tree is a tree where every internal node has only one child. It essentially behaves like a linked list. This is the worst case for a binary tree.

Left-Skewed: Right-Skewed: 1 1 / \ 2 2 / \ 3 3 Like a linked list — O(n) search time!
Why Skewed Trees are Bad

In a degenerate tree, operations like search, insert, and delete degrade to O(n) instead of O(log n), completely defeating the purpose of using a tree structure. This is why self-balancing trees like AVL were invented.

6. AVL Tree

Definition

An AVL Tree (named after Adelson-Velsky and Landis) is a self-balancing Binary Search Tree where the heights of the two child subtrees of any node differ by at most one. If at any time this property is violated, the tree is rebalanced through rotations.

AVL Tree Rotations

When the balance factor becomes less than -1 or greater than +1, one of four rotations is applied:

Case Imbalance Condition Rotation Applied
LL Case Left-Left (BF > 1, left child BF ≥ 0) Right Rotation
RR Case Right-Right (BF < -1, right child BF ≤ 0) Left Rotation
LR Case Left-Right (BF > 1, left child BF < 0) Left-Right Rotation
RL Case Right-Left (BF < -1, right child BF > 0) Right-Left Rotation
AVL Tree Complexity
OperationAverageWorst Case
SearchO(log n)O(log n)
InsertO(log n)O(log n)
DeleteO(log n)O(log n)

Note: Unlike regular BST (O(n) worst case), AVL guarantees O(log n) always.

7. B-Tree

Definition

A B-Tree is a self-balancing, multi-way search tree designed for systems that read and write large blocks of data (like databases and file systems). Unlike binary trees, B-Tree nodes can have more than two children.

B-Tree Properties (Order m)
  • Every node has at most m children
  • Every non-leaf node (except root) has at least ⌈m/2⌉ children
  • Root has at least 2 children (if not a leaf)
  • All leaves appear at the same level
  • A non-leaf node with k children has k-1 keys
Why B-Tree for Databases?
  • Minimizes disk I/O — each node is a disk block (large, stores many keys)
  • All leaves at same level — guaranteed O(log n) search
  • Used in MySQL, PostgreSQL, file systems like NTFS, ext4
  • Reduces tree height significantly compared to binary trees

Graphs

Definition

A Graph is a non-linear data structure consisting of a finite set of vertices (nodes) and a set of edges that connect pairs of vertices. A graph G is defined as G = (V, E) where V is the set of vertices and E is the set of edges.

Real-World Examples
  • Social Network: People = vertices, Friendships = edges
  • Road Map: Cities = vertices, Roads = edges (with distances as weights)
  • Internet: Computers = vertices, Connections = edges
  • Circuit Board: Components = vertices, Wires = edges
  • Flight Network: Airports = vertices, Routes = edges
Undirected Graph: Directed Graph (Digraph): V = {1,2,3,4} V = {A,B,C,D} E = {(1,2),(2,3),(3,4)} E = {(A→B),(B→C),(C→D),(D→A)} 1 ─── 2 A ──→ B | | ↑ | 4 ─── 3 D ←── C

Graph Terminology

Vertex (Node)

A fundamental unit of a graph representing an entity (person, city, computer). V = {1, 2, 3, 4}.

Edge

A connection between two vertices representing a relationship. E = {(1,2), (2,3)}.

Directed Graph (Digraph)

Edges have a direction (A → B means edge from A to B only, not B to A). Example: Twitter follows.

Undirected Graph

Edges have no direction (bidirectional). A-B means edge between A and B in both directions. Example: Facebook friendship.

Weighted Graph

Edges have weights (costs). Example: Road map where weight = distance between cities.

Degree of Vertex

Number of edges incident on the vertex. In digraphs: in-degree (edges coming in) + out-degree (edges going out).

Path

A sequence of vertices where each adjacent pair is connected by an edge. Example: 1→2→3→4.

Cycle

A path that starts and ends at the same vertex with no repeated edges. Example: 1→2→3→1.

Connected Graph

There is a path between every pair of vertices. All vertices are reachable from any vertex.

Disconnected Graph

Not all vertices are connected. Some vertices cannot be reached from others.

Strongly Connected

In directed graphs: there is a directed path from every vertex to every other vertex.

Adjacent Vertices

Two vertices are adjacent if they are connected by a direct edge.

Graph Representations

1. Set Representation

Set Representation

A graph is represented mathematically as two sets:

  • V: Set of all vertices
  • E: Set of all edges (pairs of vertices)

Example: G = (V, E) where V = {1, 2, 3, 4} and E = {(1,2), (2,3), (3,4), (4,1)}

2. Adjacency Matrix

Definition

An Adjacency Matrix is a 2D array of size n×n (where n = number of vertices). matrix[i][j] = 1 if there is an edge from vertex i to vertex j, else 0. For weighted graphs, matrix[i][j] = weight of edge.

Adjacency Matrix Example

Graph: Vertices {1,2,3,4}, Edges: 1-2, 2-3, 3-4, 4-1 (undirected)

1234
10101
21010
30101
41010

Note: For undirected graphs, the matrix is symmetric (matrix[i][j] = matrix[j][i]).

Adjacency Matrix in C
#define V 4

int graph[V][V] = {
    {0, 1, 0, 1},  // Vertex 1: connected to 2, 4
    {1, 0, 1, 0},  // Vertex 2: connected to 1, 3
    {0, 1, 0, 1},  // Vertex 3: connected to 2, 4
    {1, 0, 1, 0}   // Vertex 4: connected to 1, 3
};

void printMatrix() {
    printf("Adjacency Matrix:\n");
    for(int i = 0; i < V; i++) {
        for(int j = 0; j < V; j++) {
            printf("%d ", graph[i][j]);
        }
        printf("\n");
    }
}

3. Adjacency List

Definition

An Adjacency List represents a graph as an array of linked lists. For each vertex i, the list at index i contains all vertices adjacent to vertex i. It is memory-efficient for sparse graphs.

Adjacency List Example

Same graph: Vertices {1,2,3,4}, Edges: 1-2, 2-3, 3-4, 4-1

Vertex 1: → 2 → 4 → NULL
Vertex 2: → 1 → 3 → NULL
Vertex 3: → 2 → 4 → NULL
Vertex 4: → 3 → 1 → NULL
Adjacency List in C
#include <stdio.h>
#include <stdlib.h>
#define V 5

struct AdjNode {
    int dest;
    struct AdjNode* next;
};

struct AdjList {
    struct AdjNode* head;
};

struct Graph {
    int numVertices;
    struct AdjList* array;
};

struct Graph* createGraph(int v) {
    struct Graph* graph = malloc(sizeof(struct Graph));
    graph->numVertices = v;
    graph->array = malloc(v * sizeof(struct AdjList));
    for(int i = 0; i < v; i++)
        graph->array[i].head = NULL;
    return graph;
}

void addEdge(struct Graph* graph, int src, int dest) {
    // Add edge src → dest
    struct AdjNode* n = malloc(sizeof(struct AdjNode));
    n->dest = dest;
    n->next = graph->array[src].head;
    graph->array[src].head = n;
    // For undirected: also add dest → src
    n = malloc(sizeof(struct AdjNode));
    n->dest = src;
    n->next = graph->array[dest].head;
    graph->array[dest].head = n;
}

void printGraph(struct Graph* graph) {
    for(int i = 0; i < graph->numVertices; i++) {
        struct AdjNode* curr = graph->array[i].head;
        printf("Vertex %d: ", i);
        while(curr) {
            printf("→ %d ", curr->dest);
            curr = curr->next;
        }
        printf("NULL\n");
    }
}

Graph Traversals

Graph Traversal Overview

Graph traversal means visiting all vertices of a graph systematically. Unlike trees, graphs may have cycles, so we need to track visited vertices to avoid infinite loops. Two standard traversal algorithms are:

  • BFS — Breadth-First Search (uses a Queue)
  • DFS — Depth-First Search (uses a Stack or Recursion)
Example Graph for BFS and DFS: 0 / \ 1 2 / \ \ 3 4 5 Adjacency: 0→{1,2}, 1→{3,4}, 2→{5}

BFS — Breadth-First Search

Definition

BFS (Breadth-First Search) traverses a graph level by level. It starts from a source vertex and visits all its neighbors first, then all the neighbors of those neighbors, and so on. It uses a Queue (FIFO).

BFS Algorithm
BFS(graph, start):
1. Create a visited[] array, initialize all to false
2. Create an empty queue
3. Mark start as visited; enqueue start
4. While queue is not empty:
   a. Dequeue front vertex v; print v
   b. For each neighbor u of v:
      - If u is not visited:
        * Mark u as visited
        * Enqueue u
5. End
BFS in C (Adjacency Matrix)
#include <stdio.h>
#define V 6

int graph[V][V] = {
    {0,1,1,0,0,0},  // 0: connected to 1,2
    {1,0,0,1,1,0},  // 1: connected to 0,3,4
    {1,0,0,0,0,1},  // 2: connected to 0,5
    {0,1,0,0,0,0},  // 3: connected to 1
    {0,1,0,0,0,0},  // 4: connected to 1
    {0,0,1,0,0,0}   // 5: connected to 2
};

int visited[V];
int queue[V];
int front = -1, rear = -1;

void enqueue(int v) { queue[++rear] = v; }
int  dequeue()      { return queue[++front]; }
int  isEmpty()      { return front == rear; }

void BFS(int start) {
    for(int i = 0; i < V; i++) visited[i] = 0;
    front = rear = -1;

    visited[start] = 1;
    enqueue(start);
    printf("BFS: ");
    while(!isEmpty()) {
        int v = dequeue();
        printf("%d ", v);
        for(int u = 0; u < V; u++) {
            if(graph[v][u] == 1 && !visited[u]) {
                visited[u] = 1;
                enqueue(u);
            }
        }
    }
    printf("\n");
}

int main() {
    BFS(0);
    return 0;
}
// Output: BFS: 0 1 2 3 4 5

  • Finding the shortest path in an unweighted graph

DFS — Depth-First Search

Definition

DFS (Depth-First Search) traverses as far as possible along each branch before backtracking. It starts from a source vertex and goes deeper into the graph until it reaches a dead end, then backtracks. It uses a Stack (or recursion).

DFS Algorithm (Recursive)
DFS(graph, v, visited[]):
1. Mark v as visited; print v
2. For each neighbor u of v:
   - If u is not visited:
     * DFS(graph, u, visited)
3. End

Main:
1. Create visited[] array, all false
2. Call DFS(graph, start, visited)
DFS in C (Recursive)

    {0,1,0,0,0,0},

    }
}

Key Formulas

Tree Formulas

Number of edges = n - 1 (n = number of nodes)

Maximum nodes at level i = 2^i

Maximum nodes in binary tree of height h = 2^(h+1) - 1

Minimum height with n nodes = ⌊log₂(n)⌋

Number of leaf nodes in full BT = (n+1)/2

Array Representation of Binary Tree (1-indexed)

Root: index 1

Left child of node i: 2 × i

Right child of node i: 2 × i + 1

Parent of node i: ⌊i / 2⌋

Perfect Binary Tree

Total nodes = 2^(h+1) - 1

Leaf nodes = 2^h

Internal nodes = 2^h - 1

Height h = log₂(n+1) - 1

AVL Tree Balance Factor

Balance Factor = Height(Left Subtree) - Height(Right Subtree)

Valid AVL BF values: -1, 0, +1

If BF = +2 → Left heavy → Right rotation or Left-Right rotation

If BF = -2 → Right heavy → Left rotation or Right-Left rotation

Graph Formulas

Maximum edges in undirected graph = V(V-1)/2

Maximum edges in directed graph = V(V-1)

Sum of degrees = 2 × |E| (Handshaking Lemma)

Adjacency Matrix size = V × V

Adjacency List space = O(V + E)

BFS and DFS Time Complexity = O(V + E)

Key Definitions

Tree

A non-linear hierarchical data structure with nodes connected by edges. Has one root and no cycles.

Root

The topmost node of a tree. Has no parent. There is exactly one root per tree.

Leaf Node

A node with no children. Also called an external node or terminal node.

Height of Tree

The number of edges on the longest path from root to any leaf node.

Depth of Node

Number of edges from the root to that node. Root has depth 0.

Binary Tree

A tree where each node has at most two children: left child and right child.

Full Binary Tree

Every node has 0 or 2 children. No node has exactly 1 child.

Complete Binary Tree

All levels filled except possibly last, which is filled left to right.

Perfect Binary Tree

All internal nodes have 2 children and all leaves are at the same level.

Skewed Tree

Every node has only one child. Behaves like a linked list. Worst case for BST.

AVL Tree

Self-balancing BST where height difference between left and right subtrees ≤ 1.

B-Tree

Self-balancing multi-way tree. All leaves at same level. Used in databases/file systems.

Pre-order

Tree traversal: Visit Root, then Left subtree, then Right subtree. (Root→Left→Right)

In-order

Tree traversal: Left subtree, then Root, then Right subtree. (Left→Root→Right)

Post-order

Tree traversal: Left subtree, Right subtree, then Root. (Left→Right→Root)

Level-order

Tree traversal level by level using a queue. Also known as BFS for trees.

Graph

A non-linear data structure G=(V,E) with set of vertices V connected by edges E.

Directed Graph

A graph where edges have direction (one-way connection). Also called Digraph.

Undirected Graph

A graph where edges have no direction (bidirectional connection).

Weighted Graph

A graph where edges have weights/costs associated with them.

Adjacency Matrix

V×V 2D array where matrix[i][j]=1 if edge exists between i and j, else 0.

Adjacency List

Array of linked lists where each list stores neighbors of a vertex. Space: O(V+E).

BFS

Breadth-First Search — graph traversal level by level using a queue.

DFS

Depth-First Search — graph traversal along each branch using stack/recursion.

Cycle

A path in a graph that starts and ends at the same vertex.

Connected Graph

A graph where there is a path between every pair of vertices.

Degree of Vertex

Number of edges incident on the vertex. In digraphs: in-degree + out-degree.

Balance Factor

Height(left subtree) - Height(right subtree) of a node. Must be -1, 0, or +1 in AVL.

    printf("%d ", r->data);

    root->right->right= newNode(7);

Quick Revision

Quick Revision Points
  • Tree: Hierarchical, acyclic; n nodes → n-1 edges; one root.
  • Binary Tree: Each node has at most 2 children (left, right).
  • Array Representation (1-indexed): Left child = 2i, Right child = 2i+1, Parent = i/2.
  • Pre-order: Root→Left→Right. Used for copying tree.
  • In-order: Left→Root→Right. BST gives sorted output.
  • Post-order: Left→Right→Root. Used for deleting tree.
  • Level-order: Uses Queue, visits level by level.
  • Full BT: 0 or 2 children per node.
  • Complete BT: All levels filled; last level left to right.
  • Perfect BT: All leaves same level; total nodes = 2^(h+1)-1.
  • Skewed BT: Only one child per node; behaves like linked list.
  • AVL Tree: Self-balancing BST; Balance Factor ∈ {-1,0,+1}; 4 rotation types.
  • B-Tree: Multi-way, disk-optimized; all leaves at same level; used in databases.
  • Graph: G=(V,E); vertices + edges; may have cycles.
  • Directed Graph: Edges have direction (one-way).
  • Undirected Graph: Edges bidirectional; matrix is symmetric.
  • Adjacency Matrix: V×V array; O(V²) space; O(1) edge check.
  • Adjacency List: O(V+E) space; best for sparse graphs.
  • BFS: Uses Queue; level by level; finds shortest path.
  • DFS: Uses Stack/Recursion; deep first; cycle detection, topological sort.
  • BFS/DFS Time: O(V+E) for both.
  • Handshaking Lemma: Sum of all degrees = 2 × |E|.
Must Remember for Exams
  • Tree has n nodes → exactly n-1 edges — frequently asked in MCQs.
  • Array representation formulas: Left=2i, Right=2i+1, Parent=i/2 — memorize these.
  • All four traversals — practice writing them for any given tree.
  • Pre-order = Copy; In-order = Sort (BST); Post-order = Delete — remember these uses.
  • AVL Balance Factor must be -1, 0, or +1 — know the 4 rotation types.
  • BFS uses Queue (FIFO); DFS uses Stack/Recursion — very commonly asked.
  • BFS finds shortest path in unweighted graphs — important application.
  • DFS used for topological sorting and cycle detection — important application.
  • Adjacency Matrix: O(V²) space; Adjacency List: O(V+E) space — comparison table.
  • Skewed tree worst case = O(n) operations — reason AVL trees were invented.
  • Perfect BT: nodes = 2^(h+1) - 1; leaves = 2^h — important formulas.
  • B-Tree: all leaves at same level; used in MySQL, PostgreSQL, file systems.
Common Mistakes to Avoid
  • Confusing pre-order with post-order — pre visits ROOT first, post visits ROOT last.
  • In-order is Left→Root→Right, NOT Root→Left→Right — common mix-up.
  • Forgetting to mark nodes as visited in BFS/DFS — causes infinite loop in cyclic graphs.
  • Using wrong array index formula — always start index from 1 for standard formula.
  • Confusing Full BT (0 or 2 children) with Complete BT (filled left to right).
  • Thinking AVL tree rotation is always one type — there are 4 types (LL, RR, LR, RL).
  • Writing adjacency matrix as V×E instead of V×V — it is always V×V.
  • Treating a Tree as a Graph — trees are a special case of graphs (connected, acyclic).
  • Forgetting that undirected adjacency matrix is symmetric — matrix[i][j] = matrix[j][i].
  • Claiming BFS finds shortest path in weighted graphs — it only works for unweighted graphs.
