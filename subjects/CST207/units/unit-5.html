Addressing & Address Decoding

Why Address Decoding?

A microprocessor system typically has multiple memory chips and I/O devices. When the CPU sends an address on the address bus, only the intended chip should respond. Address decoding uses the upper address lines and logic circuits (decoders, gates) to generate a Chip Select (CS̄) signal that activates only the correct chip.

  • Address Bus: Carries the full address (20-bit in 8086).
  • Lower Address Lines: Used to select a specific location within a chip.
  • Upper Address Lines: Used to select which chip is activated via address decoding.
  • Chip Select (CS̄): Active LOW signal that enables a specific memory chip.
Address Decoding Techniques

1. Full Address Decoding (Absolute Decoding)

All address lines are used to uniquely identify each memory location. No address aliasing. Each memory address maps to exactly one physical location. More complex hardware but no wasted address space.

2. Partial Address Decoding

Only some upper address lines are used. Simpler hardware but creates address aliasing — the same memory chip responds to multiple address ranges. Some address space is wasted.

3. Using 74LS138 (3-to-8 Decoder)

The 74LS138 takes 3 address lines as input and produces 8 active-LOW output lines (Y̅0 to Y̅7). Only one output is LOW at a time. Each output is connected to CS̄ of a memory chip, enabling one chip at a time.

4. Using Logic Gates (AND, NAND, OR)

Simple address decoding using combinational logic gates. Upper address lines are inputs to gates. Output connected to CS̄. Example: NAND gate with A15, A14, A13 as inputs gives CS̄ LOW only when all three are HIGH (address range 0xE000–0xFFFF).

Address Range Calculation

To find the address range of a memory chip:

Steps
  1. Determine the chip capacity (e.g., 4 KB = 4096 bytes = 2¹² locations).
  2. Number of address lines needed for the chip = log₂(capacity) (e.g., 12 lines for 4 KB).
  3. These lower address lines (A0–A11) select locations within the chip.
  4. Remaining upper address lines (A12–A19 for 8086) are used for chip select (decoded).
  5. Start address: when all lower lines = 0 and upper lines match chip select pattern.
  6. End address: when all lower lines = 1 and same upper pattern.
Address Range Size
Address Range Size = Chip Capacity = 2n bytes

where n = number of address lines connected to the chip.

Example: 8 KB EPROM, CS̄ active when A19–A13 = 1111111

8 KB = 2¹³ bytes → needs 13 address lines (A0–A12).

A19–A13 = 1111111 → Upper bits fixed.

Start: 1111111 0000000000000 = FE000H

End:   1111111 1111111111111 = FFFFFH

Address range: FE000H to FFFFFH (8 KB)

Interfacing RAM, ROM, EPROM

Memory Interfacing Concepts

Memory interfacing means connecting memory chips to the microprocessor's address, data, and control buses so the CPU can read/write data. Key signals involved:

ROM (Read Only Memory) Interfacing

ROM is non-volatile memory that stores permanent data (BIOS, bootloader). It is read-only — the CPU can read but cannot write to ROM during normal operation.

  • Address lines: A0–An connected for location selection within the chip.
  • Data lines: D0–D7 (or D0–D15 for 16-bit) connected to data bus.
  • CS̄: Connected to address decoder output.
  • OĒ: Connected to CPU's RD̄ signal. Data output enabled only during read cycle.
  • WR̄ is NOT connected (ROM is read-only).
8086 ROM at Reset

After RESET, the 8086 starts execution from FFFF0H (CS=FFFFH, IP=0000H). ROM containing the bootstrap/BIOS code must be interfaced at the top of the address space (typically FE000H–FFFFFH).

RAM (Random Access Memory) Interfacing

RAM is volatile read/write memory. Both RD̄ and WR̄ signals are connected to enable both read and write operations.

  • Address lines: A0–An for location selection.
  • Data lines: D0–D7 (or D0–D15).
  • CS̄: From address decoder.
  • OĒ: Connected to RD̄ (output data during read).
  • WĒ: Connected to WR̄ (accept data during write).
EPROM (Erasable Programmable ROM) Interfacing

EPROM is non-volatile, can be erased using UV light, and reprogrammed using a programmer device. During normal system operation, it behaves like ROM (read-only). Common chips: 2716 (2 KB), 2732 (4 KB), 2764 (8 KB), 27128 (16 KB), 27256 (32 KB).

16-bit Bus Interfacing (Even/Odd Banks)

The 8086 has a 16-bit data bus and can access either a byte or a word. To support byte access at any address, memory is organized into two banks:

  • Even Bank (Lower Bank): Connected to D0–D7. Selected when A0 = 0. Contains bytes at even addresses (0, 2, 4, ...).
  • Odd Bank (Upper Bank): Connected to D8–D15. Selected when BHĒ = 0. Contains bytes at odd addresses (1, 3, 5, ...).
  • Word access (16-bit): Both banks active simultaneously when A0=0 and BHĒ=0.
  • Even byte access: Only even bank (A0=0, BHĒ=1).
  • Odd byte access: Only odd bank (A0=1, BHĒ=0).
Misaligned Word Access

Accessing a 16-bit word at an odd address requires two bus cycles because the word spans both banks at different addresses. This is slower. Keeping data word-aligned (at even addresses) avoids this penalty.

PPI 8255 – Programmable Peripheral Interface

What is the 8255 PPI?

The 8255 PPI is a general-purpose programmable I/O device that provides three 8-bit I/O ports (Port A, Port B, Port C) and a control register. It acts as an interface between the CPU and external I/O devices, allowing the CPU to communicate with peripherals like keyboards, displays, switches, and LEDs.

8-bit, Input or Output. Group B control. Latched output, non-latched input.
Port C (PC0–PC7)
8-bit, split into upper (PC4–PC7) and lower (PC0–PC3). Used as I/O or handshake control signals.
Control Register
8-bit. Write-only. Configures port direction and mode of operation.

Modes of Operation

The 8255 operates in three modes set by the control word:

Mode 0 — Basic I/O (Simple Input/Output)

Each port can be configured as input or output independently. No handshake signals. Data is simply read from input port or written to output port. Most commonly used mode. Port C can be split: upper half in one direction, lower half in another.

Mode 1 — Strobed I/O (Handshake)

Ports A and B are used for data I/O. Port C bits are used as handshake signals (STB̄, IBF, OBF̄, ACK̄, INTR). Data transfer is synchronized using these handshake signals. Used for devices that need acknowledge/ready signaling (printers, data acquisition).

Mode 2 — Bidirectional I/O (Port A only)

Port A becomes bidirectional — can both send and receive data on the same 8 lines. Port C bits provide handshake signals for bidirectional communication. Only Port A supports Mode 2. Port B can be in Mode 0 or Mode 1 simultaneously.

Control Word Format

The control word is an 8-bit value written to the control register (A1A0=11) to configure ports:

Cache Memory

What is Cache Memory?

Cache is a small, very fast memory placed between the CPU and main memory. It stores frequently accessed data and instructions to reduce the average memory access time. Based on the principle of locality of reference:

  • Temporal Locality: Recently accessed data is likely to be accessed again soon.
  • Spatial Locality: Data near recently accessed locations is likely to be accessed soon.
Hit, Miss, and Hit Ratio
Hit Ratio
Hit Ratio (h) = Number of Hits / Total Accesses
Miss Ratio = 1 − h
Average Memory Access Time
Tavg = h × Tcache + (1 − h) × Tmain

h = hit ratio, Tcache = cache access time, Tmain = main memory access time.

Cache Mapping Techniques

Cache mapping determines how main memory blocks are mapped to cache lines. There are three techniques:

Direct Mapping

Each main memory block maps to exactly one specific cache line. Line number = Block number MOD Number of cache lines. Simple hardware but may cause conflicts (two frequently used blocks mapping to same line).

Fully Associative

Any main memory block can be placed in any cache line. Most flexible — no conflicts. But requires comparing the tag of every cache line simultaneously (expensive hardware — needs content-addressable memory).

Set-Associative

Cache is divided into sets, each containing N lines (N-way). A block maps to a specific set (like direct) but can go in any line within that set (like associative). Best compromise. 2-way and 4-way are most common.

Direct Mapping — Address Breakdown

In direct mapping, the memory address is divided into three fields:

Tag
identifies block
Line / Index
selects cache line
Word Offset
selects word in block
Direct Mapping Formulas
Cache Line = Block Number MOD Number of Lines
Tag bits = Total address bits − Index bits − Offset bits
Index bits = log₂(Number of cache lines)
Example: 16-bit address, 256 cache lines, block size = 4 words

Offset bits = log₂(4) = 2 bits (to select word within block).

Index bits = log₂(256) = 8 bits (to select cache line).

Tag bits = 16 − 8 − 2 = 6 bits.

Address format: [6-bit Tag | 8-bit Index | 2-bit Offset]

Fully Associative Mapping — Address Breakdown

No index field needed — any block can go in any line. The entire address (minus offset) becomes the tag.

Tag bits = Total address bits − Offset bits
No index field needed. Tag compared with ALL cache lines simultaneously.

Cache is divided into sets. Set number = Block MOD Number of sets. Within a set, associative search is performed.

Virtual Memory

What is Virtual Memory?

Virtual memory is a memory management technique that provides the illusion of a much larger main memory by using disk storage as an extension of RAM. Programs use logical (virtual) addresses which are translated to physical addresses in RAM by the Memory Management Unit (MMU).

  • Logical Address (Virtual): Address generated by the CPU. This is what the program sees.
  • Physical Address: Actual address in physical RAM. Used to access memory hardware.
  • Page: Fixed-size block of virtual memory (e.g., 4 KB).
  • Frame: Fixed-size block of physical memory (same size as page).
  • Page Table: Maps virtual page numbers to physical frame numbers.
Address Translation Process
CPUGenerates Logical Address
→
MMUTranslates using Page Table
→
Physical MemoryRAM access at physical address
Translation Steps
  1. CPU generates logical address: [Page Number | Offset].
  2. Page number used as index into the Page Table.
  3. Page table entry gives the corresponding physical Frame Number.
  4. Physical address = [Frame Number | Offset] (offset stays same).
  5. If page is not in RAM (page fault), OS loads it from disk.
Address Breakdown
Page Number bits = log₂(Number of Pages)
Offset bits = log₂(Page Size)
Physical Address = Frame Number × Page Size + Offset
TLB — Translation Lookaside Buffer

The TLB is a small, very fast cache inside the MMU that stores recently used page table entries. It speeds up address translation by avoiding the page table lookup in main memory.

TLB Lookup Process
  1. CPU generates logical address with page number.
  2. MMU checks TLB for the page number (associative search).
  3. TLB Hit: Frame number found in TLB → physical address generated immediately (very fast).
  4. TLB Miss: Page table in RAM is consulted. Frame number fetched and stored in TLB for future use.
  5. Page Fault: If page not even in RAM, OS loads from disk (very slow).
Effective Memory Access Time with TLB
Teff = h × (TTLB + Tmem) + (1 − h) × (TTLB + 2 × Tmem)

h = TLB hit ratio. On hit: TLB + 1 memory access. On miss: TLB + 2 memory accesses (page table + actual data).

Page Table Entry Contents

Each entry in the page table contains:

FieldPurpose
Frame NumberPhysical frame where the page is stored in RAM
Valid/Present Bit1 = page is in RAM. 0 = page is on disk (page fault if accessed)
Modified/Dirty Bit1 = page has been written to (must be saved to disk before replacement)
Referenced/Accessed Bit1 = page has been read/written recently (used by replacement algorithms)
Protection BitsRead/Write/Execute permissions for the page
Example: 16-bit logical, 15-bit physical, page = 2 KB

Page size = 2 KB = 2¹¹ bytes → Offset = 11 bits.

Virtual pages = 2¹⁶ / 2¹¹ = 2⁵ = 32 pages → Page number = 5 bits.

Physical frames = 2¹⁵ / 2¹¹ = 2⁴ = 16 frames → Frame number = 4 bits.

Logical: [5-bit Page | 11-bit Offset]. Physical: [4-bit Frame | 11-bit Offset].

Page table size = 32 entries × (4 bits + control bits) per entry.

Key Definitions

Address Decoding

The process of using upper address lines and logic circuits (decoders, gates) to generate a Chip Select (CS̄) signal that activates only the intended memory chip or I/O device when the CPU outputs an address on the address bus.

Chip Select (CS̄)

An active-LOW signal generated by the address decoder that enables a specific memory chip or I/O device. Only the chip whose CS̄ is asserted LOW responds to the CPU's read or write operation.

EPROM (Erasable Programmable Read-Only Memory)

A type of non-volatile memory that can be erased by exposing it to ultraviolet light and reprogrammed using a special programmer device. During normal system operation, it functions as read-only memory. Common types: 2716, 2732, 2764.

PPI 8255

The Intel 8255 Programmable Peripheral Interface is a general-purpose I/O chip that provides three 8-bit I/O ports (Port A, B, C) and a control register. It can operate in three modes (Mode 0, 1, 2) and is used to interface the microprocessor with external I/O devices.

Cache Memory

A small, high-speed memory placed between the CPU and main memory that stores copies of frequently accessed data and instructions to reduce the average memory access time. It operates on the principle of locality of reference.

Hit Ratio

The fraction of memory accesses that are found in the cache (cache hits) out of the total number of memory accesses. A higher hit ratio means better cache performance. Hit Ratio = Hits / Total Accesses.

Virtual Memory

A memory management technique that creates the illusion of a very large main memory by using secondary storage (disk) as an extension of RAM. Programs use logical addresses which are translated to physical addresses by the MMU using page tables.

Page Fault

An exception that occurs when a program accesses a page that is mapped in the virtual address space but is not currently loaded in physical RAM. The operating system must load the required page from disk into a free frame in RAM.

TLB (Translation Lookaside Buffer)

A small, high-speed associative cache inside the MMU that stores recently used page table entries (page-to-frame mappings). It speeds up virtual-to-physical address translation by avoiding the slower page table lookup in main memory for frequently accessed pages.

Direct Mapping (Cache)

A cache mapping technique where each block of main memory can be placed in exactly one specific cache line, determined by: Line = Block MOD Number of Lines. Simple hardware but prone to conflict misses.

Multiple Choice Questions

Q 1

In direct-mapped cache, which formula determines the cache line for a memory block?

  • a. Block MOD Tag size
  • b. Block MOD Number of cache lines
  • c. Block MOD Offset bits
  • d. Block MOD Page size
Answer: b. Block MOD Number of cache lines

In direct mapping, each block maps to exactly one cache line determined by: Line = Block Number MOD Total Cache Lines. This is the index field of the address.

Q 2

The 8255 PPI has how many 8-bit I/O ports?

  • a. 2
  • b. 3
  • c. 4
  • d. 8
Answer: b. 3

The 8255 has three 8-bit ports: Port A (PA0–PA7), Port B (PB0–PB7), and Port C (PC0–PC7). Port C can be split into two 4-bit halves. Additionally, there is a control register (not an I/O port).

Q 3

A page fault occurs when:

  • a. Cache is full
  • b. An instruction has a syntax error
  • c. A referenced page is not in physical RAM
  • d. TLB is empty
Answer: c. A referenced page is not in physical RAM

A page fault occurs when the CPU accesses a virtual page whose valid bit is 0 in the page table — meaning the page is on disk, not in RAM. The OS must load it from disk.

Q 4

If cache access time is 10 ns, main memory access time is 100 ns, and hit ratio is 0.9, what is the average access time?

  • a. 19 ns
  • b. 55 ns
  • c. 90 ns
  • d. 110 ns
Answer: a. 19 ns

T_avg = h × T_cache + (1−h) × T_main = 0.9 × 10 + 0.1 × 100 = 9 + 10 = 19 ns.

Q 5

Which mode of 8255 allows Port A to operate as a bidirectional I/O port?

  • a. Mode 0
  • b. Mode 1
  • c. Mode 2
  • d. Mode 3
Answer: c. Mode 2

Mode 2 is bidirectional mode — only Port A supports this mode. Port A can both send and receive data on the same 8 lines. Port C bits provide handshake signals. There is no Mode 3 in 8255.

Q 6

In virtual memory, the TLB is used to speed up:

  • a. Disk access
  • b. Cache hit detection
  • c. Page table lookup (address translation)
  • d. Instruction decoding
Answer: c. Page table lookup (address translation)

TLB stores recent page-to-frame mappings. On TLB hit, the frame number is retrieved without accessing the page table in main memory, speeding up virtual-to-physical address translation.

Q 7

Which cache mapping technique requires content-addressable memory (CAM) for searching?

  • a. Direct mapping
  • b. Set-associative mapping
  • c. Fully associative mapping
  • d. None of the above
Answer: c. Fully associative mapping

In fully associative mapping, any block can be in any line. To find a block, the tag must be compared with ALL cache lines simultaneously. This requires Content Addressable Memory (CAM) — expensive hardware.

Q 8

In a 16-bit address system with 4 KB page size, how many pages are there?

  • a. 4
  • b. 16
  • c. 64
  • d. 256
Answer: b. 16

Virtual address space = 2¹⁶ = 64 KB. Page size = 4 KB = 2¹² bytes. Pages = 64 KB / 4 KB = 16 = 2⁴. Page number field = 4 bits.

Q 9

In 8086, the even memory bank is connected to data lines:

  • a. D8–D15
  • b. D0–D7
  • c. D0–D15
  • d. A0–A7
Answer: b. D0–D7

The even bank (lower bank) is connected to D0–D7 and is selected when A0=0 (even address). The odd bank (upper bank) is connected to D8–D15 and is selected when BHĒ=0 (odd address).

Q 10

The control word of 8255 with D7=1 indicates:

  • a. Port C bit set/reset mode
  • b. Mode set operation
  • c. Reset mode
  • d. Interrupt mode
Answer: b. Mode set operation

When D7=1 in the control word, it is a mode definition format — configuring port directions and operating modes. When D7=0, it is the bit set/reset format for individual Port C bits.

Q 11

An EPROM 2764 has a capacity of:

  • a. 2 KB
  • b. 4 KB
  • c. 8 KB
  • d. 16 KB
Answer: c. 8 KB

The 2764 EPROM has 8192 × 8 bits = 8 KB. It requires 13 address lines (A0–A12) and has 8 data lines (D0–D7). Common EPROMs: 2716=2KB, 2732=4KB, 2764=8KB, 27128=16KB, 27256=32KB.

Q 12

In set-associative mapping, a 4-way set-associative cache with 256 lines has how many sets?

  • a. 256
  • b. 128
  • c. 64
  • d. 32
Answer: c. 64

Number of sets = Total lines / Ways = 256 / 4 = 64 sets. Each set contains 4 lines. A block maps to one set (like direct mapping) but can go in any of the 4 lines within that set.

Short Answer Questions

Q 1

What is address decoding and why is it necessary?

Address decoding is the process of using logic circuits to generate a Chip Select (CS̄) signal for a specific memory chip based on the address output by the CPU. It is necessary because a microprocessor system has multiple memory chips and I/O devices sharing the same bus. Without address decoding, all chips would respond simultaneously, causing data bus contention and errors. Decoding ensures only the intended chip is activated for each address.

Q 2

What is the difference between full and partial address decoding?

Full decoding: All address lines are used. Each address uniquely maps to one memory location. No aliasing. More complex hardware required.

Partial decoding: Only some upper address lines are decoded. Multiple addresses can map to the same chip location (aliasing). Simpler hardware but wastes address space. Suitable for small embedded systems.

Q 3

What is the role of BHĒ in 8086 memory interfacing?

BHĒ (Bus High Enable) is used to select the odd (upper) memory bank connected to D8–D15. When BHĒ=0, the odd bank is enabled for data transfer through the upper byte of the data bus. Combined with A0, it determines the type of access: A0=0 & BHĒ=0 → word (16-bit), A0=0 & BHĒ=1 → even byte, A0=1 & BHĒ=0 → odd byte.

Q 4

Define hit ratio and miss ratio in cache memory.

Hit ratio (h): The fraction of total memory accesses found in cache. h = Hits / Total Accesses. Higher is better. Typical values: 0.85 to 0.99.

Miss ratio: 1 − h. The fraction of accesses NOT found in cache, requiring main memory access.

Q 5

What is a TLB and what problem does it solve?

TLB (Translation Lookaside Buffer) is a small, fast associative cache in the MMU that stores recently used page table entries. It solves the problem of slow address translation — without TLB, every memory access requires a page table lookup in main memory (adding 100+ ns). With TLB, most translations are done in 1–2 ns (TLB hit), significantly improving performance.

Q 6

What are the three modes of operation of the 8255 PPI?

Mode 0 (Basic I/O): Simple input/output without handshake. Each port independently configured as input or output.

Mode 1 (Strobed I/O): Handshake-based data transfer. Port C bits serve as control/status signals (STB̄, IBF, ACK̄, OBF̄).

Mode 2 (Bidirectional): Port A operates as bidirectional data port. Port C provides handshake. Only Port A supports Mode 2.

Q 7

What is the difference between a page and a frame in virtual memory?

Page: A fixed-size block in the virtual (logical) address space. The program is divided into pages. Page number is part of the logical address generated by the CPU.

Frame: A fixed-size block in physical memory (RAM). Same size as a page. The page table maps each virtual page to a physical frame. Frame number is part of the physical address sent to memory hardware.

Q 8

What is locality of reference? Name its two types.

Locality of reference is the tendency of programs to access a small portion of memory frequently over a short period. Two types:

Temporal Locality: If a location is accessed now, it is likely to be accessed again soon (e.g., loop variables).

Spatial Locality: If a location is accessed, nearby locations are likely to be accessed soon (e.g., array elements, sequential instructions).

Q 9

How is the control register of 8255 addressed? What are A1 and A0 values for each port?

The 8255 uses address lines A0 and A1 to select which port or register is accessed:

  • A1A0 = 00 → Port A
  • A1A0 = 01 → Port B
  • A1A0 = 10 → Port C
  • A1A0 = 11 → Control Register

If the base address of 8255 is 80H, then Port A=80H, Port B=81H, Port C=82H, Control=83H.

Q 10

What is address aliasing in partial address decoding?

Address aliasing occurs in partial address decoding when some address lines are not decoded. The same memory chip responds to multiple different addresses because the undecoded bits can be any value. For example, if A15 is not decoded, address 0000H and 8000H (differing only in A15) both access the same chip. This wastes address space but simplifies hardware.

Q 1

Explain the three cache mapping techniques — direct, fully associative, and set-associative — with address breakdown examples for each.

Given: 16-bit address, 128 cache lines, block size = 8 words.

Offset bits = log₂(8) = 3 bits for all three.

1. Direct Mapping

Each block maps to one specific line: Line = Block MOD 128.

Index bits = log₂(128) = 7 bits. Tag = 16−7−3 = 6 bits.

Address: [6-bit Tag | 7-bit Index | 3-bit Offset]

Simple hardware (one comparator per line). High conflict misses.

2. Fully Associative

Any block can go in any of 128 lines. No index field.

Tag = 16 − 3 = 13 bits.

Address: [13-bit Tag | 3-bit Offset]

Requires 128 parallel comparators (CAM). No conflict misses but expensive.

3. Set-Associative (4-way)

Sets = 128 / 4 = 32 sets. Each set has 4 lines.

Set bits = log₂(32) = 5 bits. Tag = 16−5−3 = 8 bits.

Address: [8-bit Tag | 5-bit Set | 3-bit Offset]

Block maps to specific set, placed in any of 4 lines. 4 comparators per lookup.

8255 PPI is a programmable I/O device with 3 ports and control register:

Q 4

Explain how to interface an 8 KB EPROM (2764) with the 8086 at address range F0000H–F1FFFH. Describe address decoding, pin connections, and signals used.

Address Range: F0000H to F1FFFH

Binary of F0000H: 1111 0000 0000 0000 0000 0

Binary of F1FFFH: 1111 0001 1111 1111 1111 1

Address Decoding:

  • A0–A12: Connected to EPROM address pins (select location within 8 KB).
  • A13–A19 = 1111000: Must be decoded to generate CS̄.
  • Use NAND gate or 74LS138 decoder to check A19=1, A18=1, A17=1, A16=1, A15=0, A14=0, A13=0.
  • When all match → CS̄ of 2764 goes LOW → chip is enabled.

Pin Connections:

  • A0–A12 → EPROM address pins
  • D0–D7 → EPROM data pins (connected to lower data bus D0–D7)
  • OĒ → Connected to 8086 RD̄ signal (output enable on read)
  • CS̄ → From address decoder output
  • WR̄ → NOT connected (EPROM is read-only)
  • VCC = +5V, GND = 0V

Q 5

Explain the concept of even and odd memory banks in 8086. Why is word-aligned access faster?

The 8086 organizes memory into two interleaved banks:

  • Even Bank (Lower): Connected to D0–D7. Selected when A0=0. Stores bytes at even addresses (0, 2, 4, ...).
  • Odd Bank (Upper): Connected to D8–D15. Selected when BHĒ=0. Stores bytes at odd addresses (1, 3, 5, ...).
Access TypeA0BHĒData BusBus Cycles
Word at even address00D0–D151 cycle
Byte at even address01D0–D71 cycle
Byte at odd address10D8–D151 cycle
Word at odd address——Split2 cycles!
Why Word-Aligned is Faster

A word at an even address spans both banks at the same address and can be read in one bus cycle (both banks active). A word at an odd address spans two different addresses across both banks — requiring two separate bus cycles (misaligned access). Therefore, keeping 16-bit data at even addresses (word-aligned) ensures single-cycle access, improving performance.

Q 6

Explain TLB with an example. How does effective memory access time change with TLB? Given: TLB access = 5 ns, memory access = 100 ns, TLB hit ratio = 0.95.

TLB Working:

  1. CPU generates logical address with page number.
  2. Page number searched in TLB (parallel/associative search).
  3. TLB Hit (95%): Frame found in TLB → Physical address = Frame + Offset → Access memory once. Total = T_TLB + T_mem = 5 + 100 = 105 ns.
  4. TLB Miss (5%): Access page table in memory (1st access) → get frame → access actual data (2nd access). Total = T_TLB + 2×T_mem = 5 + 200 = 205 ns.
Effective Access Time
T_eff = h × (T_TLB + T_mem) + (1−h) × (T_TLB + 2×T_mem)
= 0.95 × (5+100) + 0.05 × (5+200)
= 0.95 × 105 + 0.05 × 205
= 99.75 + 10.25
= 110 ns

Without TLB: every access = T_mem × 2 = 200 ns (page table + data). With TLB: 110 ns — 45% improvement.

Q 7

Explain the different page replacement scenarios during a page fault. What is the role of the dirty bit?

Page Fault Handling:

  1. CPU accesses a virtual page. Page table entry has Valid=0 → Page Fault.
  2. OS takes control. Finds the required page on disk.
  3. If free frame available: Load page from disk into the free frame. Update page table entry (frame number, Valid=1).
  4. If no free frame: Must replace an existing page. Page replacement algorithm (LRU, FIFO, etc.) selects a victim page.
  5. Dirty bit check: If victim page's dirty bit = 1 (modified), write it back to disk before overwriting. If dirty=0 (clean), simply overwrite — no write-back needed.
  6. Load new page into the freed frame. Update page table. Resume program.
Dirty Bit Role

The dirty (modified) bit indicates whether a page has been written to since it was loaded into RAM. If dirty=1, the page must be saved to disk before replacement (otherwise changes are lost). If dirty=0, the copy on disk is still valid and no write-back is needed. This saves disk I/O time and speeds up page replacement.

Revision & Quick Summary

Quick Revision Points
  • Address decoding: Upper address lines + decoder → CS̄ for specific chip. Only one chip active at a time.
  • Full decoding: All lines used, unique addresses. Partial: Some lines ignored, address aliasing.
  • 74LS138: 3-to-8 decoder. 3 input lines → 8 active-LOW outputs. Each output = CS̄ for one chip.
  • ROM: OĒ → RD̄. No WR̄ connection. EPROM erased by UV light.
  • RAM: Both OĒ → RD̄ and WĒ → WR̄ connected. Read/write memory.
  • EPROM sizes: 2716=2KB, 2732=4KB, 2764=8KB, 27128=16KB, 27256=32KB.
  • 8086 memory banks: Even bank → D0–D7, A0=0. Odd bank → D8–D15, BHĒ=0.
  • Word at even address: 1 bus cycle. Word at odd address: 2 bus cycles (misaligned).
  • 8255 PPI: 3 ports (A, B, C) + control register. Port select: A1A0 = 00→A, 01→B, 10→C, 11→Control.
  • 8255 Mode 0: Basic I/O. Mode 1: Strobed/handshake. Mode 2: Bidirectional (Port A only).
  • D7=1 in control word → mode set. D7=0 → Port C bit set/reset.
  • Cache: Small fast memory. Based on locality of reference (temporal + spatial).
  • Hit ratio h = Hits / Total. T_avg = h×T_cache + (1−h)×T_main.
  • Direct mapping: Line = Block MOD Lines. Address: [Tag | Index | Offset]. Simple but conflict misses.
  • Fully associative: Any block → any line. Address: [Tag | Offset]. Needs CAM. Best hit ratio.
  • Set-associative: Set = Block MOD Sets. N-way within each set. Address: [Tag | Set | Offset]. Best compromise.
  • Virtual memory: Logical → Physical via page table. Page = virtual block, Frame = physical block.
  • Address: Logical = [Page Number | Offset]. Physical = [Frame Number | Offset]. Offset unchanged.
  • Page fault: Page not in RAM → OS loads from disk. Very slow (ms).
  • TLB: Cache of page table entries. Speeds up translation. Hit → 1 memory access. Miss → 2 accesses.
  • T_eff with TLB = h(T_TLB + T_mem) + (1−h)(T_TLB + 2T_mem).
  • Page table entry: Frame number + Valid bit + Dirty bit + Referenced bit + Protection bits.
  • Dirty bit = 1 → page modified → write to disk before replacement. Dirty = 0 → no write-back needed.
Must Remember for Exam
  • T_avg formula: h × T_cache + (1−h) × T_main — most asked numerical.
  • Direct cache: Line = Block MOD Lines. Set-assoc: Set = Block MOD Sets.
  • Offset bits = log₂(Block Size). Index/Set bits = log₂(Lines or Sets).
  • Virtual: Pages = Virtual Space / Page Size. Frames = Physical Memory / Page Size.
  • TLB eff. time: h(T_TLB + T_mem) + (1−h)(T_TLB + 2T_mem).
  • 8255: A1A0 = 00→A, 01→B, 10→C, 11→Control. D7=1 → mode set.
  • EPROM: 2764 = 8 KB, 13 address lines, 8 data lines.
  • Even bank: A0=0, D0–D7. Odd bank: BHĒ=0, D8–D15.
Common Mistakes to Avoid
  • ❌ Confusing cache line (direct mapping index) with set (set-associative index).
  • ❌ Using wrong formula for T_avg — do NOT add T_cache + T_main for a hit. Hit = T_cache ONLY.
  • ❌ Forgetting that offset bits come from block size, not cache size or total lines.
  • ❌ Confusing page (virtual) with frame (physical) — they're same size but different spaces.
  • ❌ Saying TLB miss requires 3 memory accesses — it's 2 accesses (page table + data).
  • ❌ Forgetting that WR̄ is NOT connected to ROM/EPROM — they are read-only.
  • ❌ Confusing D7=1 (mode set) with D7=0 (bit set/reset) in 8255 control word.
  • ❌ Forgetting that word at odd address requires 2 bus cycles on 8086.
  • ❌ In virtual memory, offset bits are the same in both logical and physical addresses — only page/frame number changes.
  • ❌ Confusing full decoding (unique addresses, no aliasing) with partial decoding (aliasing, wasted space).
