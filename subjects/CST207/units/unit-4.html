Overview

How much this unit is worth

Assembly language programming carries only about four marks across the 2023–2026 papers, so this unit is a reference, not a revision priority. Read it after the 8086 addressing modes in Unit 3, because every program here is an addressing-mode exercise with a directive wrapper. The three things worth memorising are the segment skeleton, the effect of MOV/ADD on the flags, and the difference between a procedure and a macro.

How assembly is actually asked

The recent papers ask for a short instruction explanation or a two-mark comparison rather than a full program: what MOV and ADD change, why a segment register cannot take an immediate, and how a procedure differs from a macro. A complete program appears only occasionally, and then only for a simple sum or a loop.

Simple Programs

8086 Assembly Language Instructions: MOV, ADD and Arithmetic Programs

Every 8086 program is wrapped in the same skeleton: define the segments, tell the assembler which segment register points where with ASSUME, load DS at run time, do the work, then return to DOS. MOV copies a value and touches no flags; ADD writes the result back and sets the six status flags.

Add two 16-bit numbers held in memory
DATA SEGMENT
    A   DW 1234H
    B   DW 00FFH
    SUM DW ?
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA        ; segment address, not the data
    MOV DS, AX          ; DS cannot take an immediate
    MOV AX, A           ; AX <- 1234H
    ADD AX, B           ; AX <- 1234H + 00FFH = 1333H
    MOV SUM, AX
    MOV AH, 4CH         ; return to DOS
    INT 21H
CODE ENDS
    END START

Operand rules worth remembering

RuleExampleWhy
Source and destination must match in sizeMOV AX, BXMOV AX, BL is illegal
No memory-to-memory moveMOV AX, A then MOV B, AXThe CPU has one bus and one internal path
Immediate to segment register is illegalMOV AX, DATA / MOV DS, AXSegment registers take only register or memory operands
Result width1234H + 00FFH = 1333HNo carry out, so CF = 0, ZF = 0, SF = 0
32-bit addition on a 16-bit processor
; NUM1 and NUM2 are 32-bit values stored low word first
    MOV  AX, WORD PTR NUM1      ; low word of the first operand
    ADD  AX, WORD PTR NUM2      ; low halves; CF may be set
    MOV  RESULT, AX
    MOV  AX, WORD PTR NUM1+2    ; high word
    ADC  AX, WORD PTR NUM2+2    ; include the carry
    MOV  RESULT+2, AX

The low half uses ADD and the high half uses ADC; reversing them loses the carry and the answer is wrong by 65536 whenever the low halves overflow. The same pattern extends to any width.

Common errors in written answers
  • Starting a program with MOV DS, DATA — an immediate cannot be moved into a segment register.
  • Forgetting ASSUME, or believing it loads a register.
  • Missing END START, so the assembler cannot find the entry point.
  • Using ADD for the high word of a 32-bit sum instead of ADC.
  • Comparing signed values with JA/JB.
  • Leaving DX uncleared before a single-word DIV.

Logical Programs

Bit manipulation: AND, OR, XOR, TEST

AND clears bits (masking), OR sets bits, XOR toggles bits, and TEST performs an AND without writing the result — it only sets the flags, which makes it the standard way to test one bit before a jump.

Mask, set and test
    MOV  AL, [2000H]    ; read a byte from DS:2000H
    AND  AL, 0F0H       ; keep the high nibble, clear the low
    OR   AL, 05H        ; force bits 0 and 2 to 1
    XOR  AL, 0FFH       ; invert every bit
    TEST AL, 01H        ; ZF = 1 when bit 0 is 0
    JZ   EVEN           ; branch on the flag

XOR AX, AX is the shortest way to clear a register, and CMP is a subtract that keeps no result — both idioms appear in almost every exam program.

Swapping the two nibbles of a byte
    MOV  AL, [2000H]
    MOV  CL, 4
    ROL  AL, CL        ; move the high nibble into the low half
    MOV  [2000H], AL

A rotate of four positions exchanges the halves in one instruction. Four SHL/SHR pairs would need a second register, and a 4-bit rotate is impossible — ROL takes the count from CL.

Branch & Call Instructions

8086 Conditional Jumps, LOOP, CALL and RET

A jump changes IP; a conditional jump does so only when the named flag combination holds. LOOP is the compressed form of “decrement CX, jump while it is not zero”, and CALL is a jump that first pushes the return address.

Sum 1..5 with LOOP, then double the result with a procedure
    MOV  CX, 5          ; counter
    MOV  AX, 0
SUM:
    ADD  AX, CX         ; AX = AX + CX
    LOOP SUM            ; CX <- CX - 1, jump while CX != 0
    CALL DOUBLE         ; pushes the address of the next line
    MOV  RESULT, AX
    MOV  AH, 4CH
    INT  21H

DOUBLE PROC NEAR
    SHL  AX, 1          ; AX <- 2 x AX
    RET                 ; pops the return address into IP
DOUBLE ENDP
Three details that earn the marks
  • LOOP tests after decrementing, so a counter of 5 runs the body five times.
  • Signed comparisons use JG/JL; unsigned use JA/JB. Mixing them is the classic error.
  • A NEAR call pushes only IP; a FAR call pushes CS and then IP, and RET pops them in reverse order.

Sorting (Bubble Sort)

Bubble sort in outline

Bubble sort needs N − 1 passes; each pass compares adjacent elements, swaps them when they are out of order, and shrinks by one because the largest element has already settled at the end. For an array of words, a pointer register advances by 2 per step; for bytes, by 1.

Skeleton
  1. Load the count into CX and the array address into SI.
  2. Compare [SI] with [SI+2] using CMP.
  3. If the order is correct, skip; otherwise exchange the two words.
  4. Advance SI by 2 and repeat until the pass ends, then start the next pass.

CMP with JBE/JA sorts unsigned values; JLE/JG sorts signed ones.

One pass of bubble sort over words
    MOV  CX, N-1        ; comparisons in this pass
    MOV  SI, OFFSET ARR
NEXT:
    MOV  AX, [SI]
    CMP  AX, [SI+2]     ; compare adjacent words
    JBE  SKIP           ; already in order (unsigned)
    XCHG AX, [SI+2]     ; swap through AX
    MOV  [SI], AX
SKIP:
    ADD  SI, 2          ; next pair: 2 bytes per word
    LOOP NEXT

Wrap this pass in an outer count of N−1 passes and the array is sorted. XCHG needs a register operand, which is why the swap goes through AX.

Evaluation of Arithmetic Expressions

Evaluating an arithmetic expression

Evaluate (A + B) × C by working inside out: add first, then multiply, keeping the intermediate value in a register rather than in memory.

(A + B) × C
    MOV  AX, A
    ADD  AX, B          ; AX = A + B
    MOV  BX, C
    IMUL BX             ; DX:AX = AX x BX (signed)
    MOV  RESULT, AX     ; low word of the product

MUL is unsigned and IMUL is signed; both return the 32-bit product in DX:AX for 16-bit operands, so the high word is in DX. Before DIV, clear DX when the dividend is a single word.

Two products added: A×B + C×D
    MOV  AX, A
    IMUL B           ; DX:AX = A x B  (low word is enough here)
    MOV  SI, AX      ; keep the first product
    MOV  AX, C
    IMUL D           ; DX:AX = C x D
    ADD  AX, SI      ; add the two low words
    MOV  RESULT, AX

Because both products are assumed to fit in 16 bits, only the low word is kept. If they may not, the high words in DX must be saved and added with ADC as well.

String Manipulation

String instructions

A string instruction moves or compares one element and then updates the pointers automatically: SI addresses the source (DS:SI), DI the destination (ES:DI), and CX counts the repetitions.

InstructionOperationPointer updated
MOVSB / MOVSWCopy one byte or word from DS:SI to ES:DISI and DI
STOSB / STOSWStore AL or AX at ES:DIDI
LODSB / LODSWLoad DS:SI into AL or AXSI
CMPSBCompare DS:SI with ES:DI, set the flagsSI and DI
SCASBCompare AL with ES:DIDI

CLD clears DF so the pointers increment (forward); STD sets it so they decrement. REP repeats CX times, REPE while ZF = 1, and REPNE while ZF = 0. ES must be loaded explicitly before any destination string instruction.

Copying a string with REP MOVSB
    MOV  AX, DATA
    MOV  DS, AX
    MOV  AX, EXTRA
    MOV  ES, AX         ; ES must be loaded explicitly
    MOV  SI, OFFSET SRC
    MOV  DI, OFFSET DST
    MOV  CX, 20         ; number of bytes
    CLD                 ; increment SI and DI
    REP  MOVSB          ; repeat CX times

With STD instead of CLD the pointers walk backwards, so the copy starts at the end of both buffers. REP stops only when CX reaches zero; REPE and REPNE also stop on the zero flag, which is what makes CMPSB useful for comparing strings.

Counting the characters of a string
    MOV  AX, DATA
    MOV  DS, AX
    MOV  ES, AX
    LEA  DI, TEXT       ; DI points at the first character
    MOV  CX, 20         ; largest length we are willing to scan
    MOV  AL, '$'        ; terminator we are looking for
    CLD
    REPNE SCASB         ; scan forward while AL differs from ES:[DI]
    ; length = 20 - CX - 1 when the terminator was found

SCASB compares AL with the byte at ES:[DI], then either increments or decrements DI; REPNE repeats it while CX is not zero and the zero flag is clear. The scan therefore ends in one of two states, and both are examinable.

Trace: scanning for the terminator

Take the text HELLO$ and the listing above, so CX = 20 and DI starts at the first letter.

1H019+1repeat — still not the terminator

The length comes out as 20 − 14 − 1 = 5, which is HELLO without the terminator. If the terminator had been missing, the scan would have stopped with CX = 0 and ZF = 0 instead — that second ending is the one most answers forget to mention.

Three string-instruction traps
  • CX = 0 means 65,536 repetitions, not zero. The counter is tested after it is decremented, so a loop that starts with a cleared CX runs the full 16-bit range and then stops. Load CX before the REP, never after.
  • The direction flag is sticky. Nothing in the instruction sequence reloads DF, so a routine that leaves it set silently reverses the next string operation in the program. Clear it with CLD at the top of every routine that uses SI or DI.
  • REP is a prefix, not a jump. It must sit on the same line as the string instruction it modifies, and it cannot wrap a LOOP or a CALL. Writing REP over a block of two instructions assembles to a repeat of the first one only.

Assembler Directives

Assembler directives

A directive talks to the assembler, not to the CPU — it emits no machine code. That single sentence is the answer to the usual one-mark question.

DirectivePurposeNote
DB / DW / DDReserve 1, 2 or 4 bytes per valueDUP repeats a count
SEGMENT / ENDSOpen and close a logical segmentData, code, stack and extra segments
ASSUMETell the assembler which segment register addresses which segmentDoes not load any register
EQUDefine a constantOccupies no memory
ORGSet the location counterUsed for vector tables
ENDEnd of source; names the entry pointEND START

A minimal program therefore needs a data segment, a code segment, ASSUME, an END with a start label, and a run-time instruction sequence that loads DS — because ASSUME is only a promise to the assembler.

Reserving data with DUP
DATA SEGMENT
    ARR   DW 10 DUP(0)      ; ten words, all zero
    NAME  DB '8086', '$'     ; string terminated for DOS output
    COUNT DB 05H
DATA ENDS

DUP repeats a value a stated number of times, which is how an uninitialised array is reserved without listing every element.

Procedures & Macros

Assembler Directives, Procedures and Macros

A procedure lives once in memory and is reached with CALL; a macro is text the assembler copies into every place it is used. The procedure saves memory, the macro saves the call/return cycles and the register shuffling — and that trade-off is the usual exam question.

Procedure
SQUARE PROC NEAR
    PUSH BX             ; preserve the caller's register
    MOV  BX, AX
    IMUL BX             ; DX:AX <- AX x AX
    POP  BX
    RET
SQUARE ENDP
The same work as a macro
SQUARE MACRO
    MOV  BX, AX
    IMUL BX             ; expanded in place at every use
    ENDM

    SQUARE              ; the assembler pastes the two lines here

Program sizeSmallerLarger as uses grow

Use whenThe routine is long or called many timesThe fragment is two or three instructions
Passing parameters

Short routines pass values in registers, which is fast but destroys them unless they are pushed first. Longer ones pass through the stack: the caller pushes the arguments, the callee reads them with MOV BP, SP and [BP+4], and RET n discards them. Either way the callee must preserve any register the caller still needs.

Same-segment and far calls
CALL NEAR_PROC      ; pushes IP only; the callee is in this segment
CALL FAR PTR REMOTE ; pushes CS then IP; RETF pops both
CALL ADD_TWO        ; returns with RET 4 if the caller pushed two words

The RET n form adds n to SP after popping the return address, which discards the arguments the caller pushed — the usual convention for stack-passed parameters.

Syntax Reference & Key Rules

Instruction templates
MOV dst, src   (no flags changed)
ADD dst, src   SUB dst, src   CMP dst, src
MUL / IMUL src  →  DX:AX = AX × src
DIV / IDIV src  →  AX = quotient, DX = remainder
CALL: pushes IP (NEAR) or CS:IP (FAR); RET pops them back
Flag rules to quote

ADD/SUB set CF, ZF, SF, OF, PF and AF. INC/DEC set every flag except CF. MUL/DIV leave the other flags undefined.

Key Definitions

Definitions

Assembler: a program that translates mnemonic source into machine code, resolving labels and directives.

Directive: an instruction to the assembler that produces no machine code.

Procedure: a named block reached with CALL and left with RET; exists once in memory.

Macro: a named block of source text expanded inline at every invocation.

Label: a symbolic address; NEAR labels are within the segment, FAR labels outside it.

Effective address: the offset the CPU computes from the operands before adding the segment base.

Segment override: a prefix that makes an operand use a segment register other than its default.

Repeat prefix: REP, REPE or REPNE, which turns a one-element string instruction into a loop over CX.

Multiple Choice Questions

Q 1

Which instruction adds two operands while including the carry from a previous addition?

  • a. ADD
  • b. ADC
  • c. INC
  • d. SBB
Answer: b. ADC

ADC computes dst ← dst + src + CF, which is how a 32-bit sum is built from two 16-bit adds.

Q 2

MOV DS, 1000H is rejected by the assembler because —

  • a. 1000H is too large
  • b. a segment register cannot be loaded with an immediate
  • c. DS is read-only
  • d. MOV does not accept hex operands
Answer: b

Load through a general register: MOV AX, 1000H then MOV DS, AX.

Q 3

Which instruction branches by decrementing CX and jumping while it is not zero?

  • a. JNZ
  • b. LOOP
  • c. JMP
  • d. REP
Answer: b. LOOP

LOOP = DEC CX followed by JNZ to the label.

Q 4

A macro differs from a procedure because a macro —

  • a. is expanded inline at each use
  • b. is called with CALL
  • c. always saves memory
  • d. cannot contain instructions
Answer: a

The assembler pastes the body at every invocation, so the code is larger but there is no call overhead.

Q 5

After MUL BX on a 16-bit operand, the product is in —

  • a. AX only
  • b. DX:AX
  • c. BX:AX
  • d. CX:DX
Answer: b. DX:AX

The 16 × 16 product is 32 bits, so the high half goes to DX.

Q 6

ASSUME CS:CODE, DS:DATA does which of the following at run time?

  • a. Loads DS with the data segment address
  • b. Nothing — it only informs the assembler
  • c. Reserves the data segment
  • d. Sets the stack pointer
Answer: b

It is a directive. The program must still execute MOV AX, DATA and MOV DS, AX.

Short Answer Questions

Q 1

State the difference between ADD and ADC.

ADD dst, src computes dst + src. ADC dst, src computes dst + src + CF, so it carries the previous word's carry into the next word of a multi-precision addition.

Q 2

Why cannot a segment register be loaded directly with an immediate?

The 8086 encoding for MOV into a segment register has no immediate form. Use a general register: MOV AX, DATA then MOV DS, AX.

Q 3

What does TEST AL, 01H do, and how does it differ from AND AL, 01H?

Both compute a bitwise AND and set the flags, but TEST discards the result, leaving AL unchanged — which is what a bit test needs.

Q 4

Which registers must be set before MOVSB?

DS:SI for the source, ES:DI for the destination, and CX when REP is used. ES must be loaded explicitly because it cannot be assumed.

Long Answer Questions

Q 1

Write an 8086 program that adds two 16-bit numbers stored in memory and stores the sum.

Add two words
DATA SEGMENT
    A   DW 1234H
    B   DW 00FFH
    SUM DW ?
DATA ENDS
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX
    MOV AX, A
    ADD AX, B          ; 1333H
    MOV SUM, AX
    MOV AH, 4CH
    INT 21H
CODE ENDS
    END START

Six marks: correct segment skeleton, DS initialised at run time, operands fetched through DS, result stored, clean exit.

Q 2

Explain the difference between a procedure and a macro, with one example of each.

A procedure is written once and reached with CALL; the return address is pushed on the stack and RET pops it. A macro is a text template expanded inline by the assembler.

Procedure: SQUARE PROC NEAR → RET → SQUARE ENDP, called with CALL SQUARE. Macro: SQUARE MACRO → ENDM, used by writing SQUARE.

Trade-off: the procedure saves memory but costs call and stack cycles; the macro is faster but duplicates code.

Q 3

Write a loop that adds the numbers 1 to 5 and explain what LOOP does to CX.

    MOV CX, 5
    MOV AX, 0
SUM:
    ADD AX, CX
    LOOP SUM

LOOP decrements CX first and jumps when the result is non-zero, so the body runs five times and finishes with AX = 15 and CX = 0.

Practice Problems

Q 1

Write a program that clears the low nibble of a byte in memory and leaves the high nibble intact.

    MOV AL, [2000H]
    AND AL, 0F0H        ; mask: 1111 0000
    MOV [2000H], AL

The mask decides which bits survive: 1 keeps, 0 clears.

Q 2

State the value of AX and the flags after MOV AX, 0FFFFH followed by ADD AX, 0001H.

AX = 0000H, CF = 1 (carry out), ZF = 1 (result zero), SF = 0, and OF = 0 because both operands were treated as unsigned by this reasoning.

Q 3

How would you copy 100 bytes from DS:1000H to ES:2000H?

    MOV SI, 1000H
    MOV DI, 2000H
    MOV CX, 100
    CLD                 ; forward direction
    REP MOVSB

Q 4

Why must DX be cleared before DIV BX when the dividend is a single word?

DIV BX divides the 32-bit pair DX:AX by BX. Leaving stale bits in DX changes the dividend, so XOR DX, DX first.

Revision & Quick Summary

Twenty-second revision
  • Program skeleton: data segment, code segment, ASSUME, load DS, work, MOV AH,4CH / INT 21H, END START.
  • MOV never changes flags; ADD and SUB set all six status flags; INC/DEC leave CF alone.
  • AND masks, OR sets, XOR toggles, TEST tests without writing, CMP subtracts without writing.
  • Signed jumps JG/JL; unsigned jumps JA/JB.
  • LOOP = DEC CX + jump while CX ≠ 0.
  • MUL/IMUL give DX:AX; DIV/IDIV leave the quotient in AX and the remainder in DX.
  • Strings: DS:SI source, ES:DI destination, CX count; CLD forward, STD backward.
  • Directives emit no code; ASSUME is a promise, not a load.
  • Procedure = one copy plus CALL/RET; macro = inline copy at every use.
