Computer Structure

Computer Functional Units

A computer system is organized around three fundamental functional units that interact with each other to execute programs:

  • CPU (Central Processing Unit): The brain of the computer. It fetches instructions from memory, decodes them, and executes them. Contains the ALU, control unit, and registers.
  • Memory: Stores instructions and data. Primary memory (RAM/ROM) directly interacts with the CPU. Secondary memory stores data permanently.
  • I/O (Input/Output): Interfaces the computer with the external world. Includes keyboards, monitors, printers, disk drives, etc.
Von-Neumann Architecture

The Von-Neumann architecture (also called the stored-program concept) is the foundation of modern computers. Key features:

  • Stored Program Concept: Both instructions and data are stored in the same memory unit in binary form. The CPU fetches instructions from memory one by one and executes them sequentially.
  • Single Memory: Instructions and data share the same memory space and the same bus — this is called the Von-Neumann bottleneck.
  • Sequential Execution: Instructions are executed one at a time in order unless a branch/jump instruction changes the flow.
  • Components: Memory Unit, ALU, Control Unit, Input Device, Output Device.
Von-Neumann Bottleneck

Since both instructions and data share the same bus, only one can be transferred at a time. This limits performance. Harvard Architecture solves this by using separate buses and memory for instructions and data.

Bus Structures

A bus is a shared communication pathway connecting all functional units. There are three main types:

Bus Type Direction Width Purpose
Data Bus Bidirectional 8, 16, 32, 64 bits Carries actual data between CPU, memory, and I/O
Address Bus Unidirectional (CPU → Memory/IO) 16, 20, 32 bits Carries memory address to select location
Control Bus Bidirectional Varies Carries control signals: Read, Write, Interrupt, Clock
Addressable Memory
Addressable Memory = 2N locations

where N = number of address bus lines. Example: 20-bit address bus → 2²⁰ = 1 MB addressable memory.

Instruction Execution Cycle

The CPU repeatedly performs a fetch-decode-execute cycle for every instruction:

Steps of Instruction Cycle
  1. Fetch: PC (Program Counter) holds address of next instruction. MAR ← PC. Memory reads instruction into MDR. IR ← MDR. PC is incremented.
  2. Decode: Control Unit decodes the opcode in IR to determine what operation to perform.
  3. Execute: ALU performs the operation. Result stored in accumulator or register. Flags updated.
  4. Memory Access (if needed): Load/store instructions access memory in this step.
  5. Write Back (if needed): Result written back to register file.
Key Registers in Instruction Cycle
  • PC (Program Counter): Holds address of next instruction to fetch.
  • MAR (Memory Address Register): Holds address for memory operation.
  • MDR (Memory Data Register): Holds data read from or to be written to memory.
  • IR (Instruction Register): Holds the currently fetched instruction.
  • ACC (Accumulator): Holds intermediate ALU results.

Data Representation

Fixed-Point Numbers

In fixed-point representation, the binary point is assumed to be at a fixed position — either at the extreme right (integers) or at a defined position (fractions).

  • Unsigned integers: All bits represent magnitude. Range: 0 to 2ⁿ − 1 for n-bit number.
  • Sign-Magnitude: MSB is sign bit (0 = positive, 1 = negative). Remaining bits are magnitude.
  • 1's Complement: Negative number formed by inverting all bits. Has two representations of zero.
  • 2's Complement: Most widely used. Negative number = 1's complement + 1. Only one zero representation. Simplifies arithmetic.
2's Complement Ranges
n-bit 2's complement range: −2n−1 to +2n−1 − 1

Example: 8-bit → −128 to +127

Floating-Point Numbers

Floating-point representation is used for very large or very small numbers. A floating-point number has two parts:

Floating-Point Form
Number = Mantissa × BaseExponent
IEEE 754 Format Total Bits Sign Exponent Mantissa
Single Precision 32 bits 1 bit 8 bits 23 bits
Double Precision 64 bits 1 bit 11 bits 52 bits
IEEE 754 Biased Exponent

Exponent is stored in biased (excess) form to handle both positive and negative exponents. Bias = 127 for single precision, 1023 for double precision.

Stored Exponent = Actual Exponent + Bias

Error Detecting Codes

Parity Bits

A parity bit is an extra bit added to a binary data word to make the total number of 1s either even or odd, allowing single-bit error detection.

  • Even Parity: Parity bit is chosen so total number of 1s (including parity bit) is even.
  • Odd Parity: Parity bit is chosen so total number of 1s is odd.
  • Limitation: Can detect only single-bit errors. Cannot detect double-bit errors. Cannot correct errors.
Example

Data: 1011001 → Count of 1s = 4 (even)

Even parity bit = 0 (total stays even) → Transmitted: 0 1011001

Odd parity bit = 1 (to make total odd = 5) → Transmitted: 1 1011001

Hamming Code

Hamming code is an error-detecting and error-correcting code that can detect and correct single-bit errors. It inserts parity bits at specific positions (powers of 2) in the data word.

Hamming Code Construction Steps
  1. Determine number of parity bits (r) needed: 2r ≥ m + r + 1, where m = data bits.
  2. Parity bits are placed at positions 1, 2, 4, 8, 16, ... (powers of 2).
  3. Data bits fill the remaining positions.
  4. Each parity bit covers specific bit positions (those whose binary representation includes its bit position).
  5. Set each parity bit so that the total number of 1s in covered positions is even (even parity).
Parity Bit Count Formula
2r ≥ m + r + 1

For m=4 data bits: try r=3 → 2³=8 ≥ 4+3+1=8 ✅ → Need 3 parity bits → Total 7 bits

Error Detection using Hamming Code

At the receiver, recalculate all parity bits. Form a binary number (syndrome) from the results. If syndrome = 0, no error. If syndrome ≠ 0, the syndrome value indicates the bit position of the error → flip that bit to correct.

Register Transfer & Micro Operations

Register Transfer Language (RTL)

Register Transfer Language is a symbolic notation used to describe the movement of data between registers and the operations performed on that data. It provides a hardware-level description of digital systems.

RTL Notation Basics

R2 ← R1    Transfer contents of R1 to R2

R2 ← R1, if (T=1)    Conditional transfer (when control signal T is 1)

MAR ← PC    Transfer PC value to MAR

MDR ← M[MAR]    Read memory at address MAR into MDR

M[MAR] ← MDR    Write MDR contents to memory at MAR

Memory Transfers

Memory read and write operations are described using RTL:

Memory Read Operation
  1. MAR ← Address    (Load address into MAR)
  2. MDR ← M[MAR]    (Memory sends data to MDR)
  3. R ← MDR    (Transfer data to destination register)
Memory Write Operation
  1. MAR ← Address    (Load address into MAR)
  2. MDR ← R    (Load data into MDR from register)
  3. M[MAR] ← MDR    (Write MDR to memory)

Micro-Operations

What Are Micro-Operations?

A micro-operation is the most basic, elementary operation performed on data stored in registers. A single machine instruction may consist of several micro-operations. There are four types:

Arithmetic Micro-Operations
OperationRTL NotationDescription
AdditionR3 ← R1 + R2Add contents of R1 and R2, store in R3
SubtractionR3 ← R1 − R2Subtract R2 from R1 (using 2's complement)
IncrementR1 ← R1 + 1Add 1 to register R1
DecrementR1 ← R1 − 1Subtract 1 from register R1
Negate (2's comp)R1 ← R1' + 1Find 2's complement (negate) of R1
Logic Micro-Operations

Performed bit-by-bit on register operands. Used for masking, setting, and clearing bits.

OperationRTLEffectUse Case
ANDR1 ← R1 ∧ R2Bit-by-bit ANDMasking (clearing specific bits)
ORR1 ← R1 ∨ R2Bit-by-bit ORSetting specific bits
XORR1 ← R1 ⊕ R2Bit-by-bit XORToggling bits, comparing
ComplementR1 ← R1'Bit-by-bit NOT1's complement, logic inversion
Shift Micro-Operations
TypeDirectionWhat Happens
Logical Shift Left Left All bits shift left. 0 inserted at LSB. MSB lost. Equivalent to ×2.
Logical Shift Right Right All bits shift right. 0 inserted at MSB. LSB lost. Equivalent to ÷2 (unsigned).
Arithmetic Shift Left Left Same as logical shift left. MSB (sign) may change → overflow possible.
Arithmetic Shift Right Right Sign bit is replicated (copied) into MSB. LSB lost. Preserves sign for ÷2.
Circular Shift Left (Rotate) Left MSB wraps around to LSB. No bit is lost.
Circular Shift Right (Rotate) Right LSB wraps around to MSB. No bit is lost.
Key Difference

In arithmetic right shift, the sign bit is preserved (replicated). In logical right shift, 0 is always inserted at MSB regardless of sign. This is the most commonly confused point in exams.

Arithmetic Logic Shift Unit (ALU)

What is the ALU?

The Arithmetic Logic Shift Unit (ALSU / ALU) is a combinational digital circuit that performs all arithmetic micro-operations, all logic micro-operations, and all shift micro-operations in a single hardware unit. It is the computational core of the CPU.

The ALU takes two input operands (from registers), a set of function-select lines (from the control unit), and produces an output result along with status flags.

Arithmetic Ops

Add, Subtract, Increment, Decrement, Negate

Logic Ops

AND, OR, XOR, NOT / Complement

Shift Ops

Logical shift, Arithmetic shift, Circular shift

Status Flags

Zero (Z), Carry (C), Overflow (V), Sign (S)

Function Select Lines

The ALU uses select lines (S₀, S₁, ... Sₙ) from the control unit to choose which operation to perform. A multiplexer-based design routes the correct operation output to the result.

S₁ S₀OperationOutput F
0 0Transfer AF = A
0 1IncrementF = A + 1
1 0AddF = A + B
1 1SubtractF = A − B
ALU Status Flags
  • Zero (Z): Set when ALU result is 0.
  • Carry (C): Set when there is a carry out of the MSB (unsigned overflow).
  • Overflow (V): Set when signed arithmetic overflow occurs.
  • Sign (S) / Negative (N): Set when result is negative (MSB = 1 in 2's complement).

Key Definitions

Von-Neumann Architecture

A computer design model in which both instructions and data are stored in the same memory unit and accessed using the same bus, based on the stored-program concept proposed by John Von Neumann.

Register Transfer Language (RTL)

A symbolic notation used at the register level to describe the transfer of data between registers and the micro-operations performed on data during each clock cycle.

Micro-Operation

The most elementary operation performed on data stored in registers during a single clock pulse. A machine instruction consists of a sequence of micro-operations.

Hamming Code

An error-correcting code that inserts parity bits at positions that are powers of 2 in the data word, allowing detection and correction of single-bit errors and detection of double-bit errors.

ALU (Arithmetic Logic Unit)

A combinational digital circuit within the CPU that performs all arithmetic operations (add, subtract, etc.), logical operations (AND, OR, XOR, NOT), and shift operations on binary data.

Stored Program Concept

The idea that a computer program can be represented as data in the computer's memory, allowing the program to be modified or replaced without changing the hardware. This is the fundamental principle of modern computers.

Multiple Choice Questions

Q 1

The Von-Neumann architecture is based on which fundamental concept?

  • a. Harvard architecture
  • b. Stored program concept
  • c. Distributed processing
  • d. Parallel computation
Answer: b. Stored program concept

Von-Neumann architecture stores both instructions and data in the same memory, based on the stored-program concept.

Q 2

Which bus is unidirectional — from CPU to memory?

  • a. Data bus
  • b. Control bus
  • c. Address bus
  • d. System bus
Answer: c. Address bus

The address bus is unidirectional — the CPU sends addresses to memory or I/O. The data bus is bidirectional.

Q 3

How many parity bits are needed to protect a 4-bit data word using Hamming code?

  • a. 2
  • b. 3
  • c. 4
  • d. 1
Answer: b. 3

Using 2r ≥ m + r + 1: for m=4, r=3 → 8 ≥ 8 ✅. So 3 parity bits are needed. Total Hamming code length = 7 bits.

Q 4

In IEEE 754 single precision floating point, how many bits are used for the exponent?

  • a. 23
  • b. 11
  • c. 8
  • d. 1
Answer: c. 8

IEEE 754 single precision: 1 sign bit + 8 exponent bits + 23 mantissa bits = 32 bits total.

Q 5

Which arithmetic right shift operation preserves the sign bit of a 2's complement number?

  • a. Logical right shift
  • b. Circular right shift
  • c. Arithmetic right shift
  • d. Logical left shift
Answer: c. Arithmetic right shift

Arithmetic right shift replicates (copies) the sign bit (MSB) into the vacated MSB position, preserving the sign of the number.

Q 6

The register that holds the memory address for the next read/write operation is called:

  • a. Program Counter
  • b. Instruction Register
  • c. Memory Data Register
  • d. Memory Address Register
Answer: d. Memory Address Register (MAR)

MAR holds the address of the memory location to be accessed. MDR holds the actual data being read/written.

Q 7

Which logic micro-operation is used to selectively CLEAR (set to 0) specific bits of a register?

  • a. OR
  • b. XOR
  • c. AND
  • d. NOT
Answer: c. AND

AND with a mask clears bits where the mask has 0s and preserves bits where mask has 1s. This is called masking.

Q 8

If a computer has a 20-bit address bus, what is the maximum addressable memory?

  • a. 512 KB
  • b. 1 MB
  • c. 2 MB
  • d. 4 MB
Answer: b. 1 MB

2²⁰ = 1,048,576 = 1 MB. The 8086 microprocessor uses a 20-bit address bus giving 1 MB addressable memory.

Short Answer Questions

Q 1

What is the stored-program concept?

The stored-program concept states that a computer program is stored as binary data in the computer's memory. The CPU fetches instructions from memory one by one and executes them. This allows programs to be changed without altering hardware.

Q 2

What is the difference between the data bus and the address bus?

The data bus is bidirectional and carries actual data between CPU, memory, and I/O. The address bus is unidirectional (CPU to memory/IO) and carries the memory address to select a specific location.

Q 3

What is a micro-operation? Give one example.

A micro-operation is the most elementary operation performed on register data in one clock cycle. Example: R1 ← R1 + R2 (addition micro-operation that adds contents of R1 and R2 and stores result in R1).

Q 4

What is the purpose of parity bits in data transmission?

Parity bits are extra bits added to binary data to make the total count of 1s either even (even parity) or odd (odd parity). They allow the receiver to detect single-bit errors during data transmission by checking if the parity condition is satisfied.

Q 5

List the four types of micro-operations.

The four types of micro-operations are: (1) Register Transfer — moving data between registers. (2) Arithmetic — add, subtract, increment, decrement. (3) Logic — AND, OR, XOR, NOT. (4) Shift — logical, arithmetic, circular shifts.

Q 6

What is the Von-Neumann bottleneck?

The Von-Neumann bottleneck refers to the performance limitation caused by sharing a single bus between instructions and data in the Von-Neumann architecture. Since only one can be transferred at a time, the bus becomes a bottleneck limiting CPU speed.

Long Answer Questions

Q 1

Explain the Von-Neumann architecture with a neat block diagram description. What are its limitations?

Von-Neumann Architecture consists of five main components connected by buses:

  • Memory Unit: Stores both instructions and data in binary form in the same memory space.
  • ALU (Arithmetic Logic Unit): Performs arithmetic and logic operations on data.
  • Control Unit: Fetches instructions from memory, decodes them, and generates control signals.
  • Input Device: Feeds data and programs into the computer.
  • Output Device: Displays or stores results.

Working: The CPU repeatedly performs Fetch → Decode → Execute cycles. The PC holds the address of the next instruction. The instruction is fetched into IR, decoded by CU, and executed by ALU.

Limitations
  • Von-Neumann Bottleneck: Single shared bus for instructions and data limits throughput.
  • Sequential execution: Instructions execute one at a time (solved by pipelining).
  • Memory speed mismatch: CPU is much faster than memory, causing wait states.

Q 2

Explain Hamming code with an example. Encode the data 1011 using Hamming code and show how an error at bit position 5 is detected and corrected.

Step 1: Find number of parity bits

m = 4 data bits. Use 2r ≥ m + r + 1. For r=3: 8 ≥ 8 ✅. So r = 3 parity bits. Total bits = 7.

Step 2: Arrange bit positions (1 to 7)

Parity bits at positions 1, 2, 4. Data bits at positions 3, 5, 6, 7.

Pos1(P1)2(P2)3(D1)4(P4)5(D2)6(D3)7(D4)
Data 1011P1P21P4011

Step 3: Calculate parity bits (even parity)

  • P1 covers positions 1,3,5,7 → bits: P1, 1, 0, 1 → count of 1s = 2 → P1 = 0
  • P2 covers positions 2,3,6,7 → bits: P2, 1, 1, 1 → count of 1s = 3 → P2 = 1
  • P4 covers positions 4,5,6,7 → bits: P4, 0, 1, 1 → count of 1s = 2 → P4 = 0

Encoded Hamming code: 0 1 1 0 0 1 1

Error Detection: If bit 5 is flipped (0→1), received word = 0 1 1 0 1 1 1.

Recalculate parity. Syndrome = P4 P2 P1 = 1 0 1 = 5 in decimal → Error at position 5. Flip bit 5 to correct.

Q 3

Describe the instruction execution cycle with a step-by-step RTL description. What are the roles of PC, MAR, MDR, and IR in this cycle?

The instruction execution cycle (fetch-decode-execute cycle) is the sequence of operations the CPU performs to execute each instruction:

RTL Description of Instruction Cycle

Fetch Phase:

MAR ← PC  → Address of instruction sent to MAR

MDR ← M[MAR], PC ← PC + 1  → Instruction read; PC incremented

IR ← MDR  → Instruction loaded into IR

Decode Phase:

Control Unit analyzes opcode field of IR. Determines operation type and operand addresses.

Execute Phase:

MAR ← IR[address]  → Operand address sent to MAR (if memory operand)

MDR ← M[MAR]  → Operand fetched

ACC ← ACC + MDR  → ALU performs operation (example: ADD)

Register Roles
  • PC: Points to next instruction. Auto-increments after each fetch.
  • MAR: Interface to memory address bus. Holds address for any memory access.
  • MDR: Interface to memory data bus. Holds data being transferred to/from memory.
  • IR: Holds the complete current instruction being decoded and executed.

Original: 10110100

(a) Logical Right Shift by 2:

Insert 0s at MSB, shift right: 00101101

MSB sign not preserved. Two 0s inserted at left.

(b) Arithmetic Right Shift by 2:

Sign bit = 1, replicate it: 11101101

Two 1s inserted at left (sign preserved). Number ÷ 4 in signed representation.

(c) Circular Left Shift by 3:

Original: 10110100. The 3 leftmost bits (101) rotate to the right end.

Result: 10100101

No bits are lost in circular shift — they wrap around.

Revision & Quick Summary

Quick Revision Points
  • A computer has three functional units: CPU, Memory, I/O.
  • Von-Neumann: instructions and data in same memory, sequential execution.
  • Address bus is unidirectional; data bus is bidirectional; control bus carries control signals.
  • N-bit address bus → 2ᴺ addressable memory locations.
  • Instruction cycle: Fetch → Decode → Execute.
  • Key registers: PC (next instruction), MAR (memory address), MDR (memory data), IR (current instruction), ACC (ALU result).
  • 2's complement is most used: negate by inverting all bits then adding 1. Range: −2ⁿ⁻¹ to +2ⁿ⁻¹−1.
  • IEEE 754 single precision: 1 sign + 8 exponent + 23 mantissa = 32 bits. Bias = 127.
  • Parity bit detects single-bit errors only. Cannot correct errors.
  • Hamming code: parity bits at positions 1, 2, 4, 8, ... (powers of 2). Formula: 2ʳ ≥ m+r+1.
  • Hamming syndrome ≠ 0 → syndrome value = error bit position. Flip that bit to correct.
  • RTL notation: R2 ← R1 means transfer R1 to R2.
  • AND = masking/clear bits. OR = set bits. XOR = toggle bits. NOT = complement.
  • Arithmetic right shift: sign bit replicated. Logical right shift: 0 inserted at MSB.
  • Left shift by n = multiply by 2ⁿ. Right shift by n = divide by 2ⁿ.
  • ALU performs: arithmetic + logic + shift operations based on select lines from control unit.
  • ALU flags: Zero (Z), Carry (C), Overflow (V), Sign (S).
Must Remember for Exam
  • Hamming code formula: 2ʳ ≥ m + r + 1 — memorize this.
  • For 4 data bits → 3 parity bits → 7-bit Hamming code. For 8 data bits → 4 parity bits → 12-bit Hamming code.
  • Von-Neumann bottleneck = shared bus for instructions and data.
  • IEEE 754: Single precision exponent bias = 127. Double precision bias = 1023.
  • Arithmetic right shift preserves sign bit (replicate). Logical right shift inserts 0.
  • Address bus width determines maximum memory. Control bus carries Read/Write/Interrupt signals.
  • PC auto-increments after every instruction fetch.
Common Mistakes to Avoid
  • ❌ Confusing MAR (holds address) with MDR (holds data). They are different registers.
  • ❌ Confusing logical right shift (inserts 0) with arithmetic right shift (replicates sign bit).
  • ❌ Forgetting to add 1 when computing 2's complement — 1's complement alone is NOT 2's complement.
  • ❌ Hamming parity bit positions are powers of 2: 1, 2, 4, 8 — NOT 1, 2, 3, 4.
  • ❌ Syndrome value in Hamming code gives the position of error (1-indexed), not the bit index from 0.
  • ❌ Data bus width ≠ address bus width. They are independent. More address lines → more memory addressable.
  • ❌ Von-Neumann and Harvard architectures are different. Harvard uses separate instruction and data memory.
