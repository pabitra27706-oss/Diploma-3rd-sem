Console Input and Output

Console Input and Output: input(), print(), sep and end

input(prompt) always returns a string, whatever the user types. This is the single most examined fact in this section (2 marks): a program that asks for an age and then compares it to a number fails, because "25" > 18 raises TypeError. Convert first.

input() always gives you a str
name = input("Name: ")          # typing Asha
age = input("Age: ")            # typing 25 -- a str, not an int

print(type(age).__name__)       # str
print(age + "1")                # 251  -- string concatenation
print(int(age) + 1)             # 26   -- real arithmetic

# Two numbers on one line: split() then cast both
x, y = input("Two numbers: ").split()
print("sum:", int(x) + int(y))  # typing 7 8 prints sum: 15

Printed output — the values typed were Asha, 25, then 7 8. Prompts appear on the same line as what you type, so a terminal capture reads:

Actual output
Name: Age: str
251
26
Two numbers: sum: 15

print() takes any number of objects and three keyword arguments: sep (between objects), end (after the last one) and file (where to write). The defaults are a single space, a newline, and sys.stdout.

sep, end and file
print("a", "b", "c")                  # a b c      (sep default " ")
print("a", "b", "c", sep="-")         # a-b-c
print("2026", "11", "19", sep="/")    # 2026/11/19

print("no newline", end="")           # end default is "\n"
print(" continues here")              # no newline continues here

import sys
print("to stderr", file=sys.stderr)   # goes to stderr, not stdout
Python 2 note (for the viva, not for code)

In Python 2, raw_input() returned a string and input() evaluated what was typed as code — which is why old tutorials warn that input() is dangerous. In Python 3 the two were merged: input() returns a str and raw_input() no longer exists. print also became a function, so print "x" is a SyntaxError in Python 3.

Two formatting tools worth quoting in a 2-mark answer: format() with an alignment spec, and an f-string with a precision.

Alignment and rounding
print("{:>6}|{:<6}|{:^6}".format("ab", "ab", "ab"))
# "    ab|ab    |  ab  "   right, left, centre in 6 columns
print(f"{3.14159:.2f}")     # 3.14

File Handling

File handling is 34 of this unit's 49 marks (69%) — more than every other topic in Unit 4 combined. It is examined two ways: a 2-mark MCQ on which mode does what, and an 8-mark question that asks you to open, read, write and count in a file. This section covers both in the order the exam asks them.

File Opening, Access Modes, and Closing

open(path, mode, encoding) returns a file object. The mode decides three things: whether the file must already exist, whether its contents are erased on open, and where the read/write cursor starts. Getting these three right is the whole of the modes question.

Every one of those rows below was produced by running the mode on a 3-line file, so the numbers are the real tell() values:

The modes, measured
# demo.txt holds 18 characters. Each mode gets a FRESH copy, because
# 'w' and 'w+' truncate the file -- otherwise every mode after them
# would measure a 0-byte file and the table below would be wrong.
import os
open("demo.txt", "w").write("line1\nline2\nline3\n")   # 18 chars

for mode in ["r", "w", "a", "x", "r+", "w+", "a+"]:
    open("demo.txt", "w").write("line1\nline2\nline3\n")   # reset
    if mode == "x":
        os.remove("demo.txt")               # 'x' needs a missing file
    f = open("demo.txt", mode)
    print(f"{mode:>2}  tell={f.tell():<2}  readable={f.readable():<5}  writable={f.writable()}")
    f.close()
    if mode == "x":
        os.remove("demo.txt")

Two traps the exam sets

1. 'w' destroys the file the instant you open it — before you write anything. Opening an 18-character file in 'w' then closing it immediately leaves a 0-byte file. There is no undo.

2. 'x' is the only mode that refuses to overwrite. open("demo.txt", "x") on an existing file raises FileExistsError: File exists. Use it when a file must not be clobbered.

File object attributes and closing
f = open("demo.txt", "r")
print(f.name)      # demo.txt   -- the path you passed
print(f.mode)      # r          -- the mode string
print(f.closed)    # False
f.close()
print(f.closed)    # True

# Reading from a closed file is an error
f.read()           # ValueError: I/O operation on closed file

The with statement closes the file for you, even if an exception is raised inside the block. It is the form to write in an exam answer, because a forgotten close() leaks a file descriptor:

The with statement
with open("demo.txt", encoding="utf-8") as f:
    data = f.read()
# f is already closed here -- no close() call needed
print(f.closed)    # True

The File Word-Count Program, tell() and seek()

A 4-mark subpart asks for a program that counts the words in file.txt. Two correct answers exist and both are expected: the short one that reads the whole file, and the streaming one that never holds the file in memory.

Count words in file.txt — both versions
# Version 1 -- concise. Read everything, split on whitespace.
with open("file.txt", "r") as f:
    text = f.read()
print("Words:", len(text.split()))

# Version 2 -- streaming. Never holds more than one line.
count = 0
with open("file.txt", "r") as f:
    for line in f:
        count += len(line.split())
print("Words:", count)

# Related counts, same file
with open("file.txt", "r") as f:
    data = f.read()
print("Lines:", len(data.splitlines()))
print("Characters:", len(data))

For a file holding Python is easy to learn / It has simple syntax / Practice makes perfect:

Output
Words: 12
Words: 12
Lines: 3
Characters: 68
Why split() beats split(" ")

split() with no argument collapses runs of any whitespace — spaces, tabs and newlines together. split(" ") produces empty strings for double spaces and does not split at all on a newline, so it over-counts. len(text.split()) is the idiom to memorise.

tell() reports the cursor; seek(offset, whence) moves it. whence is 0 from the start (default), 1 from the current position, 2 from the end.

tell() and seek()
with open("seek.txt") as f:     # file holds ABCDEFGHIJ
    print(f.tell())             # 0
    print(f.read(3))            # ABC
    print(f.tell())             # 3
    f.seek(0)
    print(f.read(3))            # ABC  -- reset worked
    f.seek(5)
    print(f.read(3))            # FGH
    f.seek(0, 2)                # 2 = from end; 0 offset = EOF
    print(f.tell())             # 10
    print(repr(f.read()))       # ''   -- already at EOF
A real limitation worth knowing

In text mode you cannot seek to a negative offset from the end. f.seek(-2, 2) raises UnsupportedOperation: can't do nonzero end-relative seeks. Seek from the end only with a positive offset in text mode, or open in 'rb' where f.seek(-2, 2); f.read() correctly gives b'IJ'. Most textbooks and lab manuals omit this; quoting it in a viva is a differentiator.

Renaming and deleting are not file-object methods at all — they live in os, because they act on the directory entry, not on open content.

os.rename() and os.remove()
import os

os.rename("old.txt", "new.txt")    # move/rename in one step
print(os.path.exists("new.txt"))   # True
print(os.path.exists("old.txt"))   # False -- the name is gone

os.remove("new.txt")               # delete; raises FileNotFoundError if absent
print(os.path.exists("new.txt"))   # False
One line of safety, and no more

Opening a file that is not there raises FileNotFoundError. Guard it in one line — if os.path.exists("file.txt"): — or catch it with try/except. Exception handling is not part of this unit's syllabus (0 marks in 2023–2026), so do not build an answer around it.

Redirecting print() into a file

Anything print() can do to the screen it can do to a file, via file=. Useful for the practical file, where output must be saved:

with open("results.txt", "w") as f:
    print("Result 1: 42", file=f)
    print("Result 2: 85", file=f)

Regular Expressions

Regular expressions score 11 marks here — every paper asks for the same thing: explain pattern matching, then show re.match, re.search, re.findall and re.split on a sample string. Learn four return types and four methods and the section is finished.

Regular Expressions: Pattern Matching with re

A regular expression is a pattern that describes a set of strings. Instead of testing if s == "9876543210", you describe ten digits and match any string that fits: r"\d{10}". That is the definition to open an answer with.

Always write patterns as raw strings. In an ordinary string, "\d+" has \d interpreted by Python's string parser before re ever sees it; in r"\d+" the backslash reaches re intact. The two happen to be equal for \d, but not for \b, which is a backspace in a normal string and a word boundary in a raw one. Use r"..." every time and the question disappears.

The distinction examiners actually mark is match vs search. re.match only tries position 0; re.search scans the whole string. Everything else follows from that.

match, search, findall, split, sub
import re

s = "My number is 9876543210 and 12345"

print(re.match(r"\d+", s))          # None -- does not START with digits
print(re.match(r"My", s).group())   # My
print(re.search(r"\d+", s).group()) # 9876543210 -- first match anywhere

print(re.findall(r"\d+", s))        # ['9876543210', '12345']
print(re.findall(r"[aeiou]", "education"))   # ['e', 'u', 'a', 'i', 'o']

print(re.split(r"\s+", "a  b   c")) # ['a', 'b', 'c'] -- runs collapse
print(re.split(r"[,;]", "x,y;z"))   # ['x', 'y', 'z'] -- either separator

print(re.sub(r"\d+", "#", s))       # My number is # and #
print(re.sub(r"\d+", "#", s, count=1))  # only the first: # and 12345

The Match Object: group(), start(), end() and span()

A Match object is not a string. It carries the matched text plus its position, and that position is a separate 2-mark question: start() and end() give a half-open slice, which is exactly what Python slicing wants.

Reading a Match object
import re

s = "My number is 9876543210 and 12345"
m = re.search(r"\d+", s)

print(m.group())    # 9876543210  -- the matched text
print(m.start())    # 13          -- index of the first character
print(m.end())      # 23          -- index ONE PAST the last
print(m.span())     # (13, 23)    -- start() and end() as a tuple
print(s[m.start():m.end()])   # 9876543210 -- slicing with the span

# Groups: each (...) is captured separately
m2 = re.search(r"(\d+)\D+(\d+)", s)
print(m2.groups())  # ('9876543210', '12345')
print(m2.group(1))  # 9876543210
print(m2.group(2))  # 12345
print(m2.span(1))   # (13, 23) -- the span of group 1
The most common mark-loser in this section

re.match and re.search return None when nothing matches — they do not raise. So re.search(r"\d+", "abc").group() raises AttributeError: 'NoneType' object has no attribute 'group', which reads like a bug in the regex when it is really an unguarded call. Always write the guard:

m = re.search(r"\d+", text)
if m:
    print(m.group(), m.span())
else:
    print("no digits found")

Two more things the syllabus lists and the papers have not asked yet: modifiers and re.sub behaviour. They are short, so know them.

Flags (modifiers)
import re

print(re.findall(r"python", "Python PYTHON python", re.I))
# ['Python', 'PYTHON', 'python']  -- re.I ignores case

print(re.sub(r"^", "> ", "a\nb", flags=re.M))
# "> a\n> b"  -- re.M makes ^ match at every line start

print(re.findall(r"a.b", "a\nb", re.S))
# ['a\nb']  -- re.S lets . cross a newline (it does not by default)
FlagLong nameEffect
re.IIGNORECASEcase-insensitive matching
re.MMULTILINE^ and $ match at every line boundary
re.SDOTALL. also matches a newline

A worked use — a grep-style script that prints every line of a file matching a pattern. This is the practical-file script for the paired lab course and it exercises compile, search and error handling together:

grep.py — filter a file with a regex
import re, sys

pattern = sys.argv[1]
try:
    rx = re.compile(pattern)
except re.error as e:
    print("re.error:", e)
    sys.exit(1)

found = 0
for line in open("sample.txt"):
    if rx.search(line):          # search, not match -- any position
        found += 1
        print(line.rstrip())
print(f"-- {found} matching line(s)")

Three sentences that earn the marking points

1. “re.match returns a match only if the pattern is found at the beginning of the string; re.search scans the entire string.” 2. “re.findall returns a list of strings; re.search returns a Match object or None.” 3. “start() and end() return indices suitable for slicing: s[m.start():m.end()] reproduces the match.”

Key Definitions

File Object

The value returned by open(). It wraps the operating system's file handle and exposes methods for reading, writing and positioning a cursor. Read its state through .name, .mode and .closed.

File Mode

A short string passed as the second argument to open() that determines the file's permissions and initial cursor position. The base modes are 'r', 'w', 'a' and 'x'; '+' adds reading and writing together, 'b' selects binary and 't' text (the default).

File Cursor (File Pointer)

The position inside a file where the next read or write will happen. Every read and write advances it. tell() reports it; seek() sets it. Two different read methods on the same object share one cursor.

Context Manager

An object usable in a with statement that guarantees cleanup on exit — for files, close(), even when the block raised an exception. Using with open(...) as f: is the recommended way to work with files.

Truncation

The act of emptying a file to zero length. Opening an existing file in 'w' or 'w+' truncates it immediately on open, before any write occurs, so the previous contents are lost even if nothing is written.

Regular Expression

A pattern written in a formal mini-language that describes a set of strings. Python's re module compiles the pattern and matches it against text. Patterns are written as raw strings so backslashes reach re unchanged.

Pattern Matching

Testing a string against a regular expression to decide whether, where and how often it occurs. re.match tests only the start; re.search tests anywhere; re.findall returns every occurrence.

Match Object

The object returned by re.match or re.search when the pattern is found — None otherwise. It exposes group() for the matched text, start(), end() and span() for its position, and groups() for captured sub-patterns.

Meta-character

A character with special meaning inside a pattern rather than a literal meaning: . ^ $ * + ? { } [ ] \ | ( ). To match one literally it must be escaped with a backslash, as in r"\.".

Raw String

A string literal prefixed with r in which backslash sequences are not interpreted by Python. r"\d" is two characters, not a special character, which is why regular expressions are always written this way.

Modifier (Flag)

An option passed to re functions that changes how a pattern is interpreted: re.I ignores case, re.M makes ^ and $ match at every line boundary, re.S lets . match a newline.

Multiple Choice Questions

Q 1 What does f.read() return?
a. a list of lines
b. a single string containing the whole file
c. a bytes object
d. one line at a time
Answer: b. a single string

In text mode read() returns one str with every newline kept. Use readlines() for a list.

Q 2 f.readlines() returns …
a. a string
b. a tuple
c. a list of strings, one per line
d. a generator
Answer: c. a list of strings

Each item keeps its trailing \n. Verified: type(open(p).readlines()).__name__ gives 'list'.

Q 3 Opening an existing non-empty file in 'w' mode …
a. appends to the end
b. raises an error
c. leaves the content untouched
d. truncates it to zero length immediately
Answer: d. truncates it immediately

The loss happens on open(), before any write. Opening then closing a file in 'w' leaves it 0 bytes — measured.

Q 4 Which mode fails if the file already exists?
a. 'w'
b. 'a'
c. 'x'
d. 'r+'
Answer: c. 'x'

Exclusive creation raises FileExistsError. 'w' and 'a' silently overwrite or append.

Q 5 In mode 'a', where is the cursor when the file is opened?
a. at position 0
b. at the end of the file
c. undefined until the first write
d. at the last newline
Answer: b. at the end of the file

f.tell() right after open(f, "a") equals the file size — 53 on a 53-byte file, measured.

Q 6 f.write("abc") returns …
a. None
b. True
c. the number of characters written
d. the file object
Answer: c. the number of characters written

write("abc") returns 3. In contrast writelines() returns None.

Q 7 What does re.match(r"\d+", "abc123") return?
a. '123'
b. None
c. a Match object for '123'
d. []
Answer: b. None

match only tries position 0, and the string starts with letters. re.search would find '123'.

Q 8 re.findall(r"\d+", "a1 b22 c333") gives …
a. ['1', '22', '333']
b. ['1', '2', '2', '3', '3', '3']
c. '122333'
d. 3
Answer: a. ['1', '22', '333']

\d+ is greedy, so each run of digits is one match. Option b is what \d without + would give.

Q 9 For m = re.search(r"\d+", "abc123"), what is m.span()?
a. (3, 6)
b. (3, 5)
c. (4, 6)
d. (0, 3)
Answer: a. (3, 6)

start() is 3 and end() is one past the last character, so "abc123"[3:6] is '123'.

Answer: b. str, always

Typing 25 gives the string '25', so int(input()) is needed before arithmetic. This is the 2-mark MCQ the paper repeats.

Short Answer Questions

Q 1 What is the difference between read(), readline() and readlines()?

read() returns the entire remaining file as one string. readline() returns one line as a string, keeping the trailing \n, and moves the cursor to the next line. readlines() returns a list of strings, one item per line, each still carrying its \n.

The three share one cursor, so calling them in sequence continues where the last one stopped: after two readline() calls on a 3-line file, readlines() returns a list of one item.

Q 2 Explain any four file opening modes with their behaviour.

'r' — read only; the file must exist or FileNotFoundError is raised; cursor at position 0; the default mode.

'w' — write only; creates the file if missing and truncates it to zero length if it exists, before anything is written.

'a' — append; creates the file if missing, otherwise writes at the end; the cursor starts at end-of-file, so existing content is never overwritten.

'x' — exclusive creation; creates the file but raises FileExistsError if it already exists. The only mode that refuses to overwrite.

Q 3 Why is with open(...) as f: preferred over f = open(...) plus f.close()?

The with statement is a context manager: it calls close() automatically when the block ends, including when the block exits because of an exception. With a manual f = open(...), an error between open() and close() skips the close(), leaking a file descriptor; enough leaks exhaust the OS limit and later open() calls fail. The file is also closed sooner, releasing the lock on Windows. Writing with is therefore the recommended form in every exam answer.

Q 4 Differentiate re.match() and re.search().

re.match(pattern, string) tests the pattern only at position 0; if the string does not begin with a match it returns None without searching further. re.search(pattern, string) scans the whole string and returns the first match wherever it occurs.

On "abc123", re.match(r"\d+", s) returns None while re.search(r"\d+", s).group() returns '123'. Both return a Match object or None — never a string — so .group() is needed, guarded by if m:.

Q 5 What are raw strings and why are they used with regular expressions?

A raw string is prefixed with r and treats backslashes literally, so Python's own string parser does not consume them. In r"\d+" the re module receives the two characters \ and d; in an ordinary string, sequences such as \b or \n would be converted to a backspace or a newline before re ever saw them. Using r"..." for every pattern removes an entire class of bug, and it is the convention the syllabus expects.

Q 6 Write a program to count the number of words in a file.
with open("file.txt", "r") as f:
    text = f.read()
print("Words:", len(text.split()))

split() with no argument splits on any run of whitespace — spaces, tabs and newlines — so the count is correct across lines. The streaming version, sum(len(line.split()) for line in f), gives the same answer without holding the whole file in memory.

Q 7 What do tell() and seek() do?

tell() returns the current cursor position as a number of characters (bytes in binary mode) from the start of the file. seek(offset, whence) moves that cursor: whence=0 counts from the start (the default), 1 from the current position, 2 from the end.

f.seek(0) rewinds to the beginning — the usual way to re-read a file that has just been written in 'w+' mode. In text mode end-relative seeking must be zero: f.seek(-2, 2) raises UnsupportedOperation.

Long Answer Questions

Q 1 (8 marks) a) Explain the file opening modes in Python with examples. b) Explain how to read and write a file.

a) Modes. open(filename, mode) returns a file object; the mode fixes three things — whether the file must exist, whether it is emptied on open, and where the cursor starts.

'b' appends binary mode ('rb', 'wb') for images and other non-text data; 't' is text mode and is the default.

b) Reading and writing.

# Writing -- 'w' truncates first
with open("data.txt", "w") as f:
    f.write("Python is easy\n")          # returns 15 (chars written)
    f.writelines(["Files store data\n", "Regex finds patterns\n"])

# Reading -- four ways, one cursor between them
with open("data.txt", "r") as f:
    first = f.readline()                 # 'Python is easy\n'
    rest  = f.read()                     # everything after line 1
with open("data.txt", "r") as f:
    lines = f.readlines()                # list of 3 strings
    print(len(lines))                    # 3

# Counting words, the usual 4-mark follow-up
with open("data.txt", "r") as f:
    print(len(f.read().split()))         # 12

Key points to state: read() → str, readlines() → list, write() returns a character count, and no method adds a newline for you. Always use with so the file is closed on every exit path.

Q 2 (8 marks) What is regular expression pattern matching? Explain re.match, re.search, re.findall, re.split and the Match methods with examples.

Definition. A regular expression is a pattern language for describing sets of strings. Instead of comparing a string to a fixed value, the pattern says what shape it has — r"\d{10}" means "ten digits". Patterns are written as raw strings so the backslash reaches re unchanged. Meta-characters: . any character, ^/$ anchors, */+/?/{m,n} repetition, [abc]/[^abc] sets, \d/\w/\s classes, | alternation, (...) grouping.

import re
s = "My number is 9876543210 and 12345"

re.match(r"\d+", s)              # None -- does not start with digits
re.search(r"\d+", s).group()     # '9876543210'
re.findall(r"\d+", s)            # ['9876543210', '12345']
re.split(r"\s+", "a  b   c")     # ['a', 'b', 'c']
re.sub(r"\d+", "#", s)           # 'My number is # and #'

m = re.search(r"\d+", s)
m.group()    # '9876543210'
m.start()    # 13
m.end()      # 23  -- one past the last character
m.span()     # (13, 23)
s[m.start():m.end()]             # '9876543210'
FunctionReturnsSearches
re.matchMatch / Noneposition 0 only
re.searchMatch / Nonefirst match anywhere
re.findalllist[str]all non-overlapping matches
re.splitlist[str]splits at every match

Grouping captures: with r"(\d+)\D+(\d+)", m.groups() is ('9876543210', '12345') and m.group(1) is the first. Always guard against None — calling .group() on a failed search raises AttributeError.

Q 3 (8 marks) a) Explain read(), readline(), readlines(), write() and writelines() with a program that counts words in a file. b) Explain tell(), seek(), os.rename() and os.remove().

a) The five methods. read() returns the whole remaining file as one str; read(n) returns exactly n characters; readline() returns the next line as a str with its \n intact; readlines() returns a list of such strings. write(s) writes one string and returns the number of characters written; writelines(seq) writes an iterable of strings and returns None. Neither write method inserts a newline.

# Word count in file.txt -- both accepted forms
with open("file.txt", "r") as f:
    print(len(f.read().split()))          # 12

count = 0
with open("file.txt", "r") as f:
    for line in f:                        # streaming, one line at a time
        count += len(line.split())
print(count)                              # 12

# Lines and characters from the same file
with open("file.txt", "r") as f:
    data = f.read()
print(len(data.splitlines()), len(data))  # 3 63 -- 3 lines, 63 chars

b) Cursor and filesystem operations.

with open("seek.txt") as f:      # file holds ABCDEFGHIJ
    print(f.tell())              # 0
    print(f.read(3))             # ABC
    print(f.tell())              # 3
    f.seek(0)                    # back to start
    print(f.read(3))             # ABC
    f.seek(5)
    print(f.read(3))             # FGH

import os
os.rename("old.txt", "new.txt")  # rename or move
os.remove("new.txt")             # delete the file

tell() reports the cursor in characters; seek(offset, whence) moves it, with whence 0 = start, 1 = current, 2 = end. In text mode an end-relative seek must be zero: f.seek(-2, 2) raises UnsupportedOperation; open in 'rb' to seek backwards from the end. os.rename() and os.remove() act on the directory entry rather than on open content, which is why they live in os and not on the file object.

Q 4 (8 marks) a) Explain console input and output in Python. b) Write a program that reads a file and prints its lines with line numbers using a regular expression to filter them.

a) Console I/O. input(prompt) writes the prompt and returns whatever the user types as a str — never an int, even for digits. Convert explicitly with int()/float(). To read several values on one line, combine split() with casting:

name = input("Name: ")            # 'Asha'
age  = int(input("Age: "))        # '25' -> 25
x, y = input("Two numbers: ").split()
print(int(x) + int(y))            # '7 8' -> 15

print(*objects, sep=' ', end='\n', file=sys.stdout) prints each object separated by sep and terminated by end. Setting end="" keeps the cursor on the same line; sep="/" changes the separator; file=f sends output into an open file.

print("a", "b", "c")                 # a b c
print("a", "b", "c", sep="-")        # a-b-c
print("2026", "11", "19", sep="/")   # 2026/11/19
print("no newline", end="")          # then the next print continues

b) Filtered listing — numbering the lines and keeping only those the regex matches:

import re

pattern = re.compile(r"\d+")          # keep lines containing digits
with open("file.txt", "r") as f:
    for number, line in enumerate(f, 1):
        if pattern.search(line):
            print(f"{number:>3}: {line.rstrip()}")

On a file whose third line is Practice 10 times, this prints 3: Practice 10 times. Use search rather than match so the pattern may appear anywhere in the line, and rstrip() to drop the newline that print would otherwise double.

Practice Programs

Five programs, each one a lab-style task from the paired lab course (file processing, then regular expressions). Every output shown was produced by running the code exactly as written.

1. Count words in a file — two ways
with open("file.txt", "w") as f:
    f.write("Python is easy to learn\n")
    f.write("It has simple syntax\n")
    f.write("Practice makes perfect\n")

Output:

v2: 12

Both are accepted; say why for the extra mark — version 2 never holds the whole file in memory, so it works on a file larger than RAM.

2. Line, word and character counter as a reusable function
def counts(path):
    with open(path, "r") as f:
        data = f.read()
    return len(data.splitlines()), len(data.split()), len(data)

print(counts("file.txt"))

Output:

(3, 12, 68)

Returning a tuple lets one call answer all three questions. splitlines() is correct where readlines() would also work: it drops the trailing newline without needing strip() on each item.

3. Copy one file to another
with open("file.txt", "r") as src, open("copy.txt", "w") as dst:
    dst.write(src.read())

print(open("copy.txt").read().splitlines()[0])
print("identical:", open("file.txt").read() == open("copy.txt").read())

Output:

Python is easy to learn
identical: True

Two context managers in one with closes both files on exit. For images you cannot use src.read() as text — open both in 'rb'/'wb' and copy in chunks.

4. Print a file with line numbers
with open("file.txt", "r") as f:
    for i, line in enumerate(f, 1):
        print(i, line.rstrip())

Output:

1 Python is easy to learn
2 It has simple syntax
3 Practice makes perfect

enumerate(f, 1) starts numbering at 1. rstrip() removes the trailing \n; without it every printed line would end with a blank line.

5. Regex validation and extraction
import re

def valid_mobile(s):
    return bool(re.fullmatch(r"[6-9]\d{9}", s))

print(valid_mobile("9876543210"))   # True
print(valid_mobile("12345"))        # False -- too short, wrong start
print(valid_mobile("1234567890"))   # False -- does not start 6-9

emails = "a@x.com, bad@@y, c@z.org"
print(re.findall(r"[\w.]+@[\w.]+\.\w+", emails))
print(re.sub(r"\s*,\s*", " | ", emails))

Output:

True
False
False
['a@x.com', 'c@z.org']
a@x.com | bad@@y | c@z.org

fullmatch anchors both ends, so it validates rather than merely finds. The email pattern correctly rejects bad@@y when using findall, because the double @ does not fit — exactly the kind of example to quote in a viva.

Quick Revision

The unit in 12 points
  • open(path, mode) returns a file object; read its state with .name, .mode, .closed.
  • 'w' truncates on open, not on write. 'a' starts at end-of-file. 'x' raises FileExistsError if it exists.
  • 'r' on a missing file raises FileNotFoundError; 'w', 'a' and 'x' create it.
  • with open(...) as f: closes on every exit path, including exceptions. Prefer it in every answer.
  • read() → one str. read(n) → n chars. readline() → one line. readlines() → list. One shared cursor.
  • write(s) returns the character count and adds no newline. writelines() returns None and adds none either.
  • Word count: len(f.read().split()). Never split(" ") — it over-counts.
  • tell() reports the cursor; seek(0) rewinds. Negative end-relative seeks fail in text mode.
  • os.rename() and os.remove() act on the directory entry, not the open file.
  • input() always returns str; cast before arithmetic. print(sep=, end=, file=) controls output.
  • re.match tests position 0 only; re.search scans. Both return Match or None — guard before .group().
  • start()/end() give a half-open slice: s[m.start():m.end()] reproduces the match. end() is one past the last character.
Facts examiners award marks for
  • 'w' and 'w+' destroy existing content the moment the file is opened.
  • 'b' is a modifier, not a mode — it is written 'rb', never 'b' alone.
  • readlines() keeps the \n on every item, so comparisons against "line" fail — use strip().
  • Raw strings r"..." are mandatory practice with re, because \b is a backspace in an ordinary string.
  • re.findall returns strings; re.search returns a Match object. Mixing these up is the most common 2-mark loss.
  • re.split(r"[,;]", "x,y;z") works on a set of separators, one call, no loop.
  • Python 3 print is a function: print "x" is a SyntaxError. Python 2's raw_input() became input().
Where marks are commonly lost
  • Writing f = open(...) in an 8-mark answer with no close(). The examiner looks for with.
  • Saying 'r+' creates a file. It does not — it raises FileNotFoundError.
  • Claiming write() adds a newline. It does not; forgetting \n runs every line together.
  • Calling .group() straight on re.search output without an if m: guard.
  • Confusing end() with the index of the last character. It is one past it, because it is a slice bound.
  • Counting words with split(" "), which produces empty strings on double spaces and never splits at a newline.
  • Writing open("f.txt", "b"). Binary must be combined with a base mode.
