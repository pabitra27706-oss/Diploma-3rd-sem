Overview

What This Unit Covers

Unit 2 covers how Python controls the flow of program execution using decision-making and repetition:

  • Conditional Blocks: if, elif, else — make decisions based on conditions.
  • Loops: for and while — repeat blocks of code.
  • Loop Control: break, continue, pass, else-with-loops.

Decision Making

What a conditional actually does

Every program so far ran its statements top to bottom, once each. A conditional lets a program choose: the interpreter evaluates a condition, gets either True or False, and runs one indented block or another. Python has no braces and no switch statement; the block is defined purely by indentation, and the header line ends with a colon.

Three forms cover every decision: if (do something when a condition holds), if...else (choose between two), and if...elif...else (choose among several, testing each in order).

The if, elif and else Statements

Syntax — one form covers all three
if condition1:
    block1
elif condition2:
    block2
elif condition3:
    block3
else:
    default_block

Read it as a ladder: Python tests condition1; if true, block1 runs and every other block is skipped. If false it moves to condition2, and so on. else catches what fell through.

The rule that decides most marks
  • Only the first true condition runs. In an if/elif chain, later conditions are never even evaluated once an earlier one succeeds.
  • if is required and appears exactly once; elif is optional and may appear zero or more times; else is optional and may appear at most once, always last.
  • You write elif, never else if — elif is its own keyword.
  • else has no condition. Writing else x > 5: is a syntax error.
The exam grade ladder, run
marks = 78

if marks >= 90:
    grade = "A+"
elif marks >= 80:
    grade = "A"
elif marks >= 70:
    grade = "B"
else:
    grade = "F"

print(grade)

Output

B

Trace it: 78 >= 90 is false, so the first block is skipped. 78 >= 80 is false too. 78 >= 70 is true, so grade = "B" runs and the else is skipped. Note the order: the conditions are written from the highest mark down. If you wrote marks >= 70 first, 78 would take that branch and never reach the stricter tests.

Nested conditionals put one if inside another, one indent deeper, for when the second test only makes sense if the first passed:

Nested if
age, has_id = 20, True

if age >= 18:
    if has_id:
        print("entry allowed")
    else:
        print("need id")
else:
    print("too young")

Output

entry allowed
Flatten before you nest

Two levels are readable; four are not. The test above is cleaner flat: if age >= 18 and has_id:. Nest only when the inner test is meaningless alone.

Truthiness and the Conditional Expression

A condition does not have to be a comparison. Python accepts any object in a condition and converts it to a boolean by a fixed rule: an object is truthy unless it is a recognised empty or zero value.

Conditional expression — a value, not a statement

The form is value_if_true if condition else value_if_false. It is an expression: it produces a value and can sit on the right of an assignment or inside a print(). It is not a replacement for a multi-way if/elif/else — it has no elif and cannot contain statements. Use it for a two-way choice, never for a ladder.

Marks lost here every year
  • Missing the colon: if x > 0 instead of if x > 0:.
  • Inconsistent indentation — tabs mixed with spaces raises IndentationError. Pick 4 spaces and keep it.
  • else if is not Python; it is elif.
  • Expecting all matching branches to run. Only the first true one does.
  • Assuming Python has a switch statement like C. It does not in the exam syllabus; match/case exists only from Python 3.10 and the syllabus does not require it.

Iteration Statements

Two loops, two questions

A loop repeats a block. Python gives you exactly two, and the choice between them is decided by a single question: do you know how many times, or do you know when to stop?

  • for — you have a sequence of things to visit. The loop ends when the sequence is exhausted. You do not count iterations yourself.
  • while — you have a condition. The loop keeps going while it is true, and something inside the body must eventually make it false.

Both share one shape: a header ending in a colon, then an indented body. The first line back at the original indent ends the loop.

The for Loop, the while Loop and range()

The two forms side by side

The same count, written both ways

The last two lines show something worth a mark: range() is a lazy sequence object, not a list. Count the iterations without running it

For an arithmetic progression the length is ceil((stop - start) / step), clamped at zero. So range(1, 10, 3) is ceil(9 / 3) = 3 values: 1, 4, 7. Examiners ask for "how many times does this loop run" far more often than they ask you to print it.

Nested Loops

A loop inside a loop. The inner loop runs completely for each single pass of the outer loop, so the total number of inner-body executions is the product of the two counts.

Multiplication table and a triangle
n = 3
for i in range(1, 6):
    print(f"{n} x {i} = {n * i}")

for row in range(1, 5):
    print("*" * row)

total = 0
for i in range(1, 4):
    for j in range(1, 4):
        total += 1
print("inner passes:", total)

Output

3 x 1 = 3
3 x 2 = 6
3 x 3 = 9
3 x 4 = 12
3 x 5 = 15
*
**
***
****
inner passes: 9

3 x 3 = 9 inner passes, because the outer loop runs 3 times and the inner 3 times per pass. The triangle uses one loop, not two: "*" * row repeats the string, which is cheaper and clearer than an inner loop.

The Three Loop Programs the Paper Asks For

Across the four 2023–2026 papers these three programs account for 16 of Unit 2's marks. Each is short enough to memorise and each has one detail that carries the mark.

1. Prime check — why the loop stops at the square root
def is_prime(n):
    if n <= 1:
        return False
    for d in range(2, int(n ** 0.5) + 1):
        if n % d == 0:
            return False
    return True

for n in [1, 2, 7, 9, 29, 35]:
    print(n, is_prime(n))

Output

1 False
2 True
7 True
9 False
29 True
35 False

Three things earn the marks: the n <= 1 guard (1 is not prime and no loop can discover that); the bound int(n ** 0.5) + 1, because a factor above the square root implies one below, and the + 1 includes the root itself; and returning the moment a divisor is found.

2. Sum of digits — why it must be //=
def digit_sum(n):
    n = abs(n)
    total = 0
    while n > 0:
        total += n % 10
        n //= 10
    return total

print(digit_sum(1234), digit_sum(-907), digit_sum(0))

Output

10 16 0

n % 10 peels off the last digit and n //= 10 removes it. The operator matters: n /= 10 would make n a float (123.4, then 12.34…) and the loop would never reach 0, so it runs forever. Integer division is the whole point. abs() handles negatives and digit_sum(0) returns 0 because the loop body never executes.

3. Walking a tuple
t = ("red", "green", "blue")

for colour in t:
    print(colour)

print("---")
for i, colour in enumerate(t, start=1):
    print(i, colour)

Output

red
green
blue
---
1 red
2 green
3 blue

Use the plain form for values only, enumerate() when you also need a position, and start=1 to number from one without i + 1 everywhere.

Loop mistakes that cost marks
  • Forgetting to update the while variable — infinite loop.
  • Using / instead of // when digit-peeling.
  • Assuming range(1, 10) includes 10. It stops at 9.
  • Expecting range(10, 0) to count down; with the default step it is empty.
  • Printing range(5) and expecting numbers — wrap it in list().

Loop Control Statements

Changing the exit from inside

Normally a loop ends when its sequence runs out or its condition goes false. Three statements change that from inside the body, and one clause changes what happens after it. This cluster carries 21 marks (32.8% of the unit) and appears in all four papers.

The break, continue and pass Statements

All three are single keywords used as a whole statement. They behave completely differently, and the fastest way to see that is to run the same loop three times and change only which keyword sits at n == 3:

One loop, three keywords
print("break   :", end=" ")
for n in range(1, 6):
    if n == 3:
        break
    print(n, end=" ")
print()

print("continue:", end=" ")
for n in range(1, 6):
    if n == 3:
        continue
    print(n, end=" ")
print()

print("pass    :", end=" ")
for n in range(1, 6):
    if n == 3:
        pass
    print(n, end=" ")
print()

Output

break   : 1 2 
continue: 1 2 4 5 
pass    : 1 2 3 4 5

The difference is the examinable content:

  • break abandons the loop immediately. 3, 4 and 5 are never reached, and any else clause on the loop is skipped.
  • continue abandons only the rest of this one iteration. It jumps back to the header, takes the next value, and the loop carries on — so 3 is missing but 4 and 5 still print.
  • pass does nothing at all. It is a placeholder for a block Python's grammar requires but you have not written yet. The loop is completely unaffected, which is why all five numbers print.

pass is not continue

continue skips the rest of the iteration; pass keeps going through it. A useful check: delete the pass line — if the program is still valid, it was a placeholder, not logic.

break only breaks one level

In a nested loop, break exits the innermost loop only; the outer loop continues with its next value. On for i in range(3) wrapping for j in range(3) with break at j == 1, only the three (i, 0) pairs are produced — nine inner passes become three. To leave both levels, use a flag or a return from a function.

The Loop else Clause

Both for and while accept an optional else block after the body. It is one of Python's most-misunderstood features, and the rule is short:

The rule, in one line

The else block runs only if the loop finished without hitting break. That includes a loop that ran zero times, and a while whose condition was false from the start. It is not an "if the loop was empty" clause — that is the single most common wrong answer in the paper.

Read for ... else as "for ... and then", or as "if no break happened". It is the natural fit for a search.

A search, written with for...else
def search(items, target):
    for item in items:
        if item == target:
            print(f"found {target}")
            break
    else:
        print(f"{target} not found")

search([4, 8, 15, 16], 15)
search([4, 8, 15, 16], 99)

Output

found 15
99 not found

The first call breaks, so else is skipped. The second never breaks, so else runs. Without the clause you would need a found = False flag before the loop and an if not found: after it — the else version is exactly the same logic with the flag removed.

The three cases the paper tests
# 1. zero iterations: else STILL runs
for x in range(0):
    print("never")
else:
    print("zero-iteration loop still runs else")

# 2. normal exhaustion: else runs
n = 3
while n > 0:
    print("n =", n)
    n -= 1
else:
    print("while exhausted")

# 3. break: else is skipped
n = 3
while True:
    if n == 1:
        break
    n -= 1
else:
    print("never printed")
print("done, n =", n)

Output

zero-iteration loop still runs else
n = 3
n = 2
n = 1
while exhausted
done, n = 1

Case 1 is the one that separates a full mark from a half: range(0) produces no values, the body never runs, and else still executes. "Never printed" in case 3 never appears, which is the only effect break has on the clause.

If you cannot remember which way round it is

Think of what the clause is for. It exists so a search can say "I looked at everything and found nothing". Finding something is the exceptional path, and that is the break. So else belongs to the not-found case — which means it must be skipped when you do find something. The behaviour follows from the purpose.

Marks lost in this section
  • Saying the else clause runs "when the loop body is empty" — the real condition is "no break", and a zero-iteration loop runs it too.
  • Saying pass skips an iteration. It does nothing; continue skips.
  • Expecting break in an inner loop to exit the outer one as well.
  • Writing break outside any loop — a SyntaxError. Same for continue and return where no function exists.
  • Confusing continue in a while loop with a safe skip: if the update statement sits after the continue, the loop variable never changes and you get an infinite loop.

Key Definitions

Control structure

A construct that decides the order in which statements execute, instead of running them once, top to bottom. Python has two: conditionals (if, elif, else) and loops (for, while).

for loop

Iterates over the items of a sequence one by one, rebinding the loop variable to each item. It ends automatically when the sequence is exhausted, so no counter or condition is written by hand.

while loop

Repeats its body while a condition remains True. The condition is checked before each pass, so the body may run zero times. The body must eventually make the condition false.

Iteration / infinite loop

Iteration is one complete pass through a loop body. An infinite loop is one whose condition never becomes false — usually a missing update to the control variable. while True: is an intentional infinite loop, exited by break.

range()

A built-in that returns a lazy arithmetic sequence of integers, defined by start, stop and step. The stop bound is exclusive. It stores three numbers rather than the values, so its memory use is constant regardless of length.

Truthiness

The rule that converts any object to True or False when it is used in a condition. Zero, None, and empty strings and containers are falsy; almost everything else is truthy.

Multiple Choice Questions

Q 1

What does list(range(1, 10, 3)) produce?

  • a. [1, 2, 3, 4, 5, 6, 7, 8, 9]
  • b. [1, 4, 7]
  • c. [1, 4, 7, 10]
  • d. [3, 6, 9]
Answer: b. [1, 4, 7]

Start at 1, add 3 each time: 1, 4, 7, then 10 which is not less than stop, so it is excluded. Count = ceil((10 - 1) / 3) = 3.

Q 2

How many times does the inner body run?

count = 0
for i in range(3):
    for j in range(2):
        count += 1
  • a. 5
  • b. 6
  • c. 8
  • d. 9
Answer: b. 6

Outer 3 passes × inner 2 passes each = 6. count ends at 6, not at 3 × 2 written longhand as 9 — that is the 3×3 case.

Q 3

What is printed?

for n in range(1, 6):
    if n == 3:
        continue
    if n == 5:
        break
    print(n, end=" ")
  • a. 1 2 3 4
  • b. 1 2 4
  • c. 1 2 3 4 5
  • d. 1 2
Answer: b. 1 2 4

3 is skipped by continue. 4 prints. At 5 the break fires before the print, so 5 never appears.

Q 4

When does a loop's else block execute?

  • a. Every time the loop ends
  • b. Only when the loop ran at least once
  • c. Only when the loop ended without hitting break
  • d. Only when break was executed
Answer: c

"No break" is the whole rule — and a loop that runs zero times still qualifies, which is why option b is wrong.

Q 5

What does list(range(10, 0, -2)) produce?

  • a. [10, 8, 6, 4, 2, 0]
  • b. []
  • c. [10, 8, 6, 4, 2]
  • d. [0, 2, 4, 6, 8, 10]
Answer: c. [10, 8, 6, 4, 2]

Counting down by 2 from 10 stops before 0, so 0 is excluded. Option a assumes the stop is inclusive, which it never is.

Q 6

How many levels does break exit in a loop nested inside another loop?

  • a. All levels, immediately
  • b. Only the innermost loop
  • c. Only the outermost loop
  • d. It is a syntax error inside a nested loop
Answer: b

break leaves the innermost enclosing loop; the outer loop then continues with its next value. Leaving both needs a flag or a return.

Q 7

Which of these values is truthy?

  • a. 0
  • b. ""
  • c. "0"
  • d. []
Answer: c. "0"

A non-empty string is always truthy, whatever characters it holds. 0 is numeric zero and [] is an empty container, so both are falsy.

Q 8

Python has no do-while loop. Which idiom runs a body at least once?

  • a. for i in range(1):
  • b. while True: with a break inside
  • c. if True:
  • d. repeat: with until
Answer: b

while True: never checks a condition on entry, so the body always runs, and a break supplies the exit. repeat/until is not Python.

Q 9

Why does this loop never end?

n = 1234
while n > 0:
    n /= 10
  • a. n is never defined inside the loop
  • b. / produces a float, so n approaches but never reaches 0
  • c. The condition should be n >= 0
  • d. It does end after 4 iterations
Answer: b

1234 / 10 is 123.4, which is still > 0. It shrinks forever without ever becoming exactly 0. Integer division n //= 10 is what digit-peeling requires.

Q 10

What is the value of x?

x = "adult" if 16 >= 18 else "minor"
  • a. "adult"
  • b. "minor"
  • c. None
  • d. SyntaxError
Answer: b. "minor"

A conditional expression is value_if_true if condition else value_if_false. 16 >= 18 is false, so the else value is chosen.

Short Answer Questions

Q 1

Differentiate between the for loop and the while loop in Python.

for iterates over a sequence (string, list, tuple, range). The number of repetitions is decided by the sequence length and you do not maintain a counter. It ends automatically when the sequence is exhausted.

while repeats while a condition stays true. You initialise the variable before the loop and must update it inside, or the loop never ends. Use it when the number of repetitions is not known in advance, e.g. reading until a sentinel value appears.

In one line: for is sequence-driven, while is condition-driven.

Q 2

What is the purpose of the pass statement, and how does it differ from continue?

pass is a null statement: Python executes it and does nothing. It exists because the grammar requires at least one statement in every block, so it is used as a placeholder while a block is being written, or where a block is deliberately empty (for example an empty except or a class body).

continue is control flow: it abandons the remainder of the current iteration and jumps back to the loop header for the next value. So on for n in range(1, 6) with pass at n == 3 the output is 1 2 3 4 5, while with continue it is 1 2 4 5.

Q 3

Explain the else clause of a loop with an example.

A for or while loop may be followed by an else block. It executes only if the loop finished without executing break. A loop that runs zero times also satisfies this, so its else still runs.

for n in [4, 8, 15]:
    if n == 15:
        print("found")
        break
else:
    print("not found")

Prints found and skips the else. Change the target to 99 and the loop exhausts, so not found prints. It removes the need for a separate found = False flag in search code.

Q 4

What does range(2, 11, 3) produce, and how many values does it contain?

Starting at 2 and adding 3: 2, 5, 8. The next value would be 11, which is not less than the stop value 11, so it is excluded.

Count = ceil((11 - 2) / 3) = ceil(3) = 3 values. The stop bound is always exclusive; that single rule answers most range() questions.

Q 5

List any four values that are treated as False in a condition.

False, None, 0 (and 0.0), the empty string "", and the empty containers [], (), {}, set(). Any of these makes if value: take the false branch.

The trap: "0" is a non-empty string and therefore true, and [0] is a non-empty list and therefore true.

Long Answer Questions

Q 1 (8 marks)

a) Explain the if, elif and else statements with syntax and an example. b) What is a nested if?

a) The three keywords. A conditional selects which block runs, based on a condition that evaluates to True or False.

if condition1:
    block1
elif condition2:
    block2
else:
    default_block
  • if is compulsory, appears once, and is evaluated first.
  • elif is optional, may repeat, and is tested only if everything above it was false.
  • else is optional, appears at most once, is always last, and takes no condition.
  • Evaluation stops at the first true condition; no later branch is tested.
  • Every header ends in a colon and the body is indented consistently.
marks = 78

if marks >= 90:
    print("A+")
elif marks >= 80:
    print("A")
elif marks >= 70:
    print("B")
else:
    print("F")

Output: B. The conditions are ordered highest-first, so the ladder falls through to the band that contains 78.

b) Nested if. An if written inside the body of another if, one indent deeper. It is used when the second test only makes sense after the first has passed:

if age >= 18:
    if has_id:
        print("entry allowed")
    else:
        print("need id")

The inner test is never reached for an under-18 visitor. Where possible prefer the flat form if age >= 18 and has_id:; deep nesting is hard to read and is penalised in exams.

Q 2 (8 marks)

a) Explain the for and while loops with syntax and examples. b) Explain range() with all three forms.

a) for loop. Iterates over the items of a sequence; the loop ends when the sequence is exhausted.

for variable in sequence:
    body
for ch in "abc":
    print(ch)          # a b c

while loop. Repeats while a condition remains true. The variable must be initialised before and updated inside.

while condition:
    body # must change condition
i = 1
while i <= 3:
    print(i)
    i += 1             # without this the loop never ends

Same output (1 2 3) from both. for is used when the count is known or a sequence exists; while when termination depends on a condition.

b) range(). Produces an immutable arithmetic sequence without building a list, so it uses constant memory.

FormMeaninglist(...)
range(stop)0 to stop-1, step 1range(4) → [0, 1, 2, 3]
range(start, stop)start to stop-1, step 1range(2, 5) → [2, 3, 4]
range(start, stop, step)start, then +step, while < stoprange(1, 9, 3) → [1, 4, 7]

Three rules carry the marks: stop is always exclusive; a negative step counts down (range(5, 0, -1) → [5, 4, 3, 2, 1]); and a step in the wrong direction yields an empty range (range(5, 2) → []).

Q 3 (8 marks)

a) Explain break and continue with example outputs. b) Explain pass. c) What does the else clause on a loop do?

a) Both alter the normal flow, but at different points. On for n in range(1, 6): with the keyword placed at n == 3:

KeywordOutputEffect
break1 2exits the innermost loop immediately; 4 and 5 never run, and the loop else is skipped
continue1 2 4 5abandons only the rest of iteration 3, then continues with 4

b) pass is the null statement. Python requires a non-empty block, and pass satisfies that without doing anything: output is 1 2 3 4 5, unchanged. It is a placeholder while a block is unwritten, not a control statement.

c) The loop else runs only when the loop completed without break. A zero-iteration loop also runs it. It is the natural way to express "searched everything, found nothing":

for item in [4, 8, 15]:
    if item == 15:
        print("found")
        break
else:
    print("not found")        # skipped here, because break ran

With target 99 the loop exhausts and not found prints.

Q 2

Find the sum of the digits of a number using a while loop, and then reverse the number with the same technique.

Solution
n = 1234
total, reverse, temp = 0, 0, n

while temp > 0:
    digit = temp % 10
    total += digit
    reverse = reverse * 10 + digit
    temp //= 10

print("sum     =", total)
print("reverse =", reverse)

Output

sum     = 10
reverse = 4321

reverse * 10 + digit shifts the digits already collected one place left and appends the new one. Both results come from a single pass over the digits.

Q 3

Check whether a string is a palindrome using a loop (no slicing).

Solution
def is_palindrome(text):
    cleaned = text.lower().replace(" ", "")
    left, right = 0, len(cleaned) - 1
    while left < right:
        if cleaned[left] != cleaned[right]:
            return False
        left += 1
        right -= 1
    return True

for word in ["Madam", "Python", "Never odd or even"]:
    print(f"{word!r:22} {is_palindrome(word)}")

Output

'Madam'                True
'Python'               False
'Never odd or even'    True

Two indices walk towards each other; the loop stops at the middle because left < right fails when they meet. This is O(n/2) comparisons instead of building a reversed copy.

Q 4

Print the first n terms of the Fibonacci series using a while loop.

Solution
n = 8
a, b, count = 0, 1, 0
series = []

while count < n:
    series.append(a)
    a, b = b, a + b
    count += 1

print(series)

Output

[0, 1, 1, 2, 3, 5, 8, 13]

a, b = b, a + b is a simultaneous assignment: the right side is evaluated fully before either name is rebound, so no temporary variable is needed. Writing it as two separate lines gives the wrong series.

Revision

The points that decide the marks
  • if once, elif zero or more, else at most once and last. Only the first true branch runs.
  • elif is one keyword; else if is a syntax error.
  • Falsy: False, None, 0, "", [], (), {}, set(). "0" and [0] are true.
  • range(): stop is exclusive. A negative step counts down; the wrong direction gives an empty range.
  • for is sequence-driven, while is condition-driven. No do-while — use while True: plus break.
  • break exits the innermost loop only; continue skips one iteration; pass does nothing.
  • A loop's else runs only when no break happened — including a zero-iteration loop.
  • n //= 10 peels digits; n /= 10 makes a float and the loop never ends.
  • Nested inner passes = outer × inner.
Must remember for the exam
  • With break at n == 3 on range(1, 6): 1 2. With continue: 1 2 4 5. With pass: 1 2 3 4 5.
  • list(range(2, 10, 3)) → [2, 5, 8]; list(range(10, 0, -2)) → [10, 8, 6, 4, 2].
  • Prime test: guard n <= 1, then range(2, int(n ** 0.5) + 1).
  • Digit sum of 907 is 16.
Where marks are lost
  • Saying the loop else runs "when the loop is empty" — the rule is "no break".
  • Treating pass as a way to skip an iteration.
  • Assuming break leaves every enclosing loop.
  • Writing range(1, 10) for a 1-to-10 table and losing the last row.
  • Forgetting the update in a while loop.
  • Using / instead of // in digit extraction, so the loop never terminates.
  • Inconsistent indentation — tabs mixed with spaces raise IndentationError.
