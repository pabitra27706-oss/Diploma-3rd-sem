Introduction to Python

Python Basics: History, Features, Indentation, Keywords and Comments

Python is a high-level, interpreted, dynamically typed language created by Guido van Rossum and first released in 1991. It was designed for readability: the language uses indentation instead of braces, and its standard library ships with the language rather than as an add-on. The name comes from the British comedy series Monty Python's Flying Circus, not from the snake.

Eight features carry most of the marks when the question says "explain the features of Python":

Interpreted

Executed by the interpreter statement by statement. No separate compile-and-link step like C.

High-level

Memory is managed for you — no malloc, no pointers, no manual free.

Dynamically typed

A name is bound to whatever object you assign. No type declaration, and the type can change later.

Object-oriented

Everything is an object, including int and functions. Classes and inheritance are built in.

Free and open source

Usable and redistributable at no cost, with source available.

Extensive library

A large standard library plus third-party packages installed with pip.

Cross-platform

The same source runs on Windows, Linux and macOS without modification.

Readable

Indentation makes block structure visible; English-like keywords keep conditions short.

Indentation is syntax, not decoration

Python groups statements into a block purely by their leading whitespace. Every line of a block must share the same indent; the block ends when the indent drops back. The convention — and what every paper expects you to say — is four spaces per level. There is no { } and no end keyword, so the whitespace is the syntax.

Indentation, comments and docstrings
# Single-line comment: Python ignores everything after #
"""
A triple-quoted string. When it is the first statement in a
module, function or class it becomes that object's __doc__.
"""

def greet():
    """Returned by greet.__doc__ -- not printed anywhere."""
    return "hi"

if True:
    print("Indented 4 spaces -> inside the if block")
    print("Same indent -> still the same block")
print("Dedented -> outside the block")

print(greet())
print(repr(greet.__doc__))
Two errors that come straight from whitespace
  • IndentationError — the block is empty, over-indented, or the first line under a colon is not indented. A colon at the end of if, for, while, def or else promises a block, so the next line must be indented one level deeper.
  • TabError — the same block is indented with a mixture of tabs and spaces. Python 3 forbids the mixture outright rather than guessing which you meant. Pick one and never mix.

A comment is stripped before execution and is not part of the program. A docstring is a real string expression that survives as metadata, so help() can print it. That difference is exactly what a "comments vs docstrings" question is testing.

Identifiers and keywords

An identifier is a name you invent: a variable, function, class or module. A keyword is a name the language has already reserved, and you may not reuse it. Python 3 has 35 keywords, and three of them are case-sensitive surprises — True, False and None are capitalised, so true and none are ordinary (undefined) names.

Both modes use the same interpreter, so the same statement behaves identically — the difference is only who prints the result. In the interactive prompt the interpreter echoes it; in a script you must call print() yourself.

Built-in functions the paper names

A built-in function is already available when the interpreter starts — it needs no import. The ones that recur in objective questions are len(), type(), id(), int(), str(), range(), all(), any(), max(), min() and sum(). all() returns True only if every element is truthy; any() returns True if at least one is. Both return True for an empty sequence, which is the detail that catches people out.

all(), any(), len() and type()
print(all([True, True, False]))   # False -- one falsy element is enough
print(any([False, False, True]))  # True  -- one truthy element is enough
print(all([]), any([]))           # True False -- vacuous truth on empty
print(len("Python"), "Python"[0], "Python"[-1])   # 6 P n
print(type(10).__name__)          # int
Setup and PATH (syllabus topic, not yet examined)

Install from python.org (tick Add Python to PATH) or sudo apt install python3; verify with python3 --version. PATH is where the shell looks for a command, so "python3: not found" means the install folder is missing from it. PYTHONPATH is unrelated: it lists folders that import searches for your modules. Read a traceback bottom-up — the last line names the exception (SyntaxError, IndentationError, NameError, TypeError, IndexError, KeyError), the lines above it name the file and line number.

Exam important
  • Guido van Rossum, 1991; Python 3 (2008) is not backward compatible with Python 2.
  • Blocks are defined by indentation — four spaces, never mixed with tabs.
  • # is a comment and is discarded; a triple-quoted docstring is a live string kept in __doc__.
  • 35 keywords; True, False, None are capitalised. print is a built-in function, not a keyword.
  • Interactive mode echoes expressions; script mode needs an explicit print().

Variables and Data Types

Built-in Data Types, Mutability and Type Conversion

A Python name is not a typed box; it is a label tied to an object. x = 10 builds the integer object 10 and binds the name x to it. Assign a string to x later and the name is simply re-pointed at a different object — nothing about x was ever declared. That is what dynamic typing means, and it is why type() has to be asked at runtime rather than read from a declaration.

Mutable vs immutable — proved, not asserted

An object is immutable when no operation can change it in place. Every "change" you write actually builds a new object and re-binds the name. id() returns the identity of an object and makes the difference visible: after s += "d" the id changes (a new string was built), while lst.append(3) leaves the id alone (the same list was modified).

The id() proof
s = "abc"
print(id(s) == id("abc"))     # True  -- same object, strings are shared
s += "d"                      # rebinds: a NEW string object
print(s, id(s) == id("abc"))  # abcd False

lst = [1, 2]
before = id(lst)
lst.append(3)                 # in-place: SAME object
print(lst, id(lst) == before) # [1, 2, 3] True

t = (1, 2)
t[0] = 99                     # TypeError: 'tuple' object does not support item assignment

Why mutability is worth marks: immutable objects are hashable, so they can be dictionary keys and set members; they are safe to share between parts of a program because nothing can change them behind your back. Mutable objects are cheaper to grow, which is why append() exists at all. Try d[[1, 2]] = "x" and Python raises TypeError: unhashable type: 'list' — that single line is the standard objective question on dictionary keys.

/ always returns a float, even when both operands divide exactly: 10 / 2 is 5.0, not 5. For an integer quotient use //. And bool is caught by both traps at once — True is a real int worth 1, so sum([True, True, False]) returns 2.

Date and Time Using the datetime Module

The datetime module supplies date (a calendar day), time (a clock time), datetime (both) and timedelta (a duration). datetime.now() gives the current local date and time; strftime() turns it into formatted text. Subtract two date or datetime objects and you get a timedelta; add a timedelta to a date and you get a new date.

Current date, formatting and arithmetic
from datetime import datetime, date, timedelta

now = datetime.now()
print(now.strftime("%Y-%m-%d %H:%M:%S"))   # 2026-11-19 05:57:57
print(now.strftime("%d/%m/%Y"))            # 19/11/2026
print(now.year, now.month, now.day)        # 2026 11 19

d = date(2024, 1, 15)
print(d, d.strftime("%d-%b-%Y"))           # 2024-01-15 15-Jan-2024
print(date.today() + timedelta(days=1))    # tomorrow
print(date(2024, 1, 15) - date(2024, 1, 1))  # 14 days, 0:00:00

stamp = datetime(2024, 1, 15, 10, 30, 0)
print(stamp.strftime("%I:%M %p"))          # 10:30 AM
delta = datetime(2024, 1, 16, 10, 30) - stamp
print(delta, delta.total_seconds(), delta.days)  # 1 day, 0:00:00 86400.0 1
strftime codes worth memorising

%Y four-digit year · %m month 01–12 · %d day 01–31 · %H hour 00–23 · %M minute · %S second · %I hour 01–12 · %p AM/PM · %b abbreviated month name · %A full weekday name. Lower-case %y gives a two-digit year and %m versus %M is month versus minute — those two swaps cause most lost marks.

String Data Type

String Literals, Indexing, Slicing and Methods

A string is an ordered, immutable sequence of characters. Ordered means every character has a fixed position; immutable means no character can ever be replaced in place. Single and double quotes are interchangeable — you switch style only so that a quote inside the text does not close the string early. Triple quotes are the one genuinely different form, because they preserve line breaks.

Four literal forms
print('He said "hi"')      # double quotes inside single quotes
print("It's fine")         # apostrophe inside double quotes
print('''multi
line''')                  # triple quotes keep the newline
print(repr(r"C:\new\test"))  # raw string: r"..." keeps backslashes literal

Methods: the string is never changed

Because strings are immutable, every method returns a new string and leaves the original untouched. Writing s.upper() and expecting s to change is the single most common beginner error — you have to assign the result back. These are methods, called with a dot on the string; len() by contrast is a built-in function called around it.

split() and join() are exact inverses, which is why papers pair them in one sub-question: ",".join("a,b,c".split(",")) == "a,b,c". Note the direction — join is called on the separator, and its argument is the sequence.

line = "  id:42 , name:Alice  "

print([p.strip() for p in parts])             # ['id:42', 'name:Alice']
print(", ".join(p.strip() for p in parts))    # id:42, name:Alice

print("hello".find("z"))   # -1        find never raises
print("hello".index("z"))  # ValueError: substring not found

String Formatting and Immutability

Python has three formatting styles, all still valid, and a question asking for "three ways" wants exactly these in order: the % operator (oldest), str.format() (Python 2.6+), and f-strings (Python 3.6+, and the one to prefer today).

The same output, three ways — with name = "Alice" and score = 95.4567
StyleCodeOutputNote
% operator"%s scored %.2f" % (name, score)Alice scored 95.46Positional; needs a matching tuple
.format()"{} scored {:.2f}".format(name, score)Alice scored 95.46Can reuse and name fields: {0}, {n}
f-stringf"{name} scored {score:.2f}"Alice scored 95.46Expressions inline: f"{len(name)}", f"{name!r}"

%.2f, {:.2f} and f"{x:.2f}" all mean "two digits after the decimal point, rounded". The format spec after the colon is the same in all three, which is why learning it once covers every style.

Immutability, in full

Assigning to a position raises TypeError: 'str' object does not support item assignment. Every apparent edit is really build a new string, then rebind the name — the pattern is slice, glue, reassign. That is what the "why are strings immutable" question is asking for, and the reason is worth stating: an immutable object cannot be changed by a function you passed it to, its hash cannot go stale, and it is therefore safe as a dictionary key.

Three formatting styles, then immutability
name, score = "Alice", 95.4567
print("%s scored %.2f" % (name, score))
print("{} scored {:.2f}".format(name, score))
print(f"{name} scored {score:.2f}")
print(f"{name!r} is {len(name)} chars")    # 'Alice' is 5 chars

s = "cat"
s = "b" + s[1:]     # slice, glue, reassign -> a new object
print(s)            # bat
# s[0] = "b" would raise TypeError: 'str' object does not support item assignment
Palindrome check — the standard 5-mark program

Normalise first (drop everything that is not a letter or digit, then lower-case it), and only then compare. Skipping the normalise step is why a candidate answers "No 'x' in Nixon" from memory instead of from code.

def normalise(text):
    """Keep letters and digits only, lower-cased."""
    return "".join(ch.lower() for ch in text if ch.isalnum())

def is_palindrome_slice(text):
    clean = normalise(text)
    return clean == clean[::-1]

def is_palindrome_loop(text):
    clean = normalise(text)
    i, j = 0, len(clean) - 1
    while i < j:
        if clean[i] != clean[j]:
            return False
        i += 1
        j -= 1
    return True

for sample in ["Madam", "Racecar", "No 'x' in Nixon", "Python"]:
    print(f"{sample!r:22} slice={is_palindrome_slice(sample)} loop={is_palindrome_loop(sample)}")

The slice version runs in one line and is what most examiners accept; the two-index loop is the version to show when the question says "without using slicing" or asks you to explain the pointer logic.

Exam important
  • Slicing: start included, stop excluded; s[::-1] reverses; out-of-range slices never raise.
  • Methods return a new string — reassign the result, or nothing changes.
  • find() returns -1; index() raises ValueError.
  • Three formatting styles: %, .format(), f-string. The format spec is the same in all three.
  • Strings are immutable: no item assignment, and + or a method builds a new object.

Collections — List, Tuple, Dict, Array

Unit 1 carries the largest single block of Python marks, and almost all of it is here: lists, tuples and dictionaries with slicing and copying account for the biggest cluster in the exam. Each of the three gets its own heading below, and the three-way comparison table at the end is the shape most 5- and 8-mark questions ask you to reproduce.

Lists: Slicing, In-place Methods and Copy Semantics

A list is an ordered, mutable sequence written in square brackets. It may hold mixed types, allows duplicates, and every element is reachable by integer index. Slicing behaves exactly as it does for strings — start included, stop excluded, negatives count from the end, and an out-of-range stop is clamped instead of raising.

Indexing, slicing and the methods that return None
nums = [10, 20, 30, 40, 50]
print(nums[1], nums[-1])           # 20 50
print(nums[1:3], nums[:2], nums[3:], nums[:])   # [20, 30] [10, 20] [40, 50] [10..50]
print(nums[::-1], nums[::2], nums[1:4:2])       # [50..10] [10, 30, 50] [20, 40]
print(nums[1:100])                 # [20, 30, 40, 50]  -- clamped
print(nums[99])                    # IndexError: list index out of range

a = [3, 1]
print(a.append(2))                 # None  <- the method returns None
print(a)                           # [3, 1, 2]
print(a.sort())                    # None  <- sorts IN PLACE
print(a)                           # [1, 2, 3]

The single most examined detail here is that mutating methods return None. append, extend, insert, remove, sort, reverse and clear all modify the list and hand back nothing. So x = list.append(4) makes x the value None, not the list. The built-in sorted() is the mirror image: it returns a new sorted list and leaves the original alone.

append vs extend, and the None trap

Aliasing, shallow copy and deep copy

Assignment never copies. b = a gives one list object with two names, so a change through either name is visible through the other. A shallow copy (a.copy(), a[:], list(a)) makes a new outer list but keeps references to the same inner objects, so editing a nested list still shows up in both. A deep copy (copy.deepcopy(a)) rebuilds the whole tree, so nothing is shared.

The three copies, run
import copy
original = [1, [2, 3], 4]
alias = original
shallow = original.copy()      # same as original[:] or list(original)
deep = copy.deepcopy(original)

original[0] = 99
original[1][0] = 777
print("alias  ", alias)        # [99, [777, 3], 4]
print("shallow", shallow)      # [1, [777, 3], 4]   nested list shared
print("deep   ", deep)         # [1, [2, 3], 4]     fully independent

List Mutation During Iteration

Never mutate a list while looping over it

Adding to a list inside a for loop over that same list makes the loop chase its own tail, because the iterator keeps finding new elements:

x = [1, 2, 3]
for s in x:
    if len(x) < 6:
        x.append(s * 10)
print(x)        # [1, 2, 3, 10, 20, 30] -- grew while being read

The safe form is to build a new list (x = [s * 10 for s in x]) or to loop over a copy (for s in x[:]). Removing elements during iteration has the mirror problem: the surviving elements slide down and the next one is skipped.

Tuples and Sequences

A tuple is an ordered, immutable sequence written in parentheses. Because it cannot change, it is the right container for fixed records (a coordinate, a date, a returned pair) and it is hashable, so it can be a dictionary key. Everything you learned about indexing and slicing transfers unchanged from strings and lists.

Singles, packing, unpacking and swapping
t = (1, 2, 3)
print(t[0], t[-1], t[1:], t.count(2), t.index(3), len(t))   # 1 3 (2, 3) 1 2 3

single = (42,)      # the comma makes it a tuple
not_tuple = (42)    # just the integer 42 in parentheses
print(type(single).__name__, type(not_tuple).__name__)      # tuple int

packed = 1, 2, 3    # packing
a, b, c = packed    # unpacking
x, y = 10, 20
x, y = y, x         # swap via tuple unpacking -- no temporary variable
print(a, b, c, x, y)   # 1 2 3 20 10

t[0] = 99           # TypeError: 'tuple' object does not support item assignment
Tuple immutability is not transitive

The tuple itself cannot be reassigned, but an object inside it can still be mutated. This is the detail that separates a full-mark answer from a half-mark one:

inner = (1, [2, 3])
inner[1].append(4)    # allowed: the tuple is unchanged, the list inside it is not
print(inner)          # (1, [2, 3, 4])

Dictionaries, Hashable Keys and Dictionary Methods

A dictionary stores data as key → value pairs in curly braces. It is mutable and, since Python 3.7, it remembers insertion order — so "unordered" answers written years ago are now only half true and should be qualified. Lookup by key is a hash lookup, not a scan, which is why it stays fast as the dictionary grows.

The key rule is the one that gets examined: keys must be hashable, i.e. immutable. Numbers, strings and tuples of immutables qualify. A list does not, and d[[1, 2]] = "x" raises TypeError: unhashable type: 'list'. Values may be absolutely anything, including lists and other dictionaries.

Access, update, delete and iterate
student = {"name": "Alice", "age": 20}
print(student["name"])            # Alice
print(student.get("age"))         # 20
print(student.get("marks", 0))    # 0     -- no KeyError, default returned
# student["marks"] would raise KeyError: 'marks'

student["age"] = 21               # update existing key
student["email"] = "a@mail.com"   # add new key
print(student.pop("email"))       # a@mail.com
print("email" in student)         # False
del student["age"]                # delete by key
print(student)                    # {'name': 'Alice'}

for k, v in student.items():
    print(k, "=", v)
print(list(student.keys()), list(student.values()), len(student))

d = {(1, 2): "tuple key works"}   # tuple key is fine
print(d[(1, 2)])
d[[1, 2]] = "x"                   # TypeError: unhashable type: 'list'

Sets — union, intersection and Set Methods

Exam note — beyond the printed unit list: set

Logical, Identity and Membership Operators

and, or and not do not return True or False; they return one of their operands. x or y evaluates x first and returns it if it is truthy, otherwise it returns y. x and y returns x if it is falsy, otherwise y. That is why 0 or "fallback" gives "fallback" and 3 and 4 gives 4 — and it is why they are called short-circuit operators: the right side is not even evaluated when the left already decides the answer.

Logical operators return operands
print(0 or "fallback")   # fallback
print("x" and "y")       # y
print(not 0)             # True
print(3 and 4)           # 4
print(0 and 4)           # 0     -- short-circuits, 4 never evaluated
print(1 < 7 < 10)        # True  -- chained comparison, not two separate tests

Identity (is, is not) asks whether two names refer to the same object — it compares id(). Equality (==) asks whether two objects have the same value. a = [1, 2] and b = [1, 2] are equal but not identical; b = a makes them both. Only None should be tested with is by convention, because there is exactly one None object.

Key Definitions

One-sentence definitions for the terms a paper asks you to define. Type comparisons and copy semantics are tabulated in their own sections.

Python

A high-level, interpreted, dynamically typed, object-oriented programming language created by Guido van Rossum in 1991, with automatic memory management and a large standard library.

Dynamic typing

The type of a value is established at runtime from the object a name is bound to, not declared in advance, so one name may refer to objects of different types over its lifetime.

Interpreted language

A language whose source is executed statement by statement by an interpreter at runtime, instead of being compiled and linked into a machine-code executable first.

Indentation

The leading whitespace that defines a block of statements in Python, replacing the braces of C-like languages; four spaces per level is the convention.

Mutability

The property of an object whose contents can be changed in place after creation. Immutable objects cannot be changed; any apparent change binds the name to a new object instead.

Operator precedence

The rule fixing which operator is applied first when an expression contains several of different rank. Associativity then decides the order among operators of equal rank.

Q 1

Who created the Python programming language?

  • a. Dennis Ritchie
  • b. James Gosling
  • c. Guido van Rossum
  • d. Bjarne Stroustrup
Answer: c. Guido van Rossum

Python was created by Guido van Rossum and first released in 1991.

Q 2

Which of the following is the correct way to define a single-element tuple in Python?

  • a. t = (42)
  • b. t = [42]
  • c. t = (42,)
  • d. t = {42}
Answer: c. t = (42,)

A single-element tuple requires a trailing comma. Without it, (42) is just an integer in parentheses, and type((42)) returns int.

Q 3

What is the output of print(-7 // 2)?

  • a. -3
  • b. -4
  • c. -3.5
  • d. 3
Answer: b. -4

Floor division rounds toward negative infinity, not toward zero. -7 / 2 is -3.5, and the floor of that is -4. This is the difference from C, where integer division truncates to -3.

Q 4

What is the value of 2 ** 3 ** 2?

  • a. 64
  • b. 512
  • c. 12
  • d. 36
Answer: b. 512

** is the only right-associative operator, so the expression groups as 2 ** (3 ** 2) = 2 ** 9 = 512. Grouping it left to right would give 64, which is the trap distractor.

Q 5

a = [1, 2, 3]. What does a.append(4) return?

  • a. [1, 2, 3, 4]
  • b. True
  • c. None
  • d. 4
Answer: c. None

All in-place mutating methods — append, extend, insert, remove, sort, reverse, clear — return None. The list itself becomes [1, 2, 3, 4], but the call's value is None, so a = a.append(4) destroys the list.

Q 6

What is the result of "Python"[1:4]?

  • a. "yth"
  • b. "ytho"
  • c. "Pyt"
  • d. "tho"
Answer: a. "yth"

The start index 1 is included and the stop index 4 is excluded, so the characters at positions 1, 2 and 3 are taken: y, t, h.

Q 7

Which of these can be used as a dictionary key?

  • a. [1, 2]
  • b. (1, 2)
  • c. {1, 2}
  • d. {"a": 1}
Answer: b. (1, 2)

Keys must be hashable, which in practice means immutable. A tuple of immutables is hashable; a list, a set and a dictionary are all mutable, so using any of them raises TypeError: unhashable type.

Q 8

a = [1, 2] and b = a. Now b.append(3). What is a?

  • a. [1, 2]
  • b. [1, 2, 3]
  • c. [3]
  • d. None
Answer: b. [1, 2, 3]

Assignment does not copy. Both names refer to one list object, so a change made through b is visible through a. To get an independent list you need b = a.copy() at the top level, or copy.deepcopy(a) for nested data.

Q 9

What is the output of print(0 or "fallback")?

  • a. False
  • b. 0
  • c. "fallback"
  • d. True
Answer: c. "fallback"

or returns one of its operands, not a boolean. Since 0 is falsy, the left operand is rejected and the right one is returned. Similarly 3 and 4 returns 4.

Q 10

With a, b = 5, 3, what is the value of a ^ b?

  • a. 1
  • b. 7
  • c. 6
  • d. 2
Answer: c. 6

XOR gives 1 only where the bits differ: 101 ^ 011 = 110, which is 6. For reference on the same pair, & gives 1 and | gives 7.

Q 11

Which statement about Python strings is true?

  • a. They are mutable, so s[0] = "X" works
  • b. They are immutable, so a method such as upper() returns a new string
  • c. They can only be written with double quotes
  • d. s[::-1] sorts the characters
Answer: b

Strings are immutable: item assignment raises TypeError, and every method returns a new string that you must assign back. Single, double and triple quotes all produce strings, and s[::-1] reverses rather than sorts.

Q 12

  • a. Returns -1
  • b. Returns None
  • c. Raises ValueError
  • d. Returns 0
Answer: c. Raises ValueError

Q 13

  • b. <class 'int'>
  • c. <class 'list'>
  • d. <class 'set'>
Answer: b. <class 'int'>

Parentheses alone only group; it is the comma that makes a tuple. (42,) is a tuple, (42) is the integer 42.

Q 14

  • a. None
  • b. lambda
  • c. True
  • d. print
Answer: d. print

print is a built-in function in Python 3, not a reserved word — which is why you can rebind it (and why doing so hides the function). None, True and lambda are all among the 35 keywords, and note the capital T and N.

Short Answer Questions

Q 1

What is dynamic typing in Python?

Dynamic typing means the type of the value is decided at runtime, from the object the name is bound to, instead of being fixed by a declaration at compile time. You do not declare int x; you write x = 10 and Python records that x now refers to an int. Rebind the same name to "ten" and it now refers to a str — the name itself never had a type. type(x) reveals the current type.

Q 2

What is the difference between / and // in Python?

/ is true division and always returns a float, even when the division is exact: 10 / 4 is 2.5 and 10 / 2 is 5.0. // is floor division: it divides and then rounds down toward negative infinity, so 10 // 3 is 3 but -7 // 2 is -4, not -3. Its result keeps the operand type, so 7.0 // 2 is 3.0.

Q 3

What is an f-string in Python? Give an example.

An f-string is a string literal prefixed with f or F in which any expression inside braces is evaluated and inserted at runtime (Python 3.6+). Example: name = "Alice"; score = 95.4567; print(f"{name} scored {score:.2f}") outputs Alice scored 95.46. It can hold arbitrary expressions (f"{age + 1}") and a format spec after a colon (:.2f).

Q 4

What is the difference between a list and a tuple?

A list ([1, 2]) is mutable and a tuple ((1, 2)) is immutable, so a tuple cannot be appended to or have an item reassigned. Both are ordered and indexable. Because a tuple cannot change it is hashable and can be a dictionary key, while a list cannot. Tuples use less memory and are the natural choice for a fixed record or a returned set of values. A one-element tuple needs a trailing comma: (42,).

Q 5

What does the % operator do, and what sign does its result carry?

% is the modulus operator: it returns the remainder left after floor division, so that a == (a // b) * b + (a % b). The result takes the sign of the divisor, not of the dividend — 7 % 3 is 1, -7 % 3 is 2 and 7 % -3 is -2. It is commonly used for divisibility tests (n % 2 == 0) and for digit extraction (n % 10 is the last digit).

Q 6

Why does Python need indentation, and what error appears when it is wrong?

Python has no braces or end keyword, so indentation is the block syntax: statements sharing an indent form one block, and dedenting closes it. The convention is four spaces per level. A missing, extra or inconsistent indent raises IndentationError; mixing tabs and spaces in the same block raises TabError, because Python 3 refuses to guess which you meant.

Q 7

What is the difference between is and == in Python?

== compares values, using the type's equality rules. is compares identity — whether both names refer to the very same object, which is what id() reports. So [1, 2] == [1, 2] is True but [1, 2] is [1, 2] is False, because they are two distinct objects; after b = a the two names are identical. By convention is is used only for None.

Q 8

Name any four string methods and state what each returns.

upper() returns a copy in capitals ("hi".upper() → "HI"). strip() returns a copy without leading and trailing whitespace (" hi ".strip() → "hi"). split(",") returns a list of pieces around the separator ("a,b".split(",") → ['a', 'b']). replace("l", "r") returns a copy with every occurrence replaced ("hello" → "herro"). All four return new strings because strings are immutable.

Long Answer Questions

Q 1

What is Python? Discuss its history and features, and distinguish interactive mode from script mode.

Definition (1). Python is a high-level, interpreted, dynamically typed, object-oriented programming language with automatic memory management and a large standard library.

History (2). Created by Guido van Rossum; published in 1991. Python 2.0 arrived in 2000 (list comprehensions, garbage collection) and Python 3.0 in 2008, which was deliberately not backward compatible — most visibly by turning print into a function. Python 2 reached end of life in 2020, so Python 3 is the only supported line.

Features (3 — state any six).

  • Interpreted — executed statement by statement, with no separate compile-and-link step.
  • High-level — memory is managed for you; no pointers and no manual allocation.
  • Dynamically typed — the type comes from the assigned object, so no declaration is needed.
  • Object-oriented — everything is an object, including integers and functions.
  • Free and open source, and cross-platform — one source file runs on Windows, Linux and macOS.
  • Extensive library plus third-party packages via pip; readable, because indentation exposes block structure.

Interactive vs script mode (2). Interactive mode is started by typing python3 and presents the >>> prompt; each statement executes as soon as it is entered and every bare expression is echoed automatically, which makes it ideal for testing one behaviour — but the session is lost when it closes. Script mode means writing a .py file and running python3 file.py: the whole file executes top to bottom, only print() produces output, and the program is saved and re-runnable. Both use the same interpreter, so behaviour is identical; only the echoing differs.

Q 2

Explain the categories of Python operators with one example of each, including a complete bitwise trace for a, b = 5, 3.

1. Arithmetic (1). + - * / // % **. Note that / always yields a float, // floors (-7 // 2 == -4) and ** is right-associative (2 ** 3 ** 2 == 512).

2. Relational / comparison (1). == != < > <= >=, returning a bool. They chain: 1 < x < 10 means both comparisons must hold.

3. Assignment (1). = plus the compound forms += -= *= /= //= %= **=, and the shorthands a, b = 1, 2 and a = b = 0.

4. Logical (1). and, or, not. They short-circuit and return an operand: 0 or "fallback" is "fallback"; 3 and 4 is 4.

5. Bitwise (2). Work on binary digits. With a, b = 5, 3, i.e. 101 and 011:

  • a & b = 101 & 011 = 001 → 1
  • a | b = 101 | 011 = 111 → 7
  • a ^ b = 101 ^ 011 = 110 → 6
  • ~a → −6, because ~x is defined as -(x + 1)
  • a << 1 = 1010 → 10 (×2 per shift)
  • a >> 1 = 10 → 2 (floor ÷2 per shift)

6. Membership (1). in and not in test a sequence: "a" in "cat" is True. Applied to a dictionary they test the keys.

7. Identity (1). is and is not compare object identity, not value: [1, 2] == [1, 2] is True while [1, 2] is [1, 2] is False.

Q 3

Compare lists, tuples and dictionaries, giving the properties, common operations and one suitable use for each.

List (2). Ordered, mutable, written [1, 2, 3], indexed by integer, duplicates allowed, may mix types. Operations: append, extend, insert, remove, pop, sort, reverse, plus len/min/max/sum and slicing. Because it is mutable it cannot be a dictionary key. Use: a collection that grows and changes — a shopping list, a queue of pending jobs.

Tuple (2). Ordered, immutable, written (1, 2, 3), indexed by integer, indexed and sliced like a list but with no mutating methods. Supports packing, unpacking and swapping (x, y = y, x). Only count() and index() are available. Immutability makes it hashable, so it can be a dictionary key. A single element needs a comma: (42,). Use: a fixed record or a function returning several values, e.g. (quotient, remainder).

Dictionary (2). Mutable mapping of unique keys to values, written {"a": 1}, accessed by key rather than position. Keys must be hashable; values may be anything. Lookup is O(1) on average. Operations: d[k] (raises KeyError), get(k, default) (does not), keys/values/items, update, pop, setdefault, del, and in which tests the keys. Insertion order is preserved from Python 3.7. Use: a lookup table — a student record keyed by roll number, or a frequency count of words.

Summary (2). Choose a list when order matters and content changes; a tuple when the content is fixed or must be hashable; a dictionary when you look values up by a name or id instead of a position. A list of tuples is a common pairing: ordered records that cannot be edited in place.

Q 4

Explain string indexing, slicing and immutability, and show three ways to format a string. Include a palindrome program.

Indexing (1). Each character has a position: non-negative from the left starting at 0, negative from the right starting at -1 for the last. s[0] is the first character, s[-1] the last. An out-of-range index raises IndexError.

Slicing (2). s[start:stop:step] returns a new string. start is included and stop is excluded; defaults are 0, len(s) and 1. "Python"[1:4] is "yth"; [:3] is "Pyt"; [3:] is "hon"; [::-1] reverses to "nohtyP"; an out-of-range stop is clamped rather than raising.

Immutability (2). No character can be replaced in place: s[0] = "J" raises TypeError: 'str' object does not support item assignment. Every apparent edit builds a new object and rebinds the name — s = "J" + s[1:]. Because the object cannot change, it is hashable (so a valid dictionary key) and safe to share.

Three formatting styles (1). "%s scored %.2f" % (name, score), "{} scored {:.2f}".format(name, score), and f"{name} scored {score:.2f}" — the last being the modern preference.

Palindrome program (2). Normalise before comparing, because case and punctuation are not part of the test:

def is_palindrome(text):
    clean = "".join(ch.lower() for ch in text if ch.isalnum())
    return clean == clean[::-1]

print(is_palindrome("Madam"))            # True
print(is_palindrome("No 'x' in Nixon"))  # True
print(is_palindrome("Python"))           # False

Q 5

Explain the built-in data types of Python and classify each as mutable or immutable. Illustrate the distinction with id(), and explain implicit versus explicit conversion.

Types (3). Numeric: int (unbounded integer), float (IEEE-754 double), complex (2+3j, with .real and .imag), and bool, which is a subclass of int so True + 1 == 2. Sequence: str and bytes. Collections: list, tuple, dict, set, plus array from the standard library. Special: NoneType, whose only value is None.

Mutability (2). Immutable: int, float, complex, bool, str, tuple, NoneType. Mutable: list, dict, set, and array.

The id() proof (1). id() returns an object's identity. After s += "d" the id changes, because a new string was built; after lst.append(3) the id is unchanged, because the same list was modified in place. That single comparison is the whole idea: immutability means every "change" is really a rebinding.

Implicit vs explicit conversion (2). Implicit (coercion) is automatic and only widens: 3 + 4.5 → 7.5, and 10 / 4 → 2.5. It never loses data and fails when the types cannot be reconciled — "3" + 4 raises TypeError. Explicit conversion is a function you call: int("42") → 42, int(3.99) → 3 (truncation does lose data), float("3.5"), str(99), bool("0") → True (any non-empty string is truthy), list("abc"), and ord("A")/chr(97) for characters.

Q 6

Explain operator precedence and associativity with the full precedence order, and evaluate 12 + 3 * 4 ** 2 // 8 - 5 % 3 step by step.

Definitions (2). Precedence decides which of several competing operators is applied first. Associativity only matters when two operators share the same precedence, and it decides the grouping: left to right, or right to left. In Python every operator associates left to right except **, which associates right to left.

Precedence, highest first (3). () grouping → ** → unary +x -x ~x → * / // % → + - → << >> → & → ^ → | → comparisons and membership (== < is in …) → not → and → or (lowest).

Step-by-step evaluation (3).

  • 4 ** 2 = 16 (highest after parentheses)
  • 3 * 16 = 48 (same level as //, left to right)
  • 48 // 8 = 6
  • 5 % 3 = 2 (same level, evaluated before the additions)
  • 12 + 6 = 18, then 18 - 2 = 16

Note the classic traps inside this one expression: the exponent is applied before the multiplication, and // and % bind tighter than + and -. Had the expression been 2 ** 3 ** 2, right-associativity would give 2 ** 9 = 512, not 64.

Q 2

Take two numbers and print the result of every arithmetic operator on them, including floor division and modulus.

Solution
a = float(input("Enter first number: "))
b = float(input("Enter second number: "))

print(f"{a} + {b}  = {a + b}")
print(f"{a} - {b}  = {a - b}")
print(f"{a} * {b}  = {a * b}")
print(f"{a} / {b}  = {a / b:.4f}")
print(f"{a} // {b} = {a // b}")
print(f"{a} % {b}  = {a % b}")
print(f"{a} ** {b} = {a ** b}")

Note that / and // disagree even on exact values, and that division by zero raises ZeroDivisionError — worth a guard if the question mentions robustness.

Q 3

Create a list of five names. Append a sixth, insert one at position 2, remove one by value, sort it, and print the length, the reversed list and a slice.

Solution
names = ["Ravi", "Sita", "Amit", "Neha", "John"]
names.append("Priya")        # add one at the end
names.insert(2, "Kiran")     # insert before index 2
names.remove("Amit")         # remove by value
names.sort()                 # in place -- returns None

print(len(names))
print(names[::-1])           # reversed copy, original untouched
print(names[1:4])

The trap: names = names.sort() would make names the value None. Call sort() as a statement, or use sorted(names) when you want a new list.

Q 4

Demonstrate string slicing and reversal, then apply at least four string methods to the same string, showing that the original is unchanged.

Solution
s = "  Hello Python  "
print(repr(s[2:7]))     # 'Hello'
print(repr(s[::-1]))    # '  nohtyP olleH  '

print(repr(s.strip()))          # 'Hello Python'
print(repr(s.strip().upper()))  # 'HELLO PYTHON'
print(repr(s.strip().replace("Python", "World")))  # 'Hello World'
print(s.strip().split())        # ['Hello', 'Python']
print(repr(" ".join(s.strip().split())))  # 'Hello Python'

print(repr(s))          # unchanged: '  Hello Python  '

Every method returned a new string and the last line proves the original survived. Methods chain because each one hands back a string.

Q 5

Demonstrate the difference between aliasing, a shallow copy and a deep copy using a nested list, and explain each printed line.

Solution
import copy

original = [1, [2, 3], 4]
alias = original
shallow = original.copy()
deep = copy.deepcopy(original)

original[0] = 99          # replace a TOP-LEVEL element
original[1][0] = 777      # mutate a NESTED element

print(alias)      # [99, [777, 3], 4]  same object -- sees both
print(shallow)    # [1, [777, 3], 4]   own outer list, shared inner list
print(deep)       # [1, [2, 3], 4]     independent at every level

alias shares the whole object. The shallow copy duplicated only the outer container, so the nested list is still one object in two places. deepcopy rebuilt the tree, which is why it shows neither change.

Q 6

Print the current date and time in three formats, and print the date exactly one week from today.

Solution
from datetime import datetime, date, timedelta

now = datetime.now()
print(now.strftime("%Y-%m-%d %H:%M:%S"))
print(now.strftime("%d/%m/%Y"))
print(now.strftime("%d-%b-%Y %I:%M %p"))

print(date.today() + timedelta(days=7))

timedelta is the only supported way to do date arithmetic — you cannot add an integer to a date. Note %m is the month and %M is the minute.

Revision

Quick Revision Points
  • Python was created by Guido van Rossum in 1991.
  • Python is interpreted, high-level, dynamically typed, and object-oriented.
  • Python uses indentation (4 spaces) to define code blocks — no curly braces.
  • Interactive mode uses >>> prompt. Script mode runs .py files.
  • Strings are immutable. Indexed from 0 (left) or -1 (right).
  • Slicing syntax: s[start:stop:step]. s[::-1] reverses a string.
  • f-strings (Python 3.6+): f"Hello {name}" — modern way to format strings.
  • List = mutable, ordered, []. Tuple = immutable, ordered, ().
  • Dictionary = key-value pairs, mutable, {}. Keys must be unique.
  • // = floor division. % = modulus. ** = exponentiation.
  • is checks identity (same object). == checks value equality.
  • Shallow copy: inner objects shared. Deep copy: fully independent.
  • Operator precedence: () → ** → unary → */%// → +- → comparisons → not → and → or.
  • datetime.now() for the current time; timedelta for date arithmetic.
Must Remember for Exam
  • Creator: Guido van Rossum, 1991.
  • Single-element tuple: Must have trailing comma — (42,) not (42).
  • / vs //: / gives float, // gives integer (floor).
  • Mutable: List, Dict, Array. Immutable: Tuple, String, int, float.
  • Deep copy: Requires import copy then copy.deepcopy().
  • Dictionary keys must be unique and immutable (strings, numbers, tuples).
  • Bitwise AND: 5 & 3 = 1 (0101 AND 0011 = 0001).
  • String reversal: s[::-1].
  • Highest precedence: Parentheses (). Lowest: or.
  • type() function returns the data type of a variable.
Common Mistakes in Exams
  • Writing (42) instead of (42,) for single-element tuple.
  • Confusing is with == — they check different things.
  • Using = instead of == in comparisons.
  • Forgetting that strings are immutable — you cannot do s[0] = "X".
  • Mixing tabs and spaces — causes IndentationError.
  • Forgetting the colon : at the end of if, for, def statements.
  • Accessing a dictionary key that doesn't exist causes KeyError — use .get() instead.
  • Confusing shallow copy with deep copy for nested lists.
  • Assuming / gives integer result — in Python 3, 10/3 = 3.333... not 3.
  • Forgetting import copy before using copy.deepcopy().
