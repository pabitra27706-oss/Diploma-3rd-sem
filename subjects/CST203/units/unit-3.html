Functions

Why functions exist

A function names a block of code so it can be called whenever it is needed, with different inputs. That gives three things a flat script cannot: the block is written once and used many times, the name documents what it does, and a bug has one place to be fixed.

Python has two kinds. A built-in function ships with the interpreter and is already there — print(), len(), sum(), max(), abs(), type(). A user-defined function is one you write with def. They are called in exactly the same way; the only difference is who wrote them and whether they are available without an import.

Defining, Calling and Returning

The shape of a function
def name(parameters):
    """optional docstring"""
    body
    return value

Three things must be said precisely about this, because each is examined separately:

  • The def line records the function; it does not run the body. The body runs only when the name is called with (). A function defined and never called produces no output at all.
  • Parameters are the names in the definition; arguments are the values in the call. The distinction is worth a mark in "differentiate" questions.
  • The body is indented, exactly like an if or for block, and the def line ends in a colon.
return — the four cases
def add(a, b):
    return a + b
print(add(3, 4))

def nothing():
    pass
print(nothing())

def both(a, b):
    return a + b, a * b
s, p = both(3, 4)
print(s, p, both(3, 4))

def first_and_last(items):
    return items[0], items[-1]
print(first_and_last([10, 20, 30]))

Output

7
None
7 12 (7, 12)
(10, 30)

Read the four cases off that output. add() returns one value. nothing() has no return, so Python returns None — not "nothing", the literal value None. both() returns two values, and Python packs them into a tuple (7, 12), which the caller unpacks with s, p = .... first_and_last() shows you can construct that tuple yourself.

return versus print

They are not interchangeable and this is the single most common lost mark in the unit. print() displays a value to the screen and returns None. return hands a value back to the caller, where it can be stored, tested or passed on. A function that prints but does not return gives the caller None:

def bad(a, b):
    print(a + b)    # caller gets None
def good(a, b):
    return a + b   # caller gets the value

bad(1, 2) shows 3 but x = bad(1, 2) leaves x as None.

A docstring is not a comment

The first statement inside a function may be a string literal. Python stores it as function.__doc__, and help(function) prints it. That is why the exam style is a one-line docstring rather than a # comment above the def.

Function Arguments

The four styles, in one ranking

Python lets a caller supply arguments in four ways. They are not alternatives you choose between freely — they are a ladder of increasing flexibility, and the exam asks you to distinguish all four:

  • Required (positional) — matched by position, must be supplied.
  • Keyword — matched by name, so order does not matter.
  • Default — has a value in the definition, so may be omitted.
  • Variable-length — *args collects extra positionals, **kwargs collects extra keywords.

Positional, Keyword and Default Arguments

All three, on one small function
def area(width, height):
    return width * height

print(area(4, 5))                  # positional
print(area(width=4, height=5))     # keyword
print(area(height=5, width=4))     # keyword, reversed order

def power(x, exp=2):
    return x ** exp

print(power(5), power(5, 3), power(5, exp=3))

Output

20
20
20
25 125 125

The three area() calls produce the same answer because the values are the same; only the mechanism differs. Positional matching pairs arguments to parameters left to right, so area(5, 4) is a different rectangle. Keyword matching uses the parameter names, so order is irrelevant.

power() shows a default: exp=2 is used when the caller omits it, and overridden when the caller supplies it — by position or by keyword.

Two rules that are always marked
  • A parameter with a default must come after all parameters without one. def f(a=1, b): is a SyntaxError. Python cannot decide what a positional argument would bind to.
  • A missing required argument raises TypeError, and so does an unexpected keyword: area(4) and area(4, 5, 6) both fail. Quote the error name, not just "error".
The mutable default trap

A default value is evaluated once, when the def line runs — not on every call. If the default is a mutable object, every call shares that one object.

Why bucket=[] is a bug
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item(1))
print(add_item(2))
print(add_item(3))

def add_item_safe(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

print(add_item_safe(1))
print(add_item_safe(2))

Output

[1]
[1, 2]
[1, 2, 3]
[1]
[2]

The first three calls accumulate into one list created at definition time. The fixed version uses None as the sentinel and builds a fresh list per call — the idiom to memorise.

Variable-Length Arguments: *args and **kwargs

The star collects; the type tells you what it collected
def total(*numbers):
    print("args type:", type(numbers).__name__, numbers)
    return sum(numbers)

print(total(1, 2, 3))
print(total())

def profile(**info):
    print("kwargs type:", type(info).__name__, info)
    for k, v in info.items():
        print(f"  {k} = {v}")

profile(name="Asha", branch="CST")

Output

args type: tuple (1, 2, 3)
6
args type: tuple ()
0
kwargs type: dict {'name': 'Asha', 'branch': 'CST'}
  name = Asha
  branch = CST

*numbers packs all extra positional arguments into a tuple — empty if there are none, which is why total() returns 0 rather than failing. **info packs extra keyword arguments into a dict. The name args/kwargs is only a convention; the star is what matters.

The full signature order
def order(a, b=2, *rest, scale=1, **extra):
    return (a, b, rest, scale, extra)

print(order(1, 3, 5, 7, scale=10, note="x"))

Output

(1, 3, (5, 7), 10, {'note': 'x'})

The order is fixed: positional, then default, then *args, then keyword-only, then **kwargs. Anything after *rest can only be passed by keyword. This one line answers "write the general form of a function signature".

Passing a List to a Function

Python passes the reference, not a copy

When you call f(my_list), the parameter name is bound to the same list object. A method that mutates in place — append(), sort(), pop() — therefore changes the caller's list. Rebinding the name inside the function (items = items.copy()) does not.

Mutation versus a defensive copy
def mutate(items):
    items.append("added")

def protect(items):
    items = items.copy()
    items.append("added")

a = ["x"]
mutate(a)
print(a)

b = ["x"]
protect(b)
print(b)

Output

['x', 'added']
['x']

mutate() reaches into the caller's list. protect() rebinds its own local name to a copy, so the caller's list is untouched. Say which one the question wants: "print the total of a list" needs neither, but "do not modify the input" requires the copy.

Exam note — lambda and recursion sit just outside the printed syllabus

The Revised-2022 syllabus lists def, arguments, return and scope for functions; it does not name anonymous functions or recursion. They are still asked — 15 marks across 2023–2026 — so they are covered here as a clearly marked extension rather than silently dropped.

A lambda is a one-expression function

Why lambda is used at all

Not for brevity alone. It lets you pass behaviour as an argument without inventing a name for a function used exactly once. Assigning a lambda to a name (square = lambda x: ...) is legal but considered poor style — that case should be a def. The idiomatic use is the callback argument.

Recursion — a function that calls itself
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(5))
for n in [0, 1, 5]:
    print(n, factorial(n))

Output

  120
0 1
1 1
5 120

Two parts are mandatory and both are marked. The base case n <= 1 stops the recursion — without it the calls never end and Python raises RecursionError after about a thousand frames. The recursive case n * factorial(n - 1) must move towards the base case; each call reduces n by one. The trace for factorial(5) is 5 × 4 × 3 × 2 × 1, and factorial(0) returns 1 by convention.

Variable Scope

Scope decides which x you mean

A namespace is the mapping from names to objects. Scope is the region of a program where a name resolves to a particular namespace. When two functions both use a variable called count, scope is what keeps them from colliding.

Python resolves a name by searching four levels, in a fixed order, remembered as LEGB:

  • Local — inside the current function.
  • Enclosing — an outer function, if this one is nested inside it.
  • Global — the module (the whole .py file).
  • Built-in — names Python provides, such as len and print.

The search stops at the first match. That is the whole rule; everything below is a consequence of it.

LEGB: local, global and nonlocal

Reading and assigning are not symmetric

Reading a name searches all four levels. Assigning to a name makes it local to the current function, full stop. So a function can read a global and then fail the moment it also assigns to it.

global, nonlocal, shadowing and the UnboundLocalError
count = 0

def bump():
    global count
    count += 1

bump(); bump()
print("global count =", count)

def outer():
    total = 0
    def inner():
        nonlocal total
        total += 1
        return total
    inner(); inner()
    return total
print("nonlocal total =", outer())

def shadow():
    count = 99
    return count
print("local shadow =", shadow(), "| global still", count)

def broken():
    print(count)
    count = 5

try:
    broken()
except UnboundLocalError as e:
    print("UnboundLocalError:", e)

Output

global count = 2
nonlocal total = 2
local shadow = 99 | global still 2
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

Four separate examinable facts sit in that output:

  • global count makes the bump() assignments write to the module-level name. Without the declaration, count += 1 would raise UnboundLocalError — it reads before assigning.
  • nonlocal total does the same for the enclosing function variable. global and nonlocal are not interchangeable: nonlocal will not reach a module-level name, and global will not reach an outer function's.
  • shadow() creates a new local named count. The global is untouched — shadowing, not assignment.
  • broken() prints before assigning, but Python has already decided count is local for the whole function body (from the assignment), so the read fails. Reversing the two lines removes the error, which is why the rule is "assignment anywhere in the function makes the name local everywhere in it".

Class Namespace Scope

A class body is a namespace, but not an enclosing scope

Names defined directly in a class body belong to the class, and are reached as ClassName.attr. Names assigned to self belong to each instance. Methods do not see class-level names as "enclosing" — there is no E level for a class — so a method must qualify the access explicitly.

Class attribute versus instance attribute
class Counter:
    total = 0                 # class attribute, shared by all instances
    def __init__(self):
        self.val = 0          # instance attribute, one per instance
    def inc(self):
        self.val += 1
        Counter.total += 1    # must qualify the class name

c1, c2 = Counter(), Counter()
c1.inc(); c2.inc(); c1.inc()
print("instance vals:", c1.val, c2.val, "| class total:", Counter.total)

Output

instance vals: 2 1 | class total: 3

c1.val is 2 and c2.val is 1 because each instance has its own val. Counter.total is 3 because it is shared. Writing self.total += 1 instead would create an instance attribute that shadows the class one — the total would then be wrong, and that mistake is the usual reason this question is set.

Modules

A module is just a .py file

Any file ending in .py is a module. Its functions, classes and top-level variables become its attributes, and import gives you access to them. There is no registration step and no special syntax inside the file — the filename is the module name, minus the extension.

That gives the two reasons modules exist: reuse (write calc.add() once, use it in ten programs) and separation (a 900-line script becomes six files whose names say what they do).

Creating a Module and the Four import Forms

A 7-line module, calc.py
"""A module: one .py file."""

def add(a, b):
    return a + b

def main():
    print("calc module self-test:", add(2, 3))

if __name__ == "__main__":
    main()

Run it directly (python3 calc.py) and the self-test prints calc module self-test: 5. Import it (import calc) and the self-test does not run — __name__ is "calc", not "__main__", so the guard is false.

The four import styles, all in force
import math                       # module name, dotted access
import math as m                  # aliased
from math import sqrt, pi         # names copied into your namespace
from math import *                # everything -- avoid

print(math.sqrt(16))
print(m.sqrt(81))
print(sqrt(81), round(pi, 2))

Output

Why from module import * is the wrong answer

It copies every public name into your namespace, so a later e = 2.718 or a function you define called sqrt silently breaks code that relied on the imported one. It also defeats every tool that tells you where a name came from. The exam phrasing is usually "why should wildcard imports be avoided" — the answer is namespace pollution and hidden name collisions.

The functions the paper actually names

sys.argv is always a list of strings. Index 0 is the script's own name, so real arguments start at index 1 — forget that and every argument is off by one. Because they are strings, a numeric argument needs int(sys.argv[1]).

The __name__ guard belongs in every module

if __name__ == "__main__": is true only when the file is run directly. It lets a file be both a runnable script and an importable module, without the self-test firing on import. This is a standard 2-mark answer and it also appears in the practical lab.

Packages & pip

A package is a folder of modules

A module is one .py file. A package is a directory of modules with an __init__.py file inside it. The __init__.py is what tells Python "this directory is importable" — it may be empty, and often is.

So the relationship is one of containment: a package groups modules, and modules contain functions. A package can contain sub-packages, giving a tree of any depth.

Module versus Package, with Directory Structure

The three package files, and importing from them
# shop/__init__.py
"""A tiny package. __init__.py marks the directory as a package."""
print("shop package imported")

# shop/billing.py
def total(prices, tax=0.05):
    return round(sum(prices) * (1 + tax), 2)

# shop/cart.py
def line_count(items):
    return len(items)

Then, from the folder containing shop/:

import shop
from shop.billing import total
from shop import cart

print(total([100, 200]))
print(cart.line_count(["a", "b", "c"]))

Output

shop package imported
315.0
3

Two things to notice. import shop runs __init__.py, which is why its print appears — that is all __init__.py means by "initialise the package". And from shop.billing import total walks the path: package shop, module billing, function total.

Installing Packages with pip

pip is Python's package installer. It downloads a package from PyPI (the Python Package Index) and installs it into your environment, after which import works exactly as for a standard-library module.

Key Definitions

Function

A named block of statements that can be called repeatedly with different inputs. Defined with def, it may take parameters and may return a value with return; without one it returns None.

Parameter and argument

A parameter is a name in the function definition. An argument is a value supplied in the call. def f(a, b) has parameters a, b; f(1, 2) passes arguments 1, 2.

Namespace

The mapping from names to objects. Each module, function and class body gets its own namespace, which is what allows the same name to mean different things in different places.

Scope and the LEGB rule

The region where a name resolves. Python searches Local → Enclosing → Global → Built-in and stops at the first match. Assignment inside a function creates a local name unless global or nonlocal declares otherwise.

Module

Any .py file. Its functions, classes and variables are its attributes, reached after import. It provides reuse and separates a large program into named files.

Package

A directory of related modules containing an __init__.py, which is what makes it importable. It groups modules into one distributable unit and may contain sub-packages.

pip

Python's package installer. It downloads a package from PyPI, installs it and its dependencies, so that import then works as for a standard-library module.

Recursion

A function that calls itself. It needs a base case that returns without recursing, and a recursive case that moves towards the base case; otherwise it runs until RecursionError.

lambda

An anonymous function written as a single expression: lambda params: expression. It has no statements and no docstring, and its expression's value is returned implicitly.

Multiple Choice Questions

Q 1

A function has no return statement. What does it return?

  • a. 0
  • b. None
  • c. an empty string
  • d. nothing — calling it is a syntax error
Answer: b. None

Python falls off the end of a function body and returns None implicitly. print(f()) would show None.

Q 2

Which is the correct signature order?

  • a. def f(*args, b=1, **kw):
  • b. def f(a, b=1, *args, **kw):
  • c. def f(a=1, b, *args):
  • d. def f(**kw, a, b=1):
Answer: b

Positional, then default, then *args, then keyword-only, then **kwargs. Option c is a SyntaxError because a non-default follows a default.

Q 3

What is the type of the value collected by *args?

  • a. list
  • b. dict
  • c. tuple
  • d. set
Answer: c. tuple

*args packs extra positionals into a tuple; **kwargs packs extra keywords into a dict. Verified: def s(*a): return type(a).__name__ gives 'tuple'.

Q 4

Why is def f(items=[]) a bug?

  • a. Lists cannot be default values
  • b. The default is evaluated once, so every call shares one list
  • c. The list is copied on every call, which is slow
  • d. It is not a bug
Answer: b

Evaluated once, when the def executes — so all calls share one list. Three calls return lengths 1, 2, 3. Use None as the sentinel.

Q 5

What does print(area(4)) do for def area(w, h): ...?

  • a. Prints None
  • b. Uses h = 0
  • c. Raises TypeError
  • d. Raises ValueError
Answer: c. TypeError

A required argument is missing: "area() missing 1 required positional argument: 'h'". There is no implicit zero default.

Q 6

What does from math import * do?

  • a. Imports only math itself
  • b. Copies every public name from math into your namespace
  • c. Imports nothing until you call a function
  • d. Is a syntax error
Answer: b

Namespace pollution: sqrt, pi and dozens more arrive unbidden and can overwrite your names.

Q 7

What makes a directory an importable Python package?

  • a. A main.py inside it
  • b. An __init__.py inside it
  • c. A requirements.txt inside it
  • d. Its name ending in _pkg
Answer: b. __init__.py

It marks the directory as a package and runs when the package is imported. It may be empty.

Q 8

In sys.argv, what is index 0?

  • a. The first command-line argument
  • b. The Python version
  • c. The script's own name
  • d. The current working directory
Answer: c. The script's own name

Real arguments start at index 1, which is why sys.argv[1:] is the argument list. Running python3 g.py alpha beta gives a length of 3.

Q 10

What does def broken(): print(x); x = 5 raise when called, given a global x?

  • a. Nothing — it prints the global x
  • b. NameError
  • c. UnboundLocalError
  • d. SyntaxError
Answer: c. UnboundLocalError

The assignment makes x local for the whole body, so the earlier read hits an uninitialised local. It is a subclass of NameError.

Q 12

A function receives a list and calls items.append(x). What does the caller see?

  • a. Nothing — the list is copied on the way in
  • b. The caller's list now contains x
  • c. A TypeError
  • d. The list is unchanged but the function returns the new one
Answer: b

The parameter is bound to the same object, so an in-place method mutates the caller's list. To avoid it, pass items.copy().

Short Answer Questions

Q 1

Differentiate between a parameter and an argument.

A parameter is the name written in the function definition. An argument is the value supplied at the call.

In def area(width, height): ... followed by area(4, 5), width and height are parameters; 4 and 5 are arguments. Parameters exist only while the function is being defined and executed; arguments are the caller's data.

Q 2

What is the difference between return and print() inside a function?

print() sends text to the screen and its own return value is None. return ends the function and hands a value back to the caller, where it can be stored or used.

So x = print(5) leaves x as None, while x = f() for a function that returns 5 leaves x as 5. A function with no return at all also returns None.

Q 3

Name the four types of function arguments in Python and give one line each.

  • Required / positional — matched left to right; omitting one raises TypeError.
  • Keyword — matched by parameter name, so order is free: area(height=5, width=4).
  • Default — given a value in the definition and therefore optional: def power(x, exp=2). Must follow all non-default parameters.
  • Variable-length — *args collects extra positionals into a tuple; **kwargs collects extra keywords into a dict.

Q 4

Explain the LEGB rule in one short paragraph.

When Python meets a name it searches four namespaces in order: Local (the current function), Enclosing (an outer function, for nested functions), Global (the module) and Built-in (names Python provides). The first match wins and the search stops.

The asymmetry to remember: reading searches all four levels, but assigning to a name inside a function creates a local one unless global or nonlocal says otherwise.

Q 5

How does a module differ from a package, and what file makes the difference?

A module is a single .py file containing functions, classes or variables. A package is a directory that groups modules, and it must contain an __init__.py file — that file is the difference.

So calc.py is a module imported as import calc; shop/ containing __init__.py, billing.py and cart.py is a package imported as from shop.billing import total. A package can nest sub-packages; a module cannot.

Q 6

What is the purpose of if __name__ == "__main__":?

__name__ is "__main__" when the file is run directly, and the module's own name when the file is imported. The guard therefore runs the block below it only in the first case.

That lets one file be both a runnable script and an importable module: a self-test or demo can run when you execute the file, and will not fire when another program imports its functions.

Long Answer Questions

Q 1 (8 marks)

a) Explain the four types of function arguments in Python with examples. b) What happens if a required argument is omitted?

a) Python matches arguments to parameters in four ways.

1. Required (positional). Matched by position; all must be supplied.

def area(width, height):
    return width * height
print(area(4, 5))        # 20

2. Keyword. Matched by name, so order is irrelevant.

print(area(height=5, width=4))    # 20

3. Default. Given a value in the definition; may be omitted. A default parameter must come after all non-default ones.

def power(x, exp=2):
    return x ** exp
print(power(5), power(5, 3))      # 25 125

4. Variable-length. *args packs extra positionals into a tuple; **kwargs packs extra keywords into a dict.

def total(*numbers):
    return sum(numbers)
print(total(1, 2, 3), total())    # 6 0

def profile(**info):
    return info
print(profile(name="Asha"))       # {'name': 'Asha'}

The general signature order is positional, default, *args, keyword-only, **kwargs, e.g. def order(a, b=2, *rest, scale=1, **extra).

b) Omitting a required argument raises TypeError, with a message naming the missing parameter: area(4) gives "area() missing 1 required positional argument: 'height'". Supplying too many also raises TypeError. There is no implicit zero.

Q 2 (8 marks)

a) Explain local, global and nonlocal scope with examples. b) What is a class namespace?

a) Names resolve in the order Local → Enclosing → Global → Built-in (LEGB); the first match wins.

Local. Created by assignment inside a function, and destroyed when the call ends.

def f():
    x = 10          # local
    return x

Global. Created at module level. A function can read it freely, but assigning needs the global declaration, or Python creates a new local:

count = 0
def bump():
    global count
    count += 1
bump(); bump()
print(count)          # 2

Without global, count += 1 raises UnboundLocalError — the assignment makes count local for the whole body, so the read finds it uninitialised.

Nonlocal. For a nested function, targets the enclosing function's variable (there is no nonlocal target at module level):

def outer():
    total = 0
    def inner():
        nonlocal total
        total += 1
    inner(); inner()
    return total
print(outer())        # 2

b) Class namespace. The body of a class is its own namespace. Names assigned directly in it are class attributes, shared by every instance and reached as ClassName.attr; names assigned to self are instance attributes, one per object. A method must qualify a class attribute explicitly:

class Counter:
    total = 0
    def __init__(self):
        self.val = 0
    def inc(self):
        self.val += 1
        Counter.total += 1

Writing self.total += 1 would create an instance attribute that shadows the class one, so the shared total would stop counting.

Q 3 (8 marks)

a) Explain how to import a module, giving the four styles. b) Explain the role of pip in installing packages.

a) A module is any .py file. Four styles:

import math                    # dotted access: math.sqrt(16)
import math as m               # alias: m.sqrt(16)
from math import sqrt, pi      # names into your namespace: sqrt(16)
from math import *             # everything -- avoid

The fourth is discouraged because it copies every public name into your namespace, silently overwriting your own names and making it impossible to tell where a name came from — namespace pollution. For a module of your own the same applies: calc.py is imported with import calc, and its functions are called as calc.add(1, 2).

b) pip is Python's package installer. It fetches a package from PyPI and installs it so that import works like any standard-library module. Key commands:

  • pip install requests — install, with dependencies.
  • pip uninstall requests — remove.
  • pip list / pip show requests — inspect.
  • pip freeze > requirements.txt then pip install -r requirements.txt — record and reproduce the exact environment, which is how a project is shared.

Q 4 (8 marks)

a) Differentiate between a module and a package, with a directory example. b) Explain lambda with a use case.

a) A module is one .py file; a package is a directory of modules containing __init__.py.

shop/
    __init__.py     # marks the directory as a package
    billing.py      # a module inside it
    cart.py         # another module
from shop.billing import total
print(total([100, 200]))     # 315.0

import shop executes __init__.py, which is what "initialising a package" means. A package can contain sub-packages; a module cannot. Purpose: a package groups related modules into one distributable unit.

b) lambda is an anonymous function written as a single expression:

square = lambda x: x * x
print(square(7))                      # 49

Its value is that behaviour can be passed as an argument without naming a function used once:

pairs = [("b", 2), ("a", 3), ("c", 1)]
print(sorted(pairs, key=lambda p: p[1]))
# [('c', 1), ('b', 2), ('a', 3)]

print(list(map(lambda n: n * 2, [1, 2, 3])))     # [2, 4, 6]

Differences from def: a lambda has exactly one expression (no statements, no docstring, no return keyword — the expression's value is returned). Assigning a lambda to a name is legal but poor style; the idiomatic use is the inline callback.

Practice Problems

Q 1

Write a function that accepts any number of marks and returns their average, handling the empty case.

Solution
def average(*marks):
    if not marks:
        return 0.0
    return sum(marks) / len(marks)

print(average(70, 80, 90))
print(average())
print(average(55))

Output

80.0
0.0
55.0

*marks is a tuple, so the guard uses truthiness: an empty tuple is falsy. Without the guard, average() would divide by zero.

Q 2

Write a function that returns both the largest and smallest value in a list, without using max() or min().

Solution
def bounds(values):
    if not values:
        return None, None
    low = high = values[0]
    for v in values[1:]:
        if v < low:
            low = v
        elif v > high:
            high = v
    return low, high

print(bounds([3, 9, -2, 7]))
low, high = bounds([42])
print(low, high, bounds([]))

Output

(-2, 9)
42 42 (None, None)

The function returns a tuple of two values, which the caller unpacks. Seeding both with values[0] is what makes a single-element list work without a special case.

Q 3

Create a module calc.py with add and sub, guard a self-test, and use it from another file.

calc.py
"""Simple arithmetic module."""

def add(a, b):
    return a + b

def sub(a, b):
    return a - b

if __name__ == "__main__":
    print("self-test:", add(2, 3), sub(5, 2))
main.py in the same folder
import calc

print(calc.add(10, 5))
print(calc.sub(10, 5))

python3 calc.py → self-test: 5 3

python3 main.py → 15 then 5, with no self-test line — on import __name__ is "calc", so the guard is false.

Q 4

Build a package shop/ with billing.py and cart.py, then import from both.

Layout and files
shop/
  __init__.py      # may be empty; marks the package
  billing.py
  cart.py

    return len(items)

Two import shapes are shown on purpose: from shop.billing import total reaches a function, from shop import cart reaches a module. Both work because __init__.py is present.

Q 5

Write a recursive function for the sum of the first n natural numbers, and show the call trace for n = 4.

Solution
def total(n):
    if n <= 0:
        return 0
    return n + total(n - 1)

print(total(4))

Output: 10

CallReturnsValue
total(0)0 (base case)0
total(1)1 + total(0)1
total(2)2 + total(1)3
total(3)3 + total(2)6
total(4)4 + total(3)10

Calls descend to the base case and the values come back up the stack in reverse order. Without n <= 0 the recursion would never stop and Python raises RecursionError.

Revision

The points that decide the marks
  • def only records a function; the body runs when it is called. A function with no return returns None.
  • return hands a value back; print only displays it. A function that prints and does not return gives the caller None.
  • Two values returned are packed into a tuple, unpacked by the caller.
  • Parameter order is fixed: positional, default, *args, keyword-only, **kwargs. A non-default after a default is a SyntaxError.
  • *args is a tuple; **kwargs is a dict.
  • Default values are evaluated once — never use a mutable default; use None as the sentinel.
  • Passing a list binds the same object, so in-place methods mutate the caller's list; items.copy() prevents it.
  • LEGB: Local → Enclosing → Global → Built-in, first match wins.
  • Assigning inside a function makes the name local everywhere in it — hence UnboundLocalError. Use global or nonlocal to assign outwards.
  • A class attribute is shared and reached by the class name; self.x is per instance.
  • A module is a .py file; a package is a directory with __init__.py.
  • from x import * pollutes the namespace; sys.argv[0] is the script name.
  • lambda = one expression, implicit return; recursion needs a base case.
Must remember for the exam
  • area(4) for def area(w, h) raises TypeError, not a default of 0.
  • Three calls to def f(items=[]) return lengths 1, 2, 3 — one shared list.
  • factorial(4) is 24; factorial(0) is 1 by the base case.
  • print(area(height=5, width=4)) works because keyword order is free.
  • pip freeze > requirements.txt then pip install -r requirements.txt reproduces an environment.
  • import shop runs shop/__init__.py.
Where marks are lost
  • Writing print where the question says the function must return a value.
  • Claiming Python passes arguments by value or by reference — it passes the object reference; say what that means for a mutable argument.
  • Confusing global with nonlocal.
  • Putting from math import * in an answer as if it were good style.
  • Saying a package "is a big module" — it is a directory of modules with __init__.py.
  • Writing a recursive function with no base case, or one whose recursion does not approach it.
  • Forgetting that sys.argv[0] is the script name, so arguments start at 1.
