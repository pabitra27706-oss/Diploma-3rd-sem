MVC Architecture

What is MVC?

MVC (Model-View-Controller) is a software design pattern that separates an application into three interconnected components. This separation makes code organized, maintainable, and reusable. It is the foundation of most modern web frameworks.

M

Model

Handles data and business logic. Communicates with the database. Defines data structure.

V

View

Handles presentation — what the user sees. Renders HTML. Displays data from the Model.

C

Controller

Handles user input. Coordinates between Model and View. Contains application logic.

MVC Request-Response Flow
  1. User sends a request (e.g., clicks a link or submits a form).
  2. The Controller receives the request and processes it.
  3. The Controller queries the Model for data.
  4. The Model returns data to the Controller.
  5. The Controller passes data to the View.
  6. The View renders the HTML and sends the response back to the user.
Django uses MVT — not MVC

Django follows a slight variation called MVT (Model-View-Template):

MVC ComponentDjango EquivalentDjango File
ModelModelmodels.py
View (presentation)Templatetemplates/*.html
Controller (logic)Viewviews.py
URL routingURL Confurls.py

In Django: View = business logic (like Controller). Template = HTML presentation (like View in MVC).

URLs and Templates

URL Patterns in urls.py

Django uses urls.py to map URL paths to view functions. When a request comes in, Django checks the URL patterns in order and calls the matching view.

urls.py Examples
# myproject/urls.py (Root URL config)
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('myapp.urls')),    # Include app URLs
]

# myapp/urls.py (App-level URL config)
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
    path('about/', views.about, name='about'),
    path('student//', views.student_detail, name='student_detail'),
    path('search/', views.search, name='search'),
]

# Path converters:
#    → integer
#  → string
#    → slug (letters, numbers, hyphens)
Views in views.py

A view in Django is a Python function (or class) that receives an HTTP request and returns an HTTP response. It contains the business logic — fetching data, processing it, and passing it to a template.

views.py Examples
# myapp/views.py
from django.shortcuts import render
from django.http import HttpResponse

# Simple view — returns plain text
def home(request):
    return HttpResponse("Hello, Django!")

# View with template rendering
def about(request):
    context = {
        "title": "About Us",
        "description": "This is a Django demo."
    }
    return render(request, "myapp/about.html", context)

# View with URL parameter
def student_detail(request, id):
    # In real app, fetch from database
    student = {"id": id, "name": "Alice", "grade": "A"}
    return render(request, "myapp/student.html", {"student": student})

# View with query parameters (?q=search_term)
def search(request):
    query = request.GET.get("q", "")
    return render(request, "myapp/search.html", {"query": query})
Django Templates

Templates are HTML files with special Django Template Language (DTL) tags. They are stored in a templates/ directory. Django fills in the data passed from views and renders the final HTML.

Django Template Language (DTL) Syntax
<!-- Variable output -->
<h1>{{ title }}</h1>
<p>Student: {{ student.name }}</p>

<!-- if tag -->
{% if user.is_authenticated %}
    <p>Welcome, {{ user.username }}!</p>
{% else %}
    <p>Please log in.</p>
{% endif %}

<!-- for tag — iterating a list -->
<ul>
{% for student in students %}
    <li>{{ student.name }} — {{ student.grade }}</li>
{% empty %}
    <li>No students found.</li>
{% endfor %}
</ul>

<!-- Filters -->
<p>{{ title|upper }}</p>           <!-- Uppercase -->
<p>{{ title|lower }}</p>           <!-- Lowercase -->
<p>{{ date_field|date:"d/m/Y" }}</p> <!-- Format date -->
<p>{{ text|truncatewords:10 }}</p>  <!-- Truncate to 10 words -->
<p>{{ price|floatformat:2 }}</p>    <!-- 2 decimal places -->
<p>{{ items|length }}</p>           <!-- Count items -->

<!-- URL tag -->
<a href="{% url 'home' %}">Home</a>
<a href="{% url 'student_detail' id=5 %}">Student 5</a>

<!-- Comment -->
{# This is a template comment — not visible in HTML #}
Template Inheritance

Template inheritance allows you to define a base template with the common layout (header, navbar, footer) and extend it in child templates. This avoids repeating the same HTML in every page.

Base Template and Child Template
<!-- templates/base.html — Base template -->
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}My Site{% endblock %}</title>
    {% load static %}
    <link rel="stylesheet" href="{% static 'css/style.css' %}">
</head>
<body>
    <nav>
        <a href="{% url 'home' %}">Home</a>
        <a href="{% url 'about' %}">About</a>
    </nav>

    <main>
        {% block content %}
        <!-- Child templates fill this block -->
        {% endblock %}
    </main>

    <footer>
        <p>Copyright 2024</p>
    </footer>
</body>
</html>

<!-- templates/myapp/about.html — Child template -->
{% extends "base.html" %}

{% block title %}About Us{% endblock %}

{% block content %}
    <h1>{{ title }}</h1>
    <p>{{ description }}</p>
{% endblock %}

Django Forms

HTML Form and request.POST

The simplest way to handle forms is to write plain HTML forms and process the submitted data in a view using request.POST.

Manual HTML Form
<!-- templates/myapp/contact.html -->
<form method="POST" action="{% url 'contact' %}">
    {% csrf_token %}
    <label>Name:</label>
    <input type="text" name="name" required>

    <label>Email:</label>
    <input type="email" name="email" required>

    <label>Message:</label>
    <textarea name="message"></textarea>

    <button type="submit">Send</button>
</form>
Processing in views.py
# myapp/views.py
from django.shortcuts import render, redirect

def contact(request):
    if request.method == "POST":
        name = request.POST.get("name")
        email = request.POST.get("email")
        message = request.POST.get("message")
        # Process the data (save to DB, send email, etc.)
        print(f"From: {name} <{email}>: {message}")
        return redirect("success")
    return render(request, "myapp/contact.html")
CSRF Protection

Every POST form in Django must include {% csrf_token %} inside the <form> tag. This is a security token that prevents Cross-Site Request Forgery attacks. Without it, Django will reject the form submission with a 403 error.

Django Form Class (forms.Form)

Django provides a Form class to define forms in Python code. This is cleaner, more reusable, and provides automatic validation.

forms.py — Creating a Form Class
# myapp/forms.py
from django import forms

class ContactForm(forms.Form):
    name = forms.CharField(
        max_length=100,
        label="Your Name",
        widget=forms.TextInput(attrs={"placeholder": "Enter name"})
    )
    email = forms.EmailField(
        label="Email Address"
    )
    age = forms.IntegerField(
        min_value=1,
        max_value=120,
        required=False
    )
    message = forms.CharField(
        widget=forms.Textarea(attrs={"rows": 4}),
        label="Your Message"
    )
    subject = forms.ChoiceField(
        choices=[
            ("general", "General Inquiry"),
            ("support", "Technical Support"),
            ("billing", "Billing")
        ]
    )
views.py — Using the Form Class
# myapp/views.py
from django.shortcuts import render, redirect
from .forms import ContactForm

def contact(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            # Access cleaned data
            name = form.cleaned_data["name"]
            email = form.cleaned_data["email"]
            message = form.cleaned_data["message"]

            # Process data here
            print(f"Valid form from {name}")
            return redirect("success")
        # If invalid, form with errors is returned
    else:
        form = ContactForm()   # Empty form for GET request

    return render(request, "myapp/contact.html", {"form": form})

Form Validation and cleaned_data

When form.is_valid() is called, Django validates all fields. If valid, form.cleaned_data contains the cleaned (validated and converted) data as Python types.

Custom Validation in forms.py
# myapp/forms.py
from django import forms

class RegistrationForm(forms.Form):
    username = forms.CharField(max_length=50)
    password = forms.CharField(widget=forms.PasswordInput)
    confirm_password = forms.CharField(widget=forms.PasswordInput)
    age = forms.IntegerField()

    # Custom field-level validation
    def clean_username(self):
        username = self.cleaned_data.get("username")
        if " " in username:
            raise forms.ValidationError("Username cannot contain spaces.")
        return username

    def clean_age(self):
        age = self.cleaned_data.get("age")
        if age < 18:
            raise forms.ValidationError("You must be at least 18 years old.")
        return age

    # Cross-field validation
    def clean(self):
        cleaned_data = super().clean()
        password = cleaned_data.get("password")
        confirm = cleaned_data.get("confirm_password")
        if password and confirm and password != confirm:
            raise forms.ValidationError("Passwords do not match.")
        return cleaned_data
ModelForm (forms.ModelForm)

A ModelForm automatically generates form fields from a Django Model. This avoids duplicate field definitions — the model defines the data structure and the ModelForm creates the form from it.

ModelForm Example
# myapp/models.py
from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
    age = models.IntegerField()
    grade = models.CharField(max_length=2)
    enrolled = models.DateField(auto_now_add=True)

    def __str__(self):
        return self.name

# myapp/forms.py
from django import forms
from .models import Student

class StudentForm(forms.ModelForm):
    class Meta:
        model = Student
        fields = ["name", "email", "age", "grade"]
        # OR: fields = "__all__"  (include all fields)
        # OR: exclude = ["enrolled"]  (exclude specific fields)

        widgets = {
            "name": forms.TextInput(attrs={
                "class": "form-control",
                "placeholder": "Enter student name"
            }),
            "email": forms.EmailInput(attrs={
                "class": "form-control"
            }),
            "age": forms.NumberInput(attrs={
                "min": 1, "max": 100
            }),
        }
        error_messages = {
            "name": {
                "required": "Please enter the student name.",
                "max_length": "Name cannot exceed 100 characters."
            },
            "email": {
                "unique": "This email is already registered."
            }
        }

# myapp/views.py
from django.shortcuts import render, redirect
from .forms import StudentForm

def add_student(request):
    if request.method == "POST":
        form = StudentForm(request.POST)
        if form.is_valid():
            form.save()   # Saves directly to database
            return redirect("student_list")
    else:
        form = StudentForm()
    return render(request, "myapp/add_student.html", {"form": form})

def edit_student(request, id):
    student = Student.objects.get(id=id)
    if request.method == "POST":
        form = StudentForm(request.POST, instance=student)
        if form.is_valid():
            form.save()   # Updates existing record
            return redirect("student_list")
    else:
        form = StudentForm(instance=student)  # Pre-fill with existing data
    return render(request, "myapp/edit_student.html", {"form": form})

Key Definitions

MVC (Model-View-Controller)

A software architectural pattern that separates an application into three components — Model (data and logic), View (presentation/UI), and Controller (handles user input and coordinates Model and View).

Django

A high-level, open-source Python web framework that follows the MVT (Model-View-Template) pattern. Known for its "batteries included" approach, built-in admin, ORM, and security features. Released in 2005.

urls.py

The URL configuration file in Django that maps URL patterns to view functions. Django checks patterns in order and calls the first matching view when a request arrives.

View (Django)

A Python function or class in views.py that receives an HTTP request, processes it (fetches data, applies logic), and returns an HTTP response. Equivalent to the Controller in traditional MVC.

Django Template Language (DTL)

Django's built-in template engine that allows embedding dynamic data into HTML files using special tags ({% %}), variables ({{ }}), and filters (|).

Template Inheritance

A Django feature where a base template defines the common layout using {% block %} tags, and child templates extend it using {% extends %} and fill in the blocks. Avoids repeating common HTML.

CSRF Token

Cross-Site Request Forgery protection token. Django requires {% csrf_token %} in every POST form to verify that the request originates from the same site. Without it, Django returns a 403 Forbidden error.

cleaned_data

A dictionary available on a validated Django form object (form.cleaned_data). Contains the validated and type-converted field values. Only accessible after form.is_valid() returns True.

ModelForm

A Django form class that automatically generates form fields from a database model. Defined by specifying the model and fields in an inner Meta class. form.save() directly creates or updates database records.

Widget

A Django component that determines the HTML input element rendered for a form field. For example, Textarea renders <textarea>, PasswordInput renders <input type="password">. Widgets can be customized with HTML attributes.

Static Files

Files that do not change dynamically — CSS stylesheets, JavaScript files, images. Stored in the static/ directory. Referenced in templates using {% load static %} and {% static 'path' %}.

Multiple Choice Questions

Q 1

What does MVC stand for?

  • a. Model-View-Controller
  • b. Module-View-Component
  • c. Model-Variable-Controller
  • d. Main-View-Class
Answer: a. Model-View-Controller

MVC is a software design pattern that separates an application into Model (data), View (presentation), and Controller (logic/input handling).

Q 2

In Django's MVT pattern, which file contains the business logic (equivalent to Controller in MVC)?

  • a. models.py
  • b. urls.py
  • c. views.py
  • d. templates/*.html
Answer: c. views.py

In Django's MVT, the View (views.py) acts as the Controller — it handles requests, processes data, and returns responses. The Template handles presentation.

Q 3

Which Django template tag is used to include a CSRF token in a form?

  • a. {% csrf %}
  • b. {{ csrf_token }}
  • c. {% csrf_token %}
  • d. {% token %}
Answer: c. {% csrf_token %}

{% csrf_token %} must be placed inside every POST form in Django. It is a template tag (uses {% %}), not a variable (not {{ }}).

Q 4

Which method is used to save a ModelForm directly to the database?

  • a. form.write()
  • b. form.commit()
  • c. form.save()
  • d. form.store()
Answer: c. form.save()

form.save() is called after form.is_valid() returns True. It creates a new database record (or updates an existing one if instance was provided).

Q 5

Which Django template tag is used to extend a base template?

  • a. {% include "base.html" %}
  • b. {% extends "base.html" %}
  • c. {% base "base.html" %}
  • d. {% inherit "base.html" %}
Answer: b. {% extends "base.html" %}

{% extends "base.html" %} must be the first tag in a child template. It tells Django that this template inherits from the base template.

Q 6

Where is validated form data accessible after form.is_valid() returns True?

  • a. form.data
  • b. form.fields
  • c. form.cleaned_data
  • d. form.validated
Answer: c. form.cleaned_data

After successful validation, form.cleaned_data is a dictionary containing the validated, type-converted form field values.

Q 7

Which Django template filter converts a string to uppercase?

  • a. |caps
  • b. |uppercase
  • c. |upper
  • d. |toUpper
Answer: c. |upper

The |upper filter converts the variable's value to uppercase. Example: {{ "hello"|upper }} renders as HELLO.

Q 8

Which file in a Django app is used to define URL patterns for that app?

  • a. views.py
  • b. models.py
  • c. settings.py
  • d. urls.py
Answer: d. urls.py

urls.py contains the URL configuration — a list of path() patterns that map URL routes to view functions.

Short Answer Questions

Q 1

What is the MVC architecture? Name its three components.

MVC (Model-View-Controller) is a software design pattern that separates an application into three components: Model (handles data and database), View (handles presentation/UI), and Controller (handles user input and coordinates Model and View).

Q 2

What is the difference between Django's MVT and the traditional MVC pattern?

In MVC: Model = data, View = presentation, Controller = logic. In Django's MVT: Model = data (models.py), Template = presentation (.html files), View = logic (views.py). Django's "View" is equivalent to MVC's "Controller", and Django's "Template" is equivalent to MVC's "View".

Q 3

What is the purpose of {% csrf_token %} in Django forms?

{% csrf_token %} adds a hidden security token to POST forms to protect against Cross-Site Request Forgery (CSRF) attacks. Django verifies this token when the form is submitted. Without it, Django returns a 403 Forbidden error.

Q 4

What is template inheritance in Django? Name the two tags used.

Template inheritance allows child templates to reuse the layout of a base template. The base template defines blocks using {% block name %}{% endblock %}. Child templates extend the base using {% extends "base.html" %} and override the blocks with their own content.

Q 5

What is the difference between forms.Form and forms.ModelForm?

forms.Form requires you to define all fields manually and handle database saving yourself. forms.ModelForm automatically generates fields from a database model and provides form.save() to directly create or update database records.

Q 6

What is a Django widget? Give two examples.

A widget determines the HTML input element rendered for a form field. It controls the visual appearance of the field. Examples: Textarea renders a multi-line text area (<textarea>), and PasswordInput renders a password field (<input type="password">).

Q 7

How do you include static files (CSS) in a Django template?

Add {% load static %} at the top of the template, then use {% static 'path/file' %} tag to generate the URL. Example: <link rel="stylesheet" href="{% static 'css/style.css' %}">. Static files are stored in the static/ directory.

Q 8

What does form.cleaned_data contain and when is it available?

form.cleaned_data is a dictionary containing the validated and type-converted values of all form fields. It is only available after form.is_valid() returns True. Each key is a field name and each value is the cleaned Python object (e.g., integer, string, date).

Long Answer Questions

Q 1

Explain the MVC architecture and how Django implements it as MVT with a diagram description and examples.

MVC (Model-View-Controller) is a design pattern that separates concerns:

  • Model: Manages data, database operations, business rules.
  • View: Handles presentation — the HTML shown to users.
  • Controller: Receives user input, calls Model, selects View.

Request flow: User → Controller → Model → Controller → View → User

Django's MVT implementation:

  • Model (models.py) — defines database structure using Python classes.
  • View (views.py) — acts as Controller. Receives request, queries model, returns response.
  • Template (.html files) — acts as View. Presents data using DTL tags.
  • URL conf (urls.py) — routes URLs to correct view functions.

Django request flow:

Browser Request → urls.py (routing) → views.py (logic) → models.py (data) → template (HTML) → Browser Response

Key difference: In Django, View = Controller and Template = View. The naming is swapped compared to traditional MVC.

Q 2

Explain Django URL routing and views with examples of URL patterns, view functions, and passing data to templates.

URL Routing: Django maps URLs to view functions in urls.py.

Root urls.py: path('', include('myapp.urls'))

App urls.py:

  • path('', views.home, name='home') → maps / to home view
  • path('student/<int:id>/', views.detail, name='detail') → URL parameter

View function:

def home(request): return render(request, "home.html", {"title": "Home"})

Passing data to template: Pass a context dictionary as the third argument to render(). In the template, access values using {{ key }}.

Template rendering: Django loads the template, substitutes {{ variables }} with context values, and returns the final HTML.

URL parameter example: def detail(request, id): student = get_object_or_404(Student, id=id); return render(request, "detail.html", {"student": student})

Q 3

Explain Django template inheritance with base templates, blocks, extends, static files, and filters with examples.

Template inheritance avoids repeating HTML in every page.

Base template (base.html): Contains the common layout — header, navbar, footer. Uses {% block name %}{% endblock %} to define regions that child templates can fill.

Child template: Uses {% extends "base.html" %} as the first line. Overrides blocks with {% block name %}...{% endblock %}.

Static files: {% load static %} at top, then {% static 'css/style.css' %} in href/src attributes.

Filters: Modify variable display using pipe |:

  • {{ name|upper }} → Uppercase
  • {{ date|date:"d/m/Y" }} → Format date
  • {{ text|truncatewords:10 }} → Truncate
  • {{ price|floatformat:2 }} → 2 decimal places
  • {{ val|lower|capfirst }} → Chain filters

Benefits: Single point of change for common layout. DRY principle. Easy maintenance.

Q 4

Explain Django Forms — forms.Form class, validation, cleaned_data, and ModelForm with complete examples.

forms.Form: Define form fields as class attributes in forms.py.

Example fields: name = forms.CharField(max_length=100), email = forms.EmailField(), age = forms.IntegerField(min_value=1)

In views.py — Standard pattern:

  • GET request → form = MyForm() (empty form)
  • POST request → form = MyForm(request.POST)
  • form.is_valid() → runs all validators
  • form.cleaned_data["field"] → get validated value

Custom validation: Define clean_fieldname() methods in the form class. Raise forms.ValidationError("message") on failure.

Cross-field validation: Override clean() method.

ModelForm: Inherits from forms.ModelForm. Inner Meta class specifies model and fields. form.save() writes to database. form = MyForm(instance=obj) pre-fills for editing.

Template rendering: {{ form.as_p }} renders all fields wrapped in <p> tags. Individual field: {{ form.name }} + {{ form.name.errors }}.

Write a Django forms.Form for a login page with username and password fields, with custom validation that checks the username is not empty and has at least 4 characters.

from django import forms

class LoginForm(forms.Form):
    username = forms.CharField(
        max_length=50,
        widget=forms.TextInput(attrs={
            "placeholder": "Enter username",
            "autofocus": True
        })
    )
    password = forms.CharField(
        widget=forms.PasswordInput(attrs={
            "placeholder": "Enter password"
        })
    )
    remember_me = forms.BooleanField(required=False)

    def clean_username(self):
        username = self.cleaned_data.get("username", "").strip()
        if len(username) < 4:
            raise forms.ValidationError(
                "Username must be at least 4 characters long."
            )
        return username

    def clean_password(self):
        password = self.cleaned_data.get("password", "")
        if len(password) < 6:
            raise forms.ValidationError(
                "Password must be at least 6 characters."
            )
        return password

Q 5

List and explain any 6 Django template filters with syntax and examples.

Django Template Filters
{# 1. upper — converts to uppercase #}
{{ "hello world"|upper }}
{# Output: HELLO WORLD #}

{# 2. lower — converts to lowercase #}
{{ "HELLO WORLD"|lower }}
{# Output: hello world #}

{# 3. date — formats a date object #}
{{ publication_date|date:"d F Y" }}
{# Output: 15 January 2024 #}

{# 4. truncatewords — truncates to N words #}
{{ "Python is a great language for everyone"|truncatewords:4 }}
{# Output: Python is a great ... #}

{# 5. length — returns count of items or characters #}
{{ students|length }}    {# number of students in list #}
{{ "hello"|length }}     {# Output: 5 #}

{# 6. default — use default if variable is empty/falsy #}
{{ user_bio|default:"No biography available." }}
{# If user_bio is empty, shows: No biography available. #}

{# 7. floatformat — format float to N decimal places #}
{{ 3.14159265|floatformat:3 }}
{# Output: 3.142 #}

{# 8. capfirst — capitalize first character only #}
{{ "hello world"|capfirst }}
{# Output: Hello world #}

{# Chaining filters #}
{{ "  hello world  "|lower|capfirst }}
{# Output: Hello world #}

Revision

Quick Revision Points
  • MVC: Model (data), View (UI), Controller (logic). Django uses MVT.
  • Django MVT: Model (models.py), View (views.py = Controller), Template (.html = View).
  • Django is high-level, batteries-included, secure, scalable. Released 2005.
  • urls.py maps URL patterns to view functions using path().
  • Views receive request object and return render(), HttpResponse(), or redirect().
  • Context dict passed to render() is accessible in template as {{ key }}.
  • DTL tags: {% if %}, {% for %}, {% extends %}, {% block %}, {% url %}, {% csrf_token %}, {% load static %}.
  • DTL filters: |upper, |lower, |date, |truncatewords, |length, |default, |floatformat.
  • Template inheritance: base uses {% block %}, child uses {% extends %} + {% block %}.
  • Static files: {% load static %} + {% static 'path' %}. Stored in static/ directory.
  • Every POST form needs {% csrf_token %} — prevents CSRF attacks.
  • forms.Form: manual fields. forms.ModelForm: auto-generated from model.
  • Form pattern: POST → Form(request.POST) → is_valid() → cleaned_data → process.
  • form.save() — ModelForm only. Saves to DB. Use instance=obj to edit.
  • Custom validation: clean_fieldname() or clean() methods. Raise forms.ValidationError.
  • Widgets control HTML input rendering. Customize with attrs={}.
  • error_messages in Meta class customizes validation error text.
Must Remember for Exam
  • In Django: View = Controller, Template = View (opposite of MVC naming).
  • {% csrf_token %} — required in every POST form. Without it → 403 error.
  • {% extends %} must be the very first line of a child template.
  • form.cleaned_data only available after form.is_valid() returns True.
  • form.save() works only with ModelForm, not forms.Form.
  • {{ form.as_p }} renders all form fields wrapped in <p> tags.
  • Static files need {% load static %} at top of template.
  • URL parameter syntax: <int:id>, <str:name> in path().
  • Filters use | pipe: {{ var|upper }}. Tags use {% %}.
  • Django released in 2005. Motto: "The web framework for perfectionists with deadlines."
Common Mistakes in Exams
  • Forgetting {% csrf_token %} in POST forms — very commonly asked.
  • Confusing Django's View with MVC's View — they are different things.
  • Placing {% extends %} anywhere other than the first line of the template.
  • Accessing form.cleaned_data before calling form.is_valid().
  • Using form.save() with a regular forms.Form — only ModelForm has this.
  • Writing {{ csrf_token }} (variable syntax) instead of {% csrf_token %} (tag syntax).
  • Forgetting {% load static %} before using {% static %} — causes TemplateSyntaxError.
  • Not ending template tags: {% if %}...{% endif %}, {% for %}...{% endfor %}, {% block %}...{% endblock %}.
