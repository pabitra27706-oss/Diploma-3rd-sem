String Sort

Sorting Strings

Standard comparison-based sorting of strings takes O(n·W·log n) where W = average string length (because comparing two strings takes O(W)). Radix-based approaches can sort strings faster by processing characters one at a time.

LSD Radix Sort for Strings

Concept

Least Significant Digit (LSD) Radix Sort processes strings from the rightmost character to the leftmost. It requires all strings to have the same length W. Uses a stable sort (counting sort) as subroutine for each character position.

Pseudocode: LSD String Sort
LSD-STRING-SORT(strings[], n, W)
  R = radix (e.g., 256 for ASCII)
  for d = W-1 downto 0       // rightmost to leftmost
    count[0..R] = {0}
    // Count frequencies
    for i = 0 to n-1: count[strings[i][d] + 1]++
    // Prefix sums
    for r = 0 to R-1: count[r+1] += count[r]
    // Distribute
    for i = 0 to n-1:
      aux[count[strings[i][d]]++] = strings[i]
    // Copy back
    for i = 0 to n-1: strings[i] = aux[i]
Complexity: LSD String Sort
  • Time: O(W · (n + R)) where W = string length, R = alphabet size.
  • Space: O(n + R).
  • Stable: Yes.
  • Limitation: All strings must have the same length.

MSD Radix Sort for Strings

Concept

Most Significant Digit (MSD) Radix Sort processes from the leftmost character first, then recursively sorts subgroups sharing the same prefix. Works with variable-length strings.

Complexity: MSD String Sort
  • Time: O(n · W) average for random strings.
  • Space: O(n + W · R) — overhead for recursive subgroup arrays.
  • Advantage: Variable-length strings; can terminate early for equal-prefix groups.
  • Disadvantage: Overhead of recursion; many small subarrays at deep levels.

Tries

Definition

A Trie (from reTRIEval) is a tree-like data structure used for storing a set of strings. Each node represents a character, and paths from the root to marked nodes form complete words. Enables prefix-based searches in O(L) time where L = length of the query string.

Trie Properties
  • Root represents the empty string.
  • Each edge represents a single character.
  • A node is marked as an end-of-word if a complete word ends there.
  • All descendants of a node share a common prefix represented by that node's path from root.
  • For R-character alphabet, each node has up to R children.
(root) / | \ a b c | | | p a a | | | p t* r* | l | e* Words: apple, bat, car * = end-of-word marker
Trie Operations
Insert
TRIE-INSERT(root, word)
  node = root
  for each character c in word:
    if node.children[c] == NULL:
      node.children[c] = new TrieNode()
    node = node.children[c]
  node.isEndOfWord = true
Search
TRIE-SEARCH(root, word)
  node = root
  for each character c in word:
    if node.children[c] == NULL:
      return false
    node = node.children[c]
  return node.isEndOfWord
Trie Complexity
  • Insert: O(L) where L = length of word.
  • Search: O(L).
  • Prefix search: O(L) to reach prefix node, then traverse subtree.
  • Space: O(n · L · R) worst case where n = number of words, R = alphabet size.
Applications of Tries
  • Autocomplete: Search engines suggest completions from prefix.
  • Spell check: Verify if word exists in dictionary.
  • IP routing: Longest prefix match.
  • T9 predictive text: Phone keyboard word suggestions.
  • DNS lookup: Domain name resolution.

Naive String Matching

Concept

The simplest substring search algorithm. Slide the pattern P (length m) over the text T (length n) one position at a time. At each position, compare all characters of P with the corresponding characters of T. If all match, a match is found.

Notation: Text T (length n), Pattern P (length m), n ≥ m.

Pseudocode: Naive String Matching
NAIVE-MATCH(T, P)
  n = length(T), m = length(P)
  for i = 0 to n - m:
    j = 0
    while j < m and T[i + j] == P[j]:
      j++
    if j == m:
      print "Pattern found at index", i
Trace: T="AABAACAADAABAABA", P="AABA"
i=0: AABAACAADAABAABA — match j=0,1,2,3 all match → Found at 0 ✅
i=1: AABAACAA... — T[1]='A', P[0]='A' ✓; T[2]='B', P[1]='A' ✗ → mismatch at j=1
i=2: AABAACAA... — T[2]='B', P[0]='A' ✗ → mismatch at j=0
i=9: AABAACAADAABAABA — match → Found at 9 ✅
i=12: AABAACAADAABAABA — match → Found at 12 ✅
Complexity: Naive String Matching
  • Best Case: O(n) — mismatch at first character of each position.
  • Worst Case: O(m · (n − m + 1)) ≈ O(m · n) — all characters match until last. Example: T="AAAA...A", P="AAAB".
  • Space: O(1).
  • No preprocessing required.

Rabin-Karp Algorithm

Concept

Rabin-Karp uses hashing for substring search. Instead of comparing characters one by one, compute a hash of the pattern and slide a rolling hash over the text. Only compare characters when hash values match (to handle hash collisions).

Rolling Hash Formula

For string s = s₀s₁...s_{m-1} with base d and modulus q:

hash(s) = (s₀ · d^(m-1) + s₁ · d^(m-2) + ... + s_{m-1}) mod q

Rolling update (removing leftmost char sᵢ and adding new char s_{i+m}):

hash_new = (d · (hash_old − sᵢ · d^(m-1)) + s_{i+m}) mod q
Pseudocode: Rabin-Karp
RABIN-KARP(T, P, d, q)
  n = len(T), m = len(P)
  h = d^(m-1) mod q
  p_hash = 0, t_hash = 0

  // Preprocessing: compute initial hash values
  for i = 0 to m-1:
    p_hash = (d * p_hash + P[i]) mod q
    t_hash = (d * t_hash + T[i]) mod q

  // Matching
  for i = 0 to n-m:
    if p_hash == t_hash:
      if T[i..i+m-1] == P[0..m-1]:  // character-by-character verify
        print "Match at", i
    if i < n-m:
      t_hash = (d*(t_hash - T[i]*h) + T[i+m]) mod q
      if t_hash < 0: t_hash += q
Trace: T="31415926", P="26", d=10, q=13
Pattern hash: (2·10 + 6) mod 13 = 26 mod 13 = 0
i=0: "31" → (3·10+1) mod 13 = 31 mod 13 = 5 ≠ 0
i=1: "14" → roll: (10·(5-3·10)+4) mod 13 = (10·(-25)+4) mod 13 = (-246) mod 13 = 1 ≠ 0
i=6: "26" → hash = 0 == 0 → verify chars: '2'=='2' ✓, '6'=='6' ✓ → Match at 6 ✅
Complexity: Rabin-Karp
  • Preprocessing: O(m).
  • Average Case: O(n + m) — few spurious hits.
  • Worst Case: O(m · n) — all hash matches are spurious (hash collisions).
  • Space: O(1).
  • Advantage: Multiple pattern search — can search for multiple patterns simultaneously.

Knuth-Morris-Pratt (KMP) Algorithm

Concept

KMP avoids redundant comparisons by preprocessing the pattern to build a LPS (Longest Proper Prefix which is also Suffix) array. On mismatch, instead of restarting from the next text position, KMP shifts the pattern based on LPS to skip characters that are already known to match.

Key Idea: When a mismatch occurs at P[j], we know P[0..j-1] has already matched. The LPS tells us the longest prefix of P[0..j-1] that is also a suffix — we can skip to that position instead of starting over.

LPS Array Construction

LPS[i] = length of the longest proper prefix of P[0..i] that is also a suffix of P[0..i].

Example: P = "ABABCABAB"

i012345678
P[i]ABABCABAB
LPS[i]001201234

LPS[8]=4 because "ABAB" is both a prefix and suffix of "ABABCABAB".

Pseudocode: Build LPS Array
BUILD-LPS(P, m)
  LPS[0] = 0
  len = 0, i = 1
  while i < m:
    if P[i] == P[len]:
      len++
      LPS[i] = len
      i++
    else:
      if len != 0:
        len = LPS[len - 1]   // Don't increment i
      else:
        LPS[i] = 0
        i++
  return LPS
Pseudocode: KMP Search
KMP-SEARCH(T, P)
  n = len(T), m = len(P)
  LPS = BUILD-LPS(P, m)
  i = 0, j = 0     // i for text, j for pattern
  while i < n:
    if T[i] == P[j]:
      i++, j++
    if j == m:
      print "Match at", i - m
      j = LPS[j - 1]     // Continue searching
    else if i < n and T[i] != P[j]:
      if j != 0:
        j = LPS[j - 1]   // Shift pattern using LPS
      else:
        i++
Trace: T="ABABDABACDABABCABAB", P="ABABCABAB"
LPS: [0, 0, 1, 2, 0, 1, 2, 3, 4]
i=0-3: T[0..3]="ABAB" matches P[0..3]. j=4.
i=4: T[4]='D' ≠ P[4]='C'. j=LPS[3]=2. (Skip — "AB" already matched)
i=4: T[4]='D' ≠ P[2]='A'. j=LPS[1]=0.
i=4: T[4]='D' ≠ P[0]='A'. j=0, i++.
i=5-8: Continue matching... Eventually find partial matches.
i=10-18: T[10..18]="ABABCABAB" matches P fully. j=9=m → Match at 10 ✅
Complexity: KMP
  • Preprocessing (LPS build): O(m).
  • Matching: O(n).
  • Total: O(n + m) — guaranteed.
  • Space: O(m) for LPS array.
  • No worst case degradation — unlike Naive and Rabin-Karp.

Horspool Algorithm

Concept

Horspool is a simplified version of Boyer-Moore. It compares the pattern right-to-left against the text, but uses only the bad character heuristic based on the rightmost character of the text window to determine the shift amount.

Key Idea: When a mismatch occurs, look at the text character aligned with the last character of the pattern window and shift based on a precomputed shift table.

Shift Table Construction

For each character c in the alphabet:

shift[c] = m (if c not in pattern or c is last char of pattern only)
shift[c] = m − 1 − (rightmost position of c in P[0..m-2])

Example: P = "BARBER", m = 6

CharBAREOthers
Shift24136
Pseudocode: Horspool
HORSPOOL(T, P)
  n = len(T), m = len(P)
  Build shift table for P
  i = m - 1      // Start at rightmost position of first window
  while i < n:
    k = 0        // Number of matches from the right
    while k < m and P[m-1-k] == T[i-k]:
      k++
    if k == m:
      print "Match at", i - m + 1
    i += shift[T[i]]    // Shift based on rightmost text character
Trace: T="JIMBOBBARBERDAN", P="BARBER"
Shift table: B=2, A=4, R=1, E=3, others=6
Window 1: T[0..5]="JIMBOB" — right char B. Compare from right: P[5]='R' vs T[5]='B' → mismatch. Shift by shift['B']=2
Window 2: T[2..7]="MBOBBA" — right char A. Mismatch. Shift by shift['A']=4
Window 3: T[6..11]="BARBER" — all match right-to-left → Match at 6 ✅
Complexity: Horspool
  • Preprocessing: O(m + |Σ|) where |Σ| = alphabet size.
  • Best Case: O(n/m) — large shifts skip many characters.
  • Average Case: O(n) — sub-linear in practice.
  • Worst Case: O(m · n) — pathological inputs.
  • Space: O(|Σ|) for shift table.

Boyer-Moore Algorithm

Concept

Boyer-Moore is the most efficient practical string matching algorithm. Like Horspool, it compares right-to-left but uses two heuristics for shifting:

  1. Bad Character Heuristic: On mismatch at T[i], find the rightmost occurrence of T[i] in the pattern and align. If T[i] doesn't occur in pattern, shift past it entirely.
  2. Good Suffix Heuristic: If a suffix of the pattern has matched, find the rightmost occurrence of that suffix elsewhere in the pattern and align. This prevents missing matches.

Shift = max(bad character shift, good suffix shift).

Bad Character Heuristic

When T[i] ≠ P[j] (mismatch at position j in pattern):

  • If T[i] occurs in P at position k (k < j): shift pattern so P[k] aligns with T[i].
  • If T[i] does not occur in P: shift entire pattern past T[i].

Shift = max(1, j − rightmost position of T[i] in P)

Good Suffix Heuristic

When P[j+1..m-1] has matched (good suffix) but P[j] mismatches:

  • Case 1: The good suffix occurs elsewhere in P → align to that occurrence.
  • Case 2: A prefix of P matches a suffix of the good suffix → align to that prefix.
  • Case 3: Neither → shift by m.
Complexity: Boyer-Moore
  • Preprocessing: O(m + |Σ|) for bad char + O(m) for good suffix.
  • Best Case: O(n/m) — can skip large portions of text. Fastest practical algorithm.
  • Average Case: O(n) — sub-linear in practice.
  • Worst Case: O(m · n) without Galil rule; O(n) with Galil rule.
  • Space: O(m + |Σ|).
Boyer-Moore vs Horspool

Horspool uses only the bad character heuristic (simplified). Boyer-Moore uses both bad character AND good suffix heuristics, making it more efficient. Boyer-Moore is the gold standard for single-pattern text search in practice (used in grep, text editors).

Regex and Automata

Every regex can be converted to a Finite Automaton (NFA or DFA) for matching. NFA construction takes O(m) time and matching takes O(n) with NFA simulation. This is the theoretical foundation of regex engines.

Elementary Data Compression

1. Huffman Coding

Concept

Huffman Coding is a lossless data compression algorithm that assigns variable-length codes to characters based on their frequencies. More frequent characters get shorter codes; less frequent characters get longer codes. The codes are prefix-free (no code is a prefix of another).

Paradigm: Greedy Algorithm.

Huffman Algorithm Steps
  1. Count frequency of each character.
  2. Create a leaf node for each character and add to a min-heap (priority queue).
  3. While heap has more than 1 node:
    • Extract two nodes with minimum frequency.
    • Create a new internal node with frequency = sum of the two.
    • Make the two extracted nodes left and right children.
    • Insert new node back into heap.
  4. The remaining node is the root of the Huffman tree.
  5. Assign codes: left edge = 0, right edge = 1. Traverse root to each leaf to get codes.
Example: Huffman Coding

Characters: A(5), B(9), C(12), D(13), E(16), F(45)

Step 1: Heap: [A:5, B:9, C:12, D:13, E:16, F:45]
Step 2: Merge A(5)+B(9)=AB(14). Heap: [C:12, D:13, AB:14, E:16, F:45]
Step 3: Merge C(12)+D(13)=CD(25). Heap: [AB:14, E:16, CD:25, F:45]
Step 4: Merge AB(14)+E(16)=ABE(30). Heap: [CD:25, ABE:30, F:45]
Step 5: Merge CD(25)+ABE(30)=CDABE(55). Heap: [F:45, CDABE:55]
Step 6: Merge F(45)+CDABE(55)=Root(100).

Concept

Run-Length Encoding replaces consecutive runs of the same character with the character followed by its count. Simple and effective for data with many repeated consecutive characters.

Key Definitions

All Key Terms
  • String Sort: Sorting strings character-by-character using radix-based methods.
  • LSD Radix Sort: Sorts strings from rightmost to leftmost character; requires equal-length strings.
  • MSD Radix Sort: Sorts from leftmost character; works with variable-length strings.
  • Trie: Tree-like data structure for storing strings; each path represents a word prefix; O(L) search.
  • Prefix-free code: No codeword is a prefix of another codeword (e.g., Huffman codes).
  • Naive String Matching: Brute-force comparison at every position; O(m·n) worst case.
  • Rabin-Karp: Hash-based matching; uses rolling hash; O(n+m) average.
  • Rolling Hash: Hash that can be updated in O(1) when sliding the window by one character.
  • KMP (Knuth-Morris-Pratt): Uses LPS array to skip redundant comparisons; O(n+m) guaranteed.
  • LPS Array: Longest Proper Prefix which is also Suffix; core of KMP preprocessing.
  • Horspool: Right-to-left matching with bad character heuristic only; simplified Boyer-Moore.
  • Boyer-Moore: Most efficient practical algorithm; uses bad character + good suffix heuristics.
  • Bad Character Heuristic: On mismatch, shift based on mismatched text character's position in pattern.
  • Good Suffix Heuristic: On mismatch, shift based on the matched suffix's other occurrences in pattern.
  • Regular Expression: A pattern language for matching strings using operators like *, +, ?, |.
  • Huffman Coding: Greedy lossless compression; variable-length prefix-free codes based on frequency.
  • Run-Length Encoding (RLE): Compression replacing consecutive repeats with character+count.
  • Lossless Compression: Original data can be exactly reconstructed from compressed form.

Multiple Choice Questions

Q 1

What is the worst-case time complexity of the Naive string matching algorithm?

  • a. O(n)
  • b. O(n + m)
  • c. O(m · n)
  • d. O(n log n)
Answer: c. O(m · n)

In the worst case (e.g., T="AAAA...A", P="AAAB"), the algorithm compares m characters at each of the n−m+1 positions, giving O(m·n).

Q 2

KMP algorithm preprocesses the pattern to build:

  • a. Hash table
  • b. Shift table
  • c. LPS (Longest Proper Prefix Suffix) array
  • d. Huffman tree
Answer: c. LPS (Longest Proper Prefix Suffix) array

The LPS array stores the length of the longest proper prefix of the pattern which is also a suffix, for each position. This allows KMP to skip redundant comparisons on mismatch.

Q 3

Which string matching algorithm uses hashing?

  • a. KMP
  • b. Naive
  • c. Rabin-Karp
  • d. Boyer-Moore
Answer: c. Rabin-Karp

Rabin-Karp uses a rolling hash function to compute hash values for the pattern and text windows. It only does character-by-character comparison when hash values match.

Q 4

A Trie search for a word of length L takes:

  • a. O(n)
  • b. O(L)
  • c. O(n log n)
  • d. O(L²)
Answer: b. O(L)

In a Trie, each character of the word is followed as an edge from the current node. For a word of length L, exactly L nodes are visited — O(L) regardless of how many words are stored.

Q 5

Huffman Coding assigns shorter codes to:

  • a. Less frequent characters
  • b. More frequent characters
  • c. Alphabetically earlier characters
  • d. All characters equally
Answer: b. More frequent characters

Huffman Coding is a greedy algorithm that assigns shorter codewords to characters with higher frequency, minimising total encoded length.

Q 6

Which algorithm compares the pattern from right to left?

  • a. Naive
  • b. KMP
  • c. Rabin-Karp
  • d. Boyer-Moore
Answer: d. Boyer-Moore

Boyer-Moore (and Horspool) compare the pattern against the text from right to left. This allows larger shifts when mismatches occur near the end of the pattern.

Q 7

The guaranteed worst-case time complexity of KMP is:

  • a. O(n²)
  • b. O(m · n)
  • c. O(n + m)
  • d. O(n log n)
Answer: c. O(n + m)

KMP guarantees O(n + m) in ALL cases — O(m) for building the LPS array and O(n) for the matching phase. Unlike Naive and Rabin-Karp, it never degrades to O(m·n).

Q 8

Run-Length Encoding of "AAABBC" is:

  • a. A3B2C
  • b. A3B2C1
  • c. 3A2B1C
  • d. ABC321
Answer: b. A3B2C1

RLE replaces each run of consecutive identical characters with the character followed by its count: A(3 times)=A3, B(2 times)=B2, C(1 time)=C1. Convention includes the count even for single occurrences.

Q 9

Which data structure does Huffman Coding use for tree construction?

  • a. Stack
  • b. Queue
  • c. Min-Heap (Priority Queue)
  • d. Hash Table
Answer: c. Min-Heap (Priority Queue)

Huffman repeatedly extracts the two nodes with minimum frequency. A min-heap provides O(log n) extract-min and insert operations, making tree construction O(n log n).

Q 10

Horspool algorithm is a simplified version of:

  • a. KMP
  • b. Rabin-Karp
  • c. Boyer-Moore
  • d. Naive
Answer: c. Boyer-Moore

Horspool uses only the bad character heuristic of Boyer-Moore. Boyer-Moore additionally uses the good suffix heuristic, making it more powerful but more complex.

Q 11

The best-case complexity of Boyer-Moore is:

  • a. O(n)
  • b. O(n + m)
  • c. O(n/m)
  • d. O(m · n)
Answer: c. O(n/m)

In the best case, Boyer-Moore can skip m characters at each step (when the rightmost character of the window doesn't appear in the pattern at all), giving O(n/m) — sub-linear time.

Q 12

Which of the following is NOT a use of Tries?

  • a. Autocomplete
  • b. Spell checking
  • c. Sorting integers
  • d. IP routing
Answer: c. Sorting integers

Tries are designed for string operations: autocomplete, spell checking, IP routing (longest prefix match), and dictionary lookup. Sorting integers uses different algorithms (Count Sort, Radix Sort).

Short Answer Questions

Q 1

What is the LPS array in KMP? Give an example.

LPS (Longest Proper Prefix which is also Suffix) array stores, for each position i in the pattern, the length of the longest proper prefix of P[0..i] that is also a suffix.

Example: P = "ABAB"

  • LPS[0] = 0 (single char, no proper prefix)
  • LPS[1] = 0 ("AB" — no prefix = suffix)
  • LPS[2] = 1 ("ABA" — "A" is both prefix and suffix)
  • LPS[3] = 2 ("ABAB" — "AB" is both prefix and suffix)

LPS = [0, 0, 1, 2]

Q 2

What is a Trie? What is its advantage over a hash table for string storage?

A Trie is a tree data structure where each path from root to a marked node represents a word. Each edge represents a character.

Advantages over hash table:

  • Prefix search: Trie can find all words with a given prefix in O(L + k) where k = number of matches. Hash table cannot do this efficiently.
  • Ordered iteration: Trie naturally gives lexicographic order.
  • No hash collisions: No worst-case degradation.

Hash table advantage: Uses less space for sparse, long strings.

Q 3

What is a rolling hash? Why is it important in Rabin-Karp?

A rolling hash is a hash function that can update the hash value in O(1) when the window slides by one character — removing the leftmost character and adding the new rightmost character.

Why important: Without rolling hash, computing hash for each window costs O(m), making the total O(m·n). With rolling hash, each window's hash is computed in O(1), making Rabin-Karp O(n+m) average case.

Formula: hash_new = (d·(hash_old − s_old·d^(m-1)) + s_new) mod q

Q 4

What is the difference between LSD and MSD Radix Sort for strings?

LSD (Least Significant Digit): Processes from the rightmost character to leftmost. Requires all strings to be the same length. Iterative. Best for fixed-width keys (e.g., license plates).

MSD (Most Significant Digit): Processes from leftmost character. Works with variable-length strings. Recursive — sorts sub-groups sharing same prefix. Can terminate early for unique prefixes.

Q 5

What is Huffman Coding? Why are Huffman codes prefix-free?

Huffman Coding is a greedy lossless compression algorithm that assigns variable-length binary codes to characters based on frequency. More frequent characters get shorter codes.

Prefix-free: No Huffman code is a prefix of another code. This is guaranteed because codes are assigned only at leaf nodes of the Huffman tree. Since no leaf is an ancestor of another leaf, no code is a prefix of another. This allows unambiguous decoding without separators.

Q 6

What are the two heuristics used in Boyer-Moore?

1. Bad Character Heuristic: On mismatch at text character c, shift the pattern so that the rightmost occurrence of c in the pattern aligns with c in the text. If c doesn't exist in the pattern, shift past it entirely.

2. Good Suffix Heuristic: If a suffix of the pattern has matched, find another occurrence of that suffix in the pattern and align to it. If no other occurrence exists, find a prefix of the pattern matching a suffix of the matched portion.

Shift = max(bad character shift, good suffix shift).

Q 7

When does Run-Length Encoding perform poorly? Give an example.

RLE performs poorly when the input has few or no consecutive repeated characters.

Example: Input: "ABCDEF" (6 chars) → RLE: "A1B1C1D1E1F1" (12 chars). The "compressed" output is twice as large as the original! RLE is only effective for data with many long runs of identical characters (e.g., bitmap images with large uniform areas).

Q 8

What is a regular expression? Give two examples.

A regular expression is a pattern that describes a set of strings using special operators (*, +, ?, |, [], etc.). Used for pattern matching, validation, and text processing.

Examples:

  • ^[0-9]{10}$ — matches exactly a 10-digit number (e.g., phone number).
  • [a-zA-Z]+@[a-zA-Z]+\.[a-z]{2,} — matches simple email format (e.g., user@domain.com).

Q 9

What is the advantage of Rabin-Karp over other string matching algorithms?

Rabin-Karp's main advantage is multiple pattern matching. It can search for multiple patterns simultaneously by computing hashes for all patterns and comparing with the text window hash. Other algorithms (Naive, KMP, Boyer-Moore) handle only single-pattern search efficiently.

Example use: Plagiarism detection — search for many known phrases in a document at once.

Q 10

Why is Boyer-Moore considered the fastest practical string matching algorithm?

Boyer-Moore achieves sub-linear O(n/m) best case — it can skip large portions of the text without reading every character. Key reasons:

  • Right-to-left comparison: Mismatches at the end allow large shifts.
  • Two heuristics: Bad character + Good suffix give larger shifts than either alone.
  • Large alphabets: More character diversity → more mismatches → bigger shifts.

Used in Unix grep, text editors, and virus scanners.

Explain Tries with insertion and search operations. Insert "cat", "car", "card", "care" into a Trie and show the resulting structure.

A Trie stores strings character-by-character in a tree. Each node has up to R children (one per alphabet character). A boolean flag marks end-of-word.

Q 6

Explain Huffman Coding and Run-Length Encoding. Compare their suitability for different types of data.

Huffman Coding: Variable-length prefix-free codes based on character frequency. More frequent → shorter code. Built using min-heap, O(n log n). Optimal among prefix-free codes. Never expands data.

Q 7

Explain the Rabin-Karp algorithm. Why can it search for multiple patterns efficiently?

Rabin-Karp: Uses a rolling hash to compare the pattern hash with text window hashes. Only verifies character-by-character when hashes match.

Steps
  1. Compute hash of pattern P: O(m).
  2. Compute hash of first text window T[0..m-1]: O(m).
  3. Slide window: update hash in O(1) using rolling hash formula.
  4. If hash matches, verify characters: O(m) per match.

Multiple pattern search: Compute hashes of ALL k patterns in O(k·m). For each text window, compare the window hash against ALL pattern hashes. With a hash set, this is O(1) per window per pattern check. Total: O(n + k·m). This is Rabin-Karp's unique advantage — KMP and Boyer-Moore handle only one pattern at a time.

Quick Revision Points
  • LSD String Sort: Right→Left, fixed-length strings, O(W(n+R)), stable.
  • MSD String Sort: Left→Right, variable-length, recursive, O(nW) avg.
  • Trie: Tree for string storage. Insert/Search O(L). Great for prefix queries.
  • Naive search: O(m·n) worst. No preprocessing. Simple but slow.
  • Rabin-Karp: Rolling hash. O(n+m) avg. O(m·n) worst. Can do multi-pattern search.
  • KMP: LPS array preprocessing O(m). Search O(n). Total O(n+m) guaranteed. Best worst-case.
  • LPS[i]: Longest proper prefix of P[0..i] that is also a suffix.
  • Horspool: Right→Left. Bad character only. Shift table. O(n/m) best. Simplified Boyer-Moore.
  • Boyer-Moore: Right→Left. Bad char + Good suffix. O(n/m) best. Most efficient in practice.
  • Regex: . (any), * (0+), + (1+), ? (0/1), | (or), [] (class), ^ (start), $ (end).
  • Huffman: Greedy compression. Prefix-free codes. Frequent chars → short codes. O(n log n).
  • RLE: Replace runs with char+count. O(n). Great for repetitive data. Can expand otherwise.
  • Rolling hash: O(1) update when window slides by 1 character.
  • Prefix-free: No code is prefix of another → unambiguous decoding.
Must Remember for Exam
  • Naive worst case: O(m·n). KMP worst case: O(n+m) — guaranteed.
  • KMP builds LPS array; Rabin-Karp uses rolling hash; Boyer-Moore uses two heuristics.
  • Boyer-Moore/Horspool compare right-to-left; Naive/KMP/Rabin-Karp compare left-to-right.
  • Rabin-Karp is unique for multiple pattern search.
  • Boyer-Moore best case is O(n/m) — sub-linear!
  • Trie search/insert: O(L) where L = word length. Independent of n (number of words).
  • Huffman codes are prefix-free — no code is prefix of another.
  • Huffman uses min-heap. Always merge two lowest frequency nodes.
  • RLE can expand data if no consecutive repeats.
  • LSD requires same-length strings; MSD works with variable length.
Common Mistakes in Exams
  • Saying KMP worst case is O(m·n) — it is O(n+m) guaranteed.
  • Confusing LPS with shift table — LPS is for KMP; shift table is for Horspool.
  • Saying Rabin-Karp always runs in O(n+m) — worst case is O(m·n) due to hash collisions.
  • Forgetting that Boyer-Moore compares right-to-left, not left-to-right.
  • Confusing Horspool and Boyer-Moore — Horspool uses only bad character; Boyer-Moore uses both heuristics.
  • Writing Trie search as O(n) — it is O(L) where L = word length, not n.
  • Saying Huffman codes can be prefix of each other — they are prefix-free by construction.
  • Applying RLE to data with no repeats and claiming compression — it expands in such cases.
  • Forgetting that LSD Radix Sort requires equal-length strings.
  • Writing rolling hash update as O(m) — it is O(1).
