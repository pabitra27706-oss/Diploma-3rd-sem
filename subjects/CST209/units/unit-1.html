Definitions and Characteristics of Algorithms

What is an Algorithm?

An algorithm is a well-defined computational procedure that takes some values as input and produces some value as output. It is a finite sequence of precise instructions to solve a specific problem.

Five Characteristics of an Algorithm

1. Finiteness

An algorithm must terminate after a finite number of steps. It cannot run indefinitely.

Example: A loop that increments from 1 to 10 is finite. An infinite loop (while true) is NOT an algorithm.

2. Definiteness

Each step of the algorithm must be precisely and unambiguously defined. No step should have multiple interpretations.

Example: "Add 5 to x" is definite. "Add some number to x" is NOT definite.

3. Input

An algorithm has zero or more inputs taken from a specified set of objects.

Example: A sorting algorithm takes an array as input. A "print hello" algorithm may have zero inputs.

4. Output

An algorithm must produce one or more outputs that have a specified relation to the inputs.

Example: A sorting algorithm outputs a sorted array.

5. Effectiveness

Every operation in the algorithm must be basic enough to be carried out exactly and in a finite amount of time. It must be feasible.

Example: Basic operations like addition, comparison are effective. Asking to "solve the halting problem" is NOT effective.

Example Algorithm: Finding Maximum

Algorithm: Find Maximum Element 
Algorithm FindMax(A, n)
  Input: Array A of n elements
  Output: Maximum element in A

  1. max ← A[0]
  2. for i = 1 to n-1 do
  3.   if A[i] > max then
  4.     max ← A[i]
  5. return max

Characteristics satisfied:

  • Finiteness: Loop runs n-1 times, then terminates
  • Definiteness: Each step is clearly defined
  • Input: Array A and size n
  • Output: Maximum element
  • Effectiveness: All operations (comparison, assignment) are basic
Exam Tip

Remember the five characteristics by the acronym FDIOE: Finiteness, Definiteness, Input, Output, Effectiveness. Questions often ask to identify which characteristic is violated in a given procedure.

Data Abstraction and ADTs

Abstract Data Type (ADT)

An Abstract Data Type (ADT) is a mathematical model for data types, defined by:

  • Data: The values it can hold
  • Operations: Functions that can be performed on the data
  • No implementation details: Only WHAT operations do, not HOW they are implemented

Example: Stack ADT defines push(), pop(), peek(), isEmpty() without specifying array or linked list implementation.

Examples of ADTs

ADT Data Primary Operations
Stack Collection of elements push(), pop(), peek(), isEmpty()
Queue Collection of elements enqueue(), dequeue(), front(), isEmpty()
List Ordered sequence insert(), delete(), search(), get()
Set Unordered unique elements add(), remove(), contains(), union()
Map Key-value pairs put(), get(), remove(), containsKey()
Benefits of ADTs
  • Encapsulation: Hide implementation details
  • Modularity: Use without knowing internals
  • Reusability: Same ADT, different implementations
  • Flexibility: Change implementation without affecting users
Key Point

ADT focuses on WHAT operations do (specification), not HOW they are implemented (implementation). The same ADT can be implemented using arrays, linked lists, or other structures.

Sets and Multisets

Set

A set is a collection of distinct elements with no duplicates and no inherent order.

Example: S = {1, 2, 3, 4} is a set. S cannot contain duplicate 2.

Operations: Union (∪), Intersection (∩), Difference (−), Subset (⊆)

Multiset (Bag)

A multiset is a collection that allows duplicate elements.

Example: M = {1, 2, 2, 3, 3, 3} is a multiset where 2 appears twice and 3 appears thrice.

Use case: Counting occurrences of items.

Set Operations Examples

Union (A ∪ B)

All elements in A or B or both.

A = {1, 2, 3}, B = {3, 4, 5}
A ∪ B = {1, 2, 3, 4, 5}
Intersection (A ∩ B)

Elements common to both A and B.

A = {1, 2, 3}, B = {3, 4, 5}
A ∩ B = {3}
Difference (A − B)

Elements in A but not in B.

A = {1, 2, 3}, B = {3, 4, 5}
A − B = {1, 2}
Property Set Multiset
Duplicates Allowed No Yes
Order Matters No No
Example {1, 2, 3} {1, 2, 2, 3, 3, 3}
Use Case Unique items Counting frequencies
Mathematical Foundation

Sets and multisets form the mathematical foundation for many algorithms, especially in graph theory, database operations, and search algorithms.

Stacks and Queues

Stack (LIFO)

A stack is a linear data structure following Last In First Out (LIFO) principle.

Operations:

  • push(x): Insert element x at top
  • pop(): Remove and return top element
  • peek() / top(): Return top element without removing
  • isEmpty(): Check if stack is empty

Examples: Function call stack, undo mechanism, expression evaluation

Queue (FIFO)

A queue is a linear data structure following First In First Out (FIFO) principle.

Operations:

  • enqueue(x): Insert element x at rear
  • dequeue(): Remove and return front element
  • front() / peek(): Return front element without removing
  • isEmpty(): Check if queue is empty

Examples: Task scheduling, BFS traversal, print queue

dequeue()   → returns 20, Q = [30]
Time Complexity

Both Stack and Queue operations (push/pop, enqueue/dequeue) have O(1) time complexity when implemented efficiently using arrays or linked lists.

Asymptotic Notations

Why Asymptotic Analysis?

We use asymptotic notations to describe the growth rate of an algorithm's running time as input size n approaches infinity. This helps compare algorithms independent of hardware or programming language.

Big-O Notation (O) — Upper Bound

Big-O (O)

Big-O describes the upper bound (worst-case) growth rate of an algorithm.

f(n) = O(g(n)) means f(n) ≤ c · g(n) for all n ≥ n₀

In simple words: f(n) grows no faster than g(n).

Example: If an algorithm takes 3n² + 5n + 10 operations, we say it is O(n²) because n² is the dominant term.

Omega Notation (Ω) — Lower Bound

Omega (Ω)

Omega describes the lower bound (best-case) growth rate of an algorithm.

f(n) = Ω(g(n)) means f(n) ≥ c · g(n) for all n ≥ n₀

In simple words: f(n) grows at least as fast as g(n).

Example: If searching in a list takes at minimum n comparisons, we say it is Ω(n).

Theta Notation (Θ) — Tight Bound

Theta (Θ)

Theta describes the tight bound (average-case) when upper and lower bounds are the same.

f(n) = Θ(g(n)) means c₁ · g(n) ≤ f(n) ≤ c₂ · g(n) for all n ≥ n₀

In simple words: f(n) grows exactly at the same rate as g(n).

Example: Merge sort is Θ(n log n) in all cases.

Common Complexity Classes (Fastest to Slowest)

Notation Name Example Algorithm
O(1) Constant Array access, push/pop in stack
O(log n) Logarithmic Binary search
O(n) Linear Linear search, single loop
O(n log n) Linearithmic Merge sort, Heap sort
O(n²) Quadratic Bubble sort, Selection sort
O(n³) Cubic Matrix multiplication (naive)
O(2ⁿ) Exponential Recursive Fibonacci, Subset generation
O(n!) Factorial Permutation generation
Example: Analyzing f(n) = 3n² + 5n + 10

Determine Big-O:

  • Drop constants: 3n² → n²
  • Drop lower-order terms: 5n and 10 are negligible for large n
  • Result: f(n) = O(n²)
Key Rule

When analyzing complexity:

  • Focus on dominant term (largest growth rate)
  • Ignore constants (3n² becomes n²)
  • Ignore lower-order terms (n² + n becomes n²)
Common Mistake

Do NOT confuse:

  • O(n) vs O(log n): log n is much faster than n
  • O(n²) vs O(2ⁿ): 2ⁿ is exponentially worse than n²

Time and Space Complexity

Time Complexity

Time complexity measures how the running time of an algorithm grows with input size n.

It counts the number of basic operations (comparisons, assignments, arithmetic) as a function of n.

Example: A loop running n times has time complexity O(n).

Space Complexity

Space complexity measures how the memory usage of an algorithm grows with input size n.

It includes:

  • Input space: Memory for storing input
  • Auxiliary space: Extra memory used during execution

Example: An algorithm using an array of size n has space complexity O(n).

Three Cases of Analysis

Best Case

Minimum time/space required by the algorithm under optimal input conditions.

Example: In linear search, best case is O(1) when the target is at the first position.

Average Case

Expected time/space required averaged over all possible inputs.

Example: In linear search, average case is O(n/2) = O(n) when target is randomly positioned.

Worst Case

Maximum time/space required by the algorithm under worst input conditions.

Example: In linear search, worst case is O(n) when the target is at the last position or not present.

Calculating Time Complexity: Examples

Example 1: Single Loop 
for (int i = 0; i < n; i++) {
    print(i);  // O(1) operation
}
Analysis

Loop runs: n times

Work per iteration: O(1)

Total Time Complexity: O(n)

Example 2: Nested Loops 
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        print(i, j);  // O(1) operation
    }
}
Analysis

Outer loop: n times

Inner loop: n times for each outer loop iteration

Total Time Complexity: O(n × n) = O(n²)

Example 3: Logarithmic Complexity 
int i = 1;
while (i < n) {
    print(i);
    i = i * 2;  // i doubles each time
}
Analysis

Iterations: i = 1, 2, 4, 8, ..., until i ≥ n

Number of iterations: log₂(n)

Total Time Complexity: O(log n)

Space Complexity Examples

Example 1: Constant Space 
int sum(int a, int b) {
    int result = a + b;
    return result;
}
Analysis

Variables: a, b, result (fixed number)

Space Complexity: O(1)

Example 2: Linear Space 
int[] createArray(int n) {
    int[] arr = new int[n];
    return arr;
}
Analysis

Array size: n elements

Space Complexity: O(n)

Important

For most practical purposes, worst-case time complexity is the most important metric because it guarantees performance even under unfavorable conditions.

Quick Rules
  • Single loop → O(n)
  • Nested loops (2 levels) → O(n²)
  • Halving input each time → O(log n)
  • Recursive calls splitting input → O(n log n) (often)
  • Constant operations → O(1)

Programming Model Concepts

Algorithm design paradigms are general approaches to solving computational problems. The three fundamental models are:

Divide and Conquer

Divide and Conquer Strategy

Break the problem into smaller sub-problems, solve them independently, and combine results.

Steps:

  1. Divide: Split the problem into smaller sub-problems
  2. Conquer: Solve each sub-problem recursively
  3. Combine: Merge solutions to get final result

Examples:

  • Merge Sort: Divide array into halves, sort each, merge sorted halves
  • Quick Sort: Partition around pivot, sort left and right partitions
  • Binary Search: Divide search space in half each time
Divide and Conquer Template 
Algorithm DivideAndConquer(Problem P)
  if P is small enough then
    solve P directly
  else
    Divide P into sub-problems P1, P2, ..., Pk
    for each Pi do
      Solution_i = DivideAndConquer(Pi)
    Combine Solution_1, Solution_2, ..., Solution_k
    return combined solution

Greedy Method

Greedy Strategy

Make the locally optimal choice at each step, hoping to find a global optimum.

Key Idea: Choose the best option available right now without considering future consequences.

When to use: Problems with optimal substructure and greedy choice property.

Examples:

  • Coin Change (specific denominations): Always pick largest coin possible
  • Huffman Coding: Build tree by merging smallest frequency nodes
  • Kruskal's MST: Always add the smallest edge that doesn't create a cycle
  • Dijkstra's Algorithm: Always visit the nearest unvisited node
Greedy Limitation

Greedy algorithms do NOT always produce optimal solutions for all problems. They work only when the problem has the greedy choice property.

Counter-example: Coin change with denominations {1, 3, 4} for amount 6:

  • Greedy: 4 + 1 + 1 = 3 coins
  • Optimal: 3 + 3 = 2 coins

Dynamic Programming (DP)

Dynamic Programming Strategy

Solve complex problems by breaking them into overlapping sub-problems and storing solutions to avoid recomputation.

Key Idea: If you solve a sub-problem, remember its solution (memoization) so you don't solve it again.

When to use: Problems with overlapping sub-problems and optimal substructure.

Examples:

  • Fibonacci Sequence: F(n) = F(n-1) + F(n-2), store computed values
  • Shortest Path (Floyd-Warshall): Build solution incrementally
  • Knapsack Problem: Optimal selection with capacity constraint
  • Longest Common Subsequence: Find longest matching subsequence
Example: Fibonacci with DP 
// Recursive (inefficient) - O(2^n)
fib(n):
  if n ≤ 1: return n
  return fib(n-1) + fib(n-2)

// Dynamic Programming (efficient) - O(n)
fibDP(n):
  dp[0] = 0, dp[1] = 1
  for i = 2 to n:
    dp[i] = dp[i-1] + dp[i-2]
  return dp[n]

Improvement: DP reduces time from exponential to linear by storing results.

Comparison of the Three Models

Aspect Divide & Conquer Greedy Dynamic Programming
Approach Split into independent sub-problems Make local optimal choices Store solutions to overlapping sub-problems
Sub-problems Independent N/A (makes choices step-by-step) Overlapping
Optimality Depends on problem Not always optimal Always optimal (if applicable)
Technique Recursion + Combine Greedy choice at each step Memoization / Tabulation
Example Merge Sort, Binary Search Dijkstra's, Huffman Fibonacci, Knapsack
Choosing the Right Paradigm
  • Use Divide & Conquer when sub-problems are independent (Merge Sort, Binary Search)
  • Use Greedy when local optimal choices lead to global optimum (Dijkstra's, Huffman)
  • Use Dynamic Programming when sub-problems overlap and you can store solutions (Fibonacci, Knapsack)

Multiple Choice Questions

Q1

Which of the following is NOT a characteristic of an algorithm?

  • a. Finiteness
  • b. Definiteness
  • c. Ambiguity
  • d. Effectiveness
Answer: c. Ambiguity

An algorithm must be definite and unambiguous. Ambiguity is NOT a characteristic.

Q2

What is the time complexity of a single loop running from 1 to n?

  • a. O(1)
  • b. O(log n)
  • c. O(n)
  • d. O(n²)
Answer: c. O(n)

A single loop running n times has linear time complexity O(n).

Q3

Which notation represents the worst-case time complexity?

  • a. Big-O (O)
  • b. Omega (Ω)
  • c. Theta (Θ)
  • d. Little-o (o)

Big-O represents the upper bound, which corresponds to worst-case complexity.

Q4

A Stack follows which principle?

  • a. FIFO
  • b. LIFO
  • c. Random Access
  • d. Priority Based

Stack follows Last In First Out (LIFO) principle.

Q5

Which of the following is an example of Divide and Conquer?

  • a. Bubble Sort
  • b. Merge Sort
  • c. Linear Search
  • d. Insertion Sort
Answer: b. Merge Sort

Merge Sort divides the array into halves, sorts each half, and combines them.

Q6

Which complexity is better: O(n) or O(log n)?

  • a. O(n)
  • b. O(log n)
  • c. Both are same
  • d. Cannot compare

O(log n) is better (faster) than O(n) because logarithmic growth is slower than linear growth.

Q7

  • b. O(log n)
  • c. O(n)

Q8

Which paradigm stores solutions to avoid recomputation?

  • a. Divide and Conquer
  • b. Greedy
  • c. Dynamic Programming

Long Questions

Q1

Explain the five characteristics of an algorithm with examples.

1. Finiteness: An algorithm must terminate after a finite number of steps. Example: A loop from 1 to 10 is finite; an infinite loop is not.

2. Definiteness: Each step must be precisely defined. Example: "Add 5 to x" is definite; "Add some number" is not.

3. Input: Zero or more inputs from a specified set. Example: A sorting algorithm takes an array.

4. Output: At least one output related to the inputs. Example: Sorting outputs a sorted array.

5. Effectiveness: All operations must be basic and executable in finite time. Example: Basic operations like addition are effective.

Q2

Describe Big-O, Omega, and Theta notations with examples.

Big-O (O): Upper bound (worst-case). f(n) = O(g(n)) means f(n) grows no faster than g(n). Example: Linear search is O(n) in the worst case.

Omega (Ω): Lower bound (best-case). f(n) = Ω(g(n)) means f(n) grows at least as fast as g(n). Example: Linear search is Ω(1) in the best case.

Theta (Θ): Tight bound (average-case). f(n) = Θ(g(n)) means f(n) grows at the same rate as g(n). Example: Merge sort is Θ(n log n) in all cases.

Q3

Compare and contrast Divide and Conquer, Greedy, and Dynamic Programming paradigms.

Divide and Conquer: Breaks the problem into independent sub-problems, solves them recursively, and combines results. Example: Merge Sort.

Greedy: Makes locally optimal choices at each step without considering future consequences. Does not always give optimal solution. Example: Dijkstra's algorithm.

Dynamic Programming: Stores solutions to overlapping sub-problems to avoid recomputation. Always gives optimal solution if applicable. Example: Fibonacci with memoization.

Sub-problems Independent N/A Overlapping
Optimality Depends Not always Always

Q4

Explain time complexity and space complexity with examples.

Time Complexity: Measures how running time grows with input size n. It counts the number of basic operations.

Example: A single loop from 1 to n has time complexity O(n). Nested loops each running n times have O(n²).

Space Complexity: Measures how memory usage grows with input size n. It includes input space and auxiliary space.

Example: An algorithm using an array of size n has space complexity O(n). An algorithm using only a few variables has O(1) space.

Trade-off: Sometimes we use more memory to reduce time (e.g., Dynamic Programming).

Q5

What is an Abstract Data Type? Explain with examples of Stack and Queue.

Abstract Data Type (ADT): A mathematical model for data types defined by the data it holds and the operations that can be performed, without specifying implementation.

Stack ADT:

  • Data: Collection of elements
  • Operations: push(), pop(), peek(), isEmpty()
  • Principle: LIFO (Last In First Out)
  • Example: Function call stack

Queue ADT:

  • Data: Collection of elements
  • Operations: enqueue(), dequeue(), front(), isEmpty()
  • Principle: FIFO (First In First Out)
  • Example: Task scheduling

Both can be implemented using arrays or linked lists without changing the ADT interface.

Practice Problems

Q1

Calculate the time complexity of the following code:

for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        print(i, j);
    }
}
Analysis

Outer loop: Runs n times (i = 0 to n-1)

Inner loop: Runs i times for each i

Total iterations: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2

Time Complexity: O(n²)

Q2

Determine the time complexity of binary search.

Binary Search Algorithm:

  • Each iteration divides the search space in half
  • If n elements, after 1 iteration → n/2 elements remain
  • After 2 iterations → n/4 elements remain
  • After k iterations → n/2ᵏ elements remain
  • Stop when n/2ᵏ = 1, i.e., 2ᵏ = n, so k = log₂(n)

Time Complexity: O(log n)

Space Complexity: O(1) for iterative, O(log n) for recursive (call stack)

Q3

Perform the following Stack operations and show the final state:

push(5), push(10), push(15), pop(), push(20), pop(), peek()

Step-by-step Trace
Initial: Stack = []
push(5):  Stack = [5]
push(10): Stack = [5, 10]
push(15): Stack = [5, 10, 15] ← top
pop():    Returns 15, Stack = [5, 10]
push(20): Stack = [5, 10, 20] ← top
pop():    Returns 20, Stack = [5, 10]
peek():   Returns 10 (not removed), Stack = [5, 10]

Final State: Stack = [5, 10], peek() returns 10

Q4

Calculate the complexity of the following code:

int i = 1;
while (i <= n) {
    print(i);
    i = i * 3;
}
Analysis

Loop iterations: i = 1, 3, 9, 27, ..., 3ᵏ

Stops when: 3ᵏ > n, i.e., k > log₃(n)

Number of iterations: k = log₃(n)

Time Complexity: O(log n)

(Base of logarithm doesn't matter in Big-O notation)

Q5

Prove that 3n² + 5n + 10 = O(n²).

Given: f(n) = 3n² + 5n + 10

To prove: f(n) = O(n²)

Proof:

  • For n ≥ 1: 5n ≤ 5n²
  • For n ≥ 1: 10 ≤ 10n²
  • Therefore: f(n) = 3n² + 5n + 10 ≤ 3n² + 5n² + 10n² = 18n²
  • So f(n) ≤ 18 · n² for all n ≥ 1

Conclusion: By definition of Big-O, f(n) = O(n²) with c = 18 and n₀ = 1.

Quick Revision

Quick Revision Points
  • Algorithm: Well-defined computational procedure with input, output, and finite steps
  • Five Characteristics: Finiteness, Definiteness, Input, Output, Effectiveness (FDIOE)
  • ADT: Mathematical model defining data and operations without implementation
  • Set: Distinct elements, no duplicates; Multiset: Allows duplicates
  • Stack: LIFO (Last In First Out) - push, pop, peek
  • Queue: FIFO (First In First Out) - enqueue, dequeue, front
  • Big-O (O): Upper bound (worst-case), f(n) ≤ c·g(n)
  • Omega (Ω): Lower bound (best-case), f(n) ≥ c·g(n)
  • Theta (Θ): Tight bound (average-case), c₁·g(n) ≤ f(n) ≤ c₂·g(n)
  • Time Complexity: Growth of running time with input size
  • Space Complexity: Growth of memory usage with input size
  • Common Complexities: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
  • Divide & Conquer: Split, solve, combine - independent sub-problems
  • Greedy: Local optimal choices - not always globally optimal
  • Dynamic Programming: Store solutions - overlapping sub-problems
  • Single loop n times: O(n)
  • Nested loops n×n: O(n²)
  • Halving each time: O(log n)
Must Remember for Exam
  • Able to identify which characteristic is violated in a given procedure
  • Calculate time complexity by analyzing loops (single → O(n), nested → O(n²), halving → O(log n))
  • Differentiate Big-O (worst), Omega (best), Theta (average)
  • Stack vs Queue: LIFO vs FIFO
  • Divide & Conquer vs Greedy vs DP differences
  • Prove complexity using Big-O definition
  • Trace Stack/Queue operations step-by-step
  • Identify ADT characteristics (data + operations, no implementation)
Common Mistakes to Avoid
  • Confusing O(n) with O(log n) - log n is much faster
  • Forgetting to drop constants and lower-order terms in Big-O
  • Mixing up Stack (LIFO) and Queue (FIFO) principles
  • Thinking Greedy always gives optimal solution - it doesn't!
  • Ignoring space complexity - it's as important as time complexity
  • Not understanding that ADT is about WHAT, not HOW
  • Confusing best-case (Ω) with worst-case (O)
  • Counting iterations incorrectly in loops (especially nested loops)
