Overview

What is this unit about?

The Sorting Problem

Formal Definition

Input: A sequence of n numbers ⟨a₁, a₂, ..., aₙ⟩.

Output: A permutation (reordering) ⟨a'₁, a'₂, ..., a'ₙ⟩ such that a'₁ ≤ a'₂ ≤ ... ≤ a'ₙ.

Key Properties of Sorting Algorithms
  • Stable: Preserves the relative order of equal elements. Example: Merge Sort, Bubble Sort, Insertion Sort, Count Sort.
  • Unstable: May not preserve relative order. Example: Quick Sort, Heap Sort, Selection Sort.
  • In-place: Uses O(1) extra memory. Example: Bubble, Selection, Insertion, Heap Sort.
  • Not in-place: Uses O(n) extra memory. Example: Merge Sort, Count Sort.
  • Comparison-based: Sorts by comparing elements. Lower bound is Ω(n log n). Example: All elementary and efficient sorts.
  • Non-comparison-based: Does not compare elements directly. Can beat Ω(n log n). Example: Count Sort, Radix Sort, Bucket Sort.
Theoretical Lower Bound

Any comparison-based sorting algorithm requires at least Ω(n log n) comparisons in the worst case. This is proven using decision trees. This is why Merge Sort, Quick Sort (avg), and Heap Sort are considered optimal among comparison sorts.

Elementary Sorting Algorithms

1. Bubble Sort

Concept

Repeatedly compare adjacent elements and swap them if they are in the wrong order. After each pass, the largest unsorted element "bubbles up" to its correct position. Perform n-1 passes total.

Pseudocode: Bubble Sort
BUBBLE-SORT(A, n)
  for i = 0 to n-2
    swapped = false
    for j = 0 to n-2-i
      if A[j] > A[j+1]
        swap(A[j], A[j+1])
        swapped = true
    if swapped == false
      break   // Array already sorted — optimization
Trace: A = [64, 34, 25, 12]
Pass 1: [34, 25, 12, 64] — 64 bubbles to end
Pass 2: [25, 12, 34, 64] — 34 in place
Pass 3: [12, 25, 34, 64] — 25 in place
Result: [12, 25, 34, 64] ✅
Complexity: Bubble Sort
  • Best Case: O(n) — array already sorted, only 1 pass needed (with swapped flag).
  • Average Case: O(n²)
  • Worst Case: O(n²) — array in reverse order, all swaps happen.
  • Space: O(1) — in-place.
  • Stable: Yes (equal elements are not swapped).

2. Selection Sort

Concept

Divide the array into a sorted part (left) and an unsorted part (right). In each pass, find the minimum element in the unsorted part and swap it with the first unsorted element.

Pseudocode: Selection Sort
SELECTION-SORT(A, n)
  for i = 0 to n-2
    minIdx = i
    for j = i+1 to n-1
      if A[j] < A[minIdx]
        minIdx = j
    if minIdx != i
      swap(A[i], A[minIdx])
Trace: A = [64, 25, 12, 22]
Pass 1: Min=12 at idx 2 → swap with idx 0 → [12, 25, 64, 22]
Pass 2: Min=22 at idx 3 → swap with idx 1 → [12, 22, 64, 25]
Pass 3: Min=25 at idx 3 → swap with idx 2 → [12, 22, 25, 64]
Result: [12, 22, 25, 64] ✅
Complexity: Selection Sort
  • Best Case: O(n²) — always scans entire unsorted portion.
  • Average Case: O(n²)
  • Worst Case: O(n²)
  • Space: O(1) — in-place.
  • Stable: No (swapping may change relative order).
  • Note: Makes at most n-1 swaps — good when swaps are expensive.

3. Insertion Sort

Concept

Build a sorted array one element at a time. For each element, find its correct position in the sorted portion and insert it there by shifting larger elements to the right. Similar to how you sort playing cards in your hand.

Pseudocode: Insertion Sort
INSERTION-SORT(A, n)
  for i = 1 to n-1
    key = A[i]
    j = i - 1
    while j >= 0 and A[j] > key
      A[j+1] = A[j]
      j = j - 1
    A[j+1] = key
Trace: A = [5, 2, 4, 1]
i=1: key=2, shift 5 right → [2, 5, 4, 1]
i=2: key=4, shift 5 right → [2, 4, 5, 1]
i=3: key=1, shift 5,4,2 right → [1, 2, 4, 5]
Result: [1, 2, 4, 5] ✅
Complexity: Insertion Sort
  • Best Case: O(n) — array already sorted, inner while loop never executes.
  • Average Case: O(n²)
  • Worst Case: O(n²) — reverse sorted array, maximum shifts.
  • Space: O(1) — in-place.
  • Stable: Yes.
  • Best for: Small arrays or nearly-sorted arrays.

4. Shell Sort

Concept

An improved version of Insertion Sort. Instead of comparing adjacent elements, compare elements separated by a gap. Start with a large gap, reduce the gap each pass, and finally perform a standard insertion sort (gap=1). This moves elements faster to their correct positions.

Gap sequence (Shell's original): n/2, n/4, ..., 1

Pseudocode: Shell Sort
SHELL-SORT(A, n)
  gap = n / 2
  while gap > 0
    for i = gap to n-1
      temp = A[i]
      j = i
      while j >= gap and A[j - gap] > temp
        A[j] = A[j - gap]
        j = j - gap
      A[j] = temp
    gap = gap / 2
Trace: A = [8, 3, 6, 1, 5], gap=2 then gap=1
gap=2: Compare positions 0&2, 1&3, 2&4 → [6, 1, 8, 3, 5] → partial ordering
gap=1: Standard insertion sort on nearly-sorted array → [1, 3, 5, 6, 8]
Result: [1, 3, 5, 6, 8] ✅
Complexity: Shell Sort
  • Best Case: O(n log n)
  • Average Case: O(n^1.5) or O(n log² n) depending on gap sequence.
  • Worst Case: O(n²) with Shell's original gap; O(n log² n) with Hibbard's gap.
  • Space: O(1) — in-place.
  • Stable: No.

Efficient Sorting Algorithms

1. Merge Sort

Concept

A classic Divide and Conquer algorithm. Divide the array into two halves, recursively sort each half, then merge the two sorted halves. The merge step is the key operation that combines two sorted arrays into one sorted array in O(n) time.

Pseudocode: Merge Sort
MERGE-SORT(A, left, right)
  if left < right
    mid = (left + right) / 2
    MERGE-SORT(A, left, mid)
    MERGE-SORT(A, mid+1, right)
    MERGE(A, left, mid, right)

MERGE(A, left, mid, right)
  n1 = mid - left + 1
  n2 = right - mid
  Create arrays L[0..n1] and R[0..n2]
  Copy A[left..mid] to L[]
  Copy A[mid+1..right] to R[]
  i = 0, j = 0, k = left
  while i < n1 and j < n2
    if L[i] <= R[j]: A[k++] = L[i++]
    else: A[k++] = R[j++]
  Copy remaining L[] or R[] elements to A[]
Trace: A = [38, 27, 43, 3]
Divide: [38,27] and [43,3]
Divide: [38],[27] and [43],[3]
Merge: [27,38] and [3,43]
Merge: Compare 27&3 → 3; 27&43 → 27; 38&43 → 38; 43 remaining
Result: [3, 27, 38, 43] ✅
Complexity: Merge Sort
  • Recurrence: T(n) = 2T(n/2) + O(n)
  • Best Case: O(n log n)
  • Average Case: O(n log n)
  • Worst Case: O(n log n) — consistent for all inputs.
  • Space: O(n) — needs extra array for merging.
  • Stable: Yes.
  • Best for: Linked lists, external sorting, when stability is needed.

2. Quick Sort

Concept

A Divide and Conquer algorithm that selects a pivot element and partitions the array into two sub-arrays: elements less than pivot (left) and elements greater than pivot (right). Then recursively sorts each sub-array. The partition step rearranges elements in O(n) time.

Pivot selection strategies: First element, Last element, Random element, Median-of-three.

Pseudocode: Quick Sort (Lomuto partition)
QUICK-SORT(A, low, high)
  if low < high
    pi = PARTITION(A, low, high)
    QUICK-SORT(A, low, pi-1)
    QUICK-SORT(A, pi+1, high)

PARTITION(A, low, high)
  pivot = A[high]
  i = low - 1
  for j = low to high-1
    if A[j] <= pivot
      i = i + 1
      swap(A[i], A[j])
  swap(A[i+1], A[high])
  return i + 1
Trace: A = [10, 7, 8, 9, 1, 5], pivot=5 (last)
Partition: Elements ≤ 5: {1,5}, Elements > 5: {10,7,8,9}
After partition: [1, 5, 10, 7, 8, 9] — pivot 5 at index 1
Recurse left: [1] — sorted
Recurse right: [10,7,8,9] → partition → [7,8,9,10]
Result: [1, 5, 7, 8, 9, 10] ✅
Complexity: Quick Sort
  • Recurrence (avg): T(n) = 2T(n/2) + O(n) → O(n log n)
  • Best Case: O(n log n) — pivot always divides array equally.
  • Average Case: O(n log n)
  • Worst Case: O(n²) — pivot is always min or max (sorted/reverse-sorted array).
  • Space: O(log n) average for recursion stack; O(n) worst case.
  • Stable: No.
  • Best for: General-purpose, in-memory sorting — fastest in practice despite O(n²) worst case.
Worst Case of Quick Sort

When the pivot always picks the smallest or largest element (e.g., array already sorted and pivot = last element), Quick Sort degrades to O(n²). This is why randomized pivot selection or median-of-three is used in practice.

3. Heap Sort

Concept

Uses a Binary Max-Heap data structure. A max-heap is a complete binary tree where every parent node is ≥ its children. Heap Sort works in two phases:

  1. Build Max-Heap: Convert array into a max-heap in O(n) time.
  2. Extract Max Repeatedly: Swap root (max) with last element, reduce heap size, call Heapify to restore heap property. Repeat n-1 times.
Pseudocode: Heap Sort
HEAPIFY(A, n, i)
  largest = i
  left = 2*i + 1
  right = 2*i + 2
  if left < n and A[left] > A[largest]: largest = left
  if right < n and A[right] > A[largest]: largest = right
  if largest != i
    swap(A[i], A[largest])
    HEAPIFY(A, n, largest)

HEAP-SORT(A, n)
  // Build max heap
  for i = n/2 - 1 downto 0
    HEAPIFY(A, n, i)
  // Extract elements
  for i = n-1 downto 1
    swap(A[0], A[i])
    HEAPIFY(A, i, 0)
Trace: A = [4, 10, 3, 5, 1]
Build Max-Heap: [10, 5, 3, 4, 1]
Extract 1: Swap 10↔1 → [1,5,3,4,10] → Heapify → [5,4,3,1,10]
Extract 2: Swap 5↔1 → [1,4,3,5,10] → Heapify → [4,1,3,5,10]
Extract 3: Swap 4↔3 → [3,1,4,5,10] → Heapify → [3,1,4,5,10]
Extract 4: Swap 3↔1 → [1,3,4,5,10]
Result: [1, 3, 4, 5, 10] ✅
Complexity: Heap Sort
  • Build Heap: O(n)
  • Each Heapify: O(log n)
  • Best Case: O(n log n)
  • Average Case: O(n log n)
  • Worst Case: O(n log n) — guaranteed.
  • Space: O(1) — in-place (no extra array needed).
  • Stable: No.
  • Best for: When O(n log n) worst-case and O(1) space are both required.

Linear Time Sorting Algorithms

Why Linear Time?

These algorithms are non-comparison-based. They exploit additional structure in the input (e.g., integer keys within a range). They can sort in O(n) or O(n+k) time, beating the Ω(n log n) lower bound for comparison sorts. The trade-off is they work only for specific input types.

1. Count Sort (Counting Sort)

Concept

For integer keys in range [0, k]: Count the frequency of each key, compute cumulative counts (prefix sums) to determine the position of each element in the output array, then place elements in their correct positions.

Requirement: Integer keys in known range [0, k].

Pseudocode: Count Sort
COUNT-SORT(A, n, k)
  Create count array C[0..k] initialized to 0
  // Step 1: Count frequencies
  for i = 0 to n-1: C[A[i]]++
  // Step 2: Prefix sums
  for i = 1 to k: C[i] += C[i-1]
  // Step 3: Build output
  Create output array B[0..n-1]
  for i = n-1 downto 0
    B[C[A[i]] - 1] = A[i]
    C[A[i]]--
  Copy B to A
Trace: A = [4, 2, 2, 8, 3, 3, 1], k=8
Count: C = [0,1,2,2,1,0,0,0,1] (index = value)
Prefix: C = [0,1,3,5,6,6,6,6,7]
Output: B = [1, 2, 2, 3, 3, 4, 8]
Result: [1, 2, 2, 3, 3, 4, 8] ✅
Complexity: Count Sort
  • Time: O(n + k) where n = number of elements, k = range of values.
  • Space: O(n + k) — extra arrays needed.
  • Stable: Yes (when implemented with backward pass).
  • Limitation: Only for integer keys; if k is large, space is wasted.

2. Radix Sort

Concept

Sort numbers digit by digit, from the least significant digit (LSD) to the most significant digit (MSD). Uses a stable sort (Count Sort) as a subroutine at each digit position. After d passes (one per digit), the array is fully sorted.

LSD Radix Sort: Process from rightmost digit to leftmost. More common.

MSD Radix Sort: Process from leftmost digit. Useful for strings.

Pseudocode: Radix Sort (LSD)
RADIX-SORT(A, n, d)
  // d = number of digits
  for i = 1 to d
    Use COUNT-SORT to sort A on digit i
    // (using 10 buckets for decimal digits)
Trace: A = [170, 45, 75, 90, 802, 24, 2, 66]
Sort by ones digit: [170, 90, 802, 2, 24, 45, 75, 66]
Sort by tens digit: [802, 2, 24, 45, 66, 170, 75, 90]
Sort by hundreds digit: [2, 24, 45, 66, 75, 90, 170, 802]
Result: [2, 24, 45, 66, 75, 90, 170, 802] ✅
Complexity: Radix Sort
  • Time: O(d × (n + k)) where d = digits, k = base (10 for decimal).
  • If d is constant: O(n).
  • Space: O(n + k).
  • Stable: Yes (uses stable Count Sort internally).

3. Bucket Sort

Concept

Distribute n elements into n buckets based on their value range. Sort each bucket individually (using insertion sort or any stable sort), then concatenate all buckets. Works best when input is uniformly distributed over [0, 1).

Pseudocode: Bucket Sort
BUCKET-SORT(A, n)
  Create n empty buckets B[0..n-1]
  for i = 0 to n-1
    Insert A[i] into bucket B[floor(n * A[i])]
  for i = 0 to n-1
    Sort bucket B[i] using insertion sort
  Concatenate B[0], B[1], ..., B[n-1] into A
Complexity: Bucket Sort
  • Best/Average Case: O(n) — uniform distribution, each bucket has ~1 element.
  • Worst Case: O(n²) — all elements in one bucket → degrades to insertion sort.
  • Space: O(n + k) where k = number of buckets.
  • Stable: Yes (if stable sort used within buckets).

Which Sort to Use When?
  • Small n or nearly sorted: Insertion Sort.
  • Guaranteed O(n log n), stable: Merge Sort.
  • Fastest in practice, general: Quick Sort (with random pivot).
  • O(n log n) worst-case + in-place: Heap Sort.
  • Integer keys, small range: Count Sort.
  • Large integers, fixed digits: Radix Sort.
  • Uniformly distributed floats [0,1): Bucket Sort.

Key Definitions

All Key Terms
  • Sorting: Rearranging elements of a sequence in a specific (ascending/descending) order.
  • Stable Sort: Preserves relative order of equal elements.
  • In-place Sort: Requires O(1) auxiliary space.
  • Comparison Sort: Determines order only by comparing pairs of elements.
  • Bubble Sort: Repeatedly swaps adjacent elements until sorted.
  • Selection Sort: Finds minimum and places at the beginning each pass.
  • Insertion Sort: Inserts each element into its correct position in the sorted portion.
  • Shell Sort: Insertion sort with decreasing gap sequence.
  • Merge Sort: Divide-and-conquer sort with stable O(n log n) performance.
  • Quick Sort: Partition-based divide-and-conquer; fastest in practice.
  • Pivot: The element chosen to partition the array in Quick Sort.
  • Heap Sort: Sorting using a binary max-heap; O(n log n) guaranteed.
  • Max-Heap: A complete binary tree where every parent ≥ its children.
  • Heapify: Restoring heap property at a node — O(log n).
  • Count Sort: Non-comparison sort using frequency counting; O(n+k).
  • Radix Sort: Sorts digit by digit using a stable subroutine; O(d(n+k)).
  • Bucket Sort: Distributes elements into buckets then sorts each bucket.
  • LSD Radix Sort: Processes digits from least significant to most significant.
  • MSD Radix Sort: Processes digits from most significant to least significant.

Multiple Choice Questions

Q 1

Which sorting algorithm has the best average-case time complexity?

  • a. Bubble Sort
  • b. Selection Sort
  • c. Merge Sort
  • d. Insertion Sort
Answer: c. Merge Sort

Merge Sort has O(n log n) average-case complexity. Bubble, Selection, and Insertion Sort all have O(n²) average case.

Q 2

What is the worst-case time complexity of Quick Sort?

  • a. O(n log n)
  • b. O(n)
  • c. O(n²)
  • d. O(log n)
Answer: c. O(n²)

Quick Sort degrades to O(n²) when the pivot is always the smallest or largest element (e.g., sorted array with last-element pivot).

Q 3

Which sorting algorithm is stable AND in-place?

  • a. Merge Sort
  • b. Heap Sort
  • c. Insertion Sort
  • d. Quick Sort
Answer: c. Insertion Sort

Insertion Sort is both stable (preserves order of equal elements) and in-place (O(1) extra space). Merge Sort is stable but not in-place; Heap Sort and Quick Sort are in-place but not stable.

Q 4

What is the time complexity of building a max-heap from an unsorted array of n elements?

  • a. O(n log n)
  • b. O(n)
  • c. O(log n)
  • d. O(n²)
Answer: b. O(n)

Building a heap using the bottom-up approach (calling Heapify on all non-leaf nodes) takes O(n) time, not O(n log n).

Q 5

Which sorting algorithm's best case is O(n)?

  • a. Selection Sort
  • b. Merge Sort
  • c. Bubble Sort
  • d. Heap Sort
Answer: c. Bubble Sort

With the "swapped" flag optimization, Bubble Sort detects an already-sorted array in one pass → O(n) best case. Insertion Sort also achieves O(n) best case. Selection Sort always does O(n²).

Q 6

Count Sort can sort n integers in range [0, k] in:

  • a. O(n log n)
  • b. O(n²)
  • c. O(n + k)
  • d. O(k log k)
Answer: c. O(n + k)

Count Sort runs in O(n + k) time and space, where n is the number of elements and k is the maximum value.

Q 7

Radix Sort sorts numbers digit by digit starting from:

  • a. Most significant digit (MSD)
  • b. Least significant digit (LSD)
  • c. Middle digit
  • d. Random digit
Answer: b. Least significant digit (LSD)

The standard LSD Radix Sort processes from the rightmost (least significant) digit to the leftmost (most significant) digit, using a stable sort at each pass.

Q 8

Which of the following is NOT a stable sorting algorithm?

  • a. Merge Sort
  • b. Bubble Sort
  • c. Heap Sort
  • d. Insertion Sort
Answer: c. Heap Sort

Heap Sort is NOT stable. The heap operations can change the relative order of equal elements. Merge Sort, Bubble Sort, and Insertion Sort are all stable.

Q 9

What is the main advantage of Merge Sort over Quick Sort?

  • a. Uses less memory
  • b. Faster in practice
  • c. Guaranteed O(n log n) worst case
  • d. In-place sorting
Answer: c. Guaranteed O(n log n) worst case

Merge Sort always runs in O(n log n) in all cases. Quick Sort has O(n²) worst case. However, Quick Sort uses less space (O(log n) vs O(n)) and is faster in practice.

Q 10

Shell Sort is an improvement over which sorting algorithm?

  • a. Bubble Sort
  • b. Selection Sort
  • c. Insertion Sort
  • d. Merge Sort
Answer: c. Insertion Sort

Shell Sort is an extension of Insertion Sort. It uses a diminishing gap sequence to move elements farther in fewer steps before performing a final Insertion Sort pass (gap=1).

Q 11

The theoretical lower bound for any comparison-based sorting algorithm is:

  • a. O(n)
  • b. Ω(n log n)
  • c. O(n²)
  • d. Ω(n²)
Answer: b. Ω(n log n)

Any comparison-based sorting algorithm requires at least Ω(n log n) comparisons in the worst case. This is proven using a decision tree argument — there are n! possible permutations and a binary tree of height h can have at most 2ʰ leaves, so h ≥ log₂(n!) = Ω(n log n).

Q 12

Bucket Sort works best when the input is:

  • a. Already sorted
  • b. In reverse order
  • c. Uniformly distributed over a range
  • d. All same values
Answer: c. Uniformly distributed over a range

Bucket Sort achieves O(n) average case when elements are uniformly distributed — each bucket gets approximately equal elements, making each bucket sort O(1).

Q 13

Which algorithm has guaranteed O(n log n) worst case AND O(1) space?

  • a. Merge Sort
  • b. Quick Sort
  • c. Heap Sort
  • d. Shell Sort
Answer: c. Heap Sort

Heap Sort guarantees O(n log n) in all cases (best, average, worst) and sorts in-place using O(1) extra space. Merge Sort needs O(n) space; Quick Sort has O(n²) worst case.

Q 14

In Quick Sort, the worst case occurs when:

  • a. Array is random
  • b. Pivot always divides array equally
  • c. Pivot is always the median
  • d. Pivot is always the smallest or largest element
Answer: d. Pivot is always the smallest or largest element

When pivot is always min or max, partitioning produces one sub-array of size n-1 and one of size 0. This gives T(n) = T(n-1) + O(n) → O(n²). This happens with sorted arrays when pivot = last element.

Q 15

Which of the following sorting algorithms can sort in O(n) time?

  • a. Merge Sort
  • b. Quick Sort
  • c. Insertion Sort
  • d. Count Sort
Answer: d. Count Sort

Count Sort is a non-comparison-based sort that runs in O(n + k) time — effectively O(n) when k is constant. Comparison-based sorts like Merge, Quick, and Insertion Sort cannot do better than Ω(n log n) in the worst case.

Short Answer Questions

Q 1

What is a stable sorting algorithm? Give two examples.

A stable sorting algorithm preserves the relative order of elements with equal keys. If two elements A[i] and A[j] have the same value and i < j before sorting, then A[i] will still appear before A[j] after sorting.

Examples: Merge Sort, Insertion Sort, Bubble Sort, Count Sort.

Q 2

Why is Quick Sort preferred in practice despite having O(n²) worst case?

Quick Sort is preferred because:

  • Its average case is O(n log n) with a very small constant factor.
  • It is in-place (O(log n) space) — good cache performance.
  • With randomized pivot, worst case is extremely unlikely.
  • In practice, it outperforms Merge Sort and Heap Sort on most inputs.

Q 3

What is the difference between in-place and not-in-place sorting?

In-place sort: Uses O(1) extra memory — sorts within the original array. Examples: Bubble, Selection, Insertion, Heap, Quick Sort.

Not in-place: Uses O(n) or more extra memory — creates additional arrays. Examples: Merge Sort (needs O(n) temp array), Count Sort (needs count + output arrays).

Q 4

What is the role of the pivot in Quick Sort?

The pivot is a chosen element used to partition the array into two sub-arrays:

  • Elements less than or equal to pivot → left sub-array.
  • Elements greater than pivot → right sub-array.

After partitioning, the pivot is in its final sorted position. The sub-arrays are then recursively sorted.

Q 5

Why can't Count Sort be used for sorting floating-point numbers?

Count Sort requires integer keys in a known finite range [0, k] to index into the counting array. Floating-point numbers:

  • Are not integers — cannot be used as array indices directly.
  • Can have an infinite range — the counting array would be impractical.

For floating-point numbers uniformly in [0,1), Bucket Sort is used instead.

Q 6

State the recurrence relation for Merge Sort and solve it.

Recurrence: T(n) = 2T(n/2) + Θ(n)

Solving using Master Theorem:

  • a = 2, b = 2, f(n) = Θ(n)
  • n^(log_b a) = n^(log₂ 2) = n^1 = n
  • f(n) = Θ(n) = Θ(n^log_b a) → Case 2
  • T(n) = Θ(n log n)

Q 7

What is the difference between LSD and MSD Radix Sort?

LSD (Least Significant Digit): Starts sorting from the rightmost digit to the leftmost. Simpler to implement, used for fixed-length integers.

MSD (Most Significant Digit): Starts from the leftmost digit. Naturally handles variable-length strings. More complex — requires recursive processing of sub-groups.

Q 8

Why is Selection Sort considered better than Bubble Sort when swaps are expensive?

Selection Sort makes at most n-1 swaps (one per pass — swaps minimum to front). Bubble Sort can make up to O(n²) swaps (swaps every adjacent pair that is out of order). When swaps are costly (e.g., writing to flash memory), Selection Sort is more efficient.

Q 9

What is a max-heap? State the heap property.

A max-heap is a complete binary tree where every node is greater than or equal to its children.

Max-heap property: A[parent(i)] ≥ A[i] for every node i.

The root always contains the maximum element. This property enables Heap Sort to extract the maximum in O(log n) time, repeated n times → O(n log n) total.

Q 10

In what scenario does Insertion Sort outperform Merge Sort?

Insertion Sort outperforms Merge Sort when:

  • The array is small (n < ~10-20) — constant factors dominate.
  • The array is nearly sorted — Insertion Sort approaches O(n) while Merge Sort always does O(n log n).

This is why many real implementations (e.g., Python's Timsort) use Insertion Sort for small sub-arrays within a larger Merge Sort framework.

Long Answer Questions

Q 1

Explain Merge Sort with algorithm, example trace on [38, 27, 43, 3, 9, 82, 10], and complete complexity analysis.

Merge Sort is a divide-and-conquer algorithm that splits the array into halves, recursively sorts them, and merges the sorted halves.

Steps
  1. Divide: Split array at midpoint into left and right halves.
  2. Conquer: Recursively sort each half (base case: size 1).
  3. Combine: Merge two sorted halves into one sorted array by comparing elements.
Trace: [38, 27, 43, 3, 9, 82, 10]
Split: [38,27,43,3] | [9,82,10]
Split: [38,27] [43,3] | [9,82] [10]
Split: [38][27] [43][3] | [9][82] [10]
Merge: [27,38] [3,43] | [9,82] [10]
Merge: [3,27,38,43] | [9,10,82]
Final Merge: [3,9,10,27,38,43,82] ✅
Complexity Analysis
  • Recurrence: T(n) = 2T(n/2) + O(n)
  • By Master Theorem (Case 2): T(n) = Θ(n log n)
  • Best/Avg/Worst: All O(n log n) — consistent.
  • Space: O(n) for temporary merge array.
  • Stable: Yes.

Q 2

Explain Quick Sort with Lomuto partition scheme. Trace on [10, 80, 30, 90, 40, 50, 70]. Analyze best, average, worst case complexity.

Quick Sort selects a pivot, partitions the array so all elements less than pivot come before it and all greater elements come after it, then recursively sorts sub-arrays.

Trace: A=[10,80,30,90,40,50,70], pivot=70 (last)
Partition: i starts at -1. Scan j=0 to 5: 10≤70→swap(i=0,j=0):[10,...], 80>70 skip, 30≤70→swap(i=1,j=2):[10,30,80,90,40,50,70], 90>70 skip, 40≤70→i=2,swap:[10,30,40,90,80,50,70], 50≤70→i=3,swap:[10,30,40,50,80,90,70]
Place pivot: swap(A[4],A[6]) → [10,30,40,50,70,90,80], pivot at index 4
Recurse: Left=[10,30,40,50] → sorted. Right=[90,80] → [80,90]
Result: [10, 30, 40, 50, 70, 80, 90] ✅
Complexity
  • Best Case: O(n log n) — pivot always splits array in half.
  • Average Case: O(n log n) — random pivot, expected equal splits.
  • Worst Case: O(n²) — sorted array with last-element pivot → T(n)=T(n-1)+O(n).
  • Space: O(log n) avg, O(n) worst (recursion stack).

Q 4

Explain Heap Sort with algorithm. Trace on A=[4,10,3,5,1]. What is the time and space complexity?

Heap Sort uses a binary max-heap. Works in two phases: Build Max-Heap, then repeatedly extract maximum.

Trace: A=[4,10,3,5,1]
Build Max-Heap: Start from i=1 (floor(5/2)-1). Heapify(1): 10 vs 5,1 → 10 ok. Heapify(0): 4 vs 10,3 → swap 4,10 → [10,4,3,5,1] → Heapify(1): 4 vs 5,1 → swap → [10,5,3,4,1]
Max-Heap: [10, 5, 3, 4, 1]
Extract 1: Swap A[0]↔A[4] → [1,5,3,4,10] → Heapify(4) → [5,4,3,1,10]
Extract 2: Swap A[0]↔A[3] → [1,4,3,5,10] → Heapify(3) → [4,1,3,5,10]
Extract 3: Swap A[0]↔A[2] → [3,1,4,5,10] → Heapify(2) → [3,1,4,5,10]
Extract 4: Swap A[0]↔A[1] → [1,3,4,5,10]
Result: [1, 3, 4, 5, 10] ✅
Complexity
  • Build Heap: O(n)
  • n-1 Heapify calls: O(n log n)
  • Total — Best/Avg/Worst: O(n log n)
  • Space: O(1) — in-place.

Revision

Quick Revision Points
  • Bubble Sort: Swap adjacent; O(n²) worst, O(n) best (with flag); stable; in-place.
  • Selection Sort: Find min, place at front; always O(n²); NOT stable; in-place; ≤ n-1 swaps.
  • Insertion Sort: Insert each into sorted portion; O(n²) worst, O(n) best; stable; in-place. Best for small/nearly sorted.
  • Shell Sort: Insertion with gap; better than O(n²); NOT stable; in-place.
  • Merge Sort: Divide-conquer; always O(n log n); stable; NOT in-place (O(n) space).
  • Quick Sort: Pivot-partition; O(n log n) avg, O(n²) worst; NOT stable; in-place. Fastest in practice.
  • Heap Sort: Max-heap; always O(n log n); NOT stable; in-place (O(1) space). Build heap: O(n).
  • Count Sort: Integer keys; O(n+k); stable; NOT in-place. Limited to integers.
  • Radix Sort: Digit by digit; O(d(n+k)); stable; NOT in-place.
  • Bucket Sort: Distribute to buckets; O(n) avg, O(n²) worst; stable; NOT in-place.
  • Comparison sorts: lower bound Ω(n log n).
  • Non-comparison sorts can beat Ω(n log n) but need special input types.
  • Heap parent: ⌊(i-1)/2⌋; left child: 2i+1; right child: 2i+2.
  • Merge Sort recurrence: T(n) = 2T(n/2) + O(n) → O(n log n).
Must Remember for Exam
  • Only Merge Sort is stable AND O(n log n) — but uses O(n) space.
  • Only Heap Sort is O(n log n) worst-case AND in-place (O(1) space) — but NOT stable.
  • Quick Sort worst case is O(n²) — occurs on sorted array with bad pivot.
  • Selection Sort always O(n²) even for sorted arrays — never improves.
  • Build heap = O(n), NOT O(n log n) — common exam trick question.
  • Comparison sort lower bound: Ω(n log n).
  • Count Sort time: O(n + k); Radix Sort: O(d(n+k)).
  • Bubble/Insertion best case: O(n); Selection best case: O(n²).
Common Mistakes in Exams
  • Saying Selection Sort best case is O(n) — it is ALWAYS O(n²).
  • Saying Merge Sort is in-place — it is NOT (needs O(n) extra space).
  • Saying Heap Sort is stable — it is NOT stable.
  • Forgetting that Quick Sort worst case is O(n²), not O(n log n).
  • Writing O(n log n) for building a heap — it's O(n).
  • Confusing LSD and MSD Radix Sort directions.
  • Applying Count Sort on floating-point numbers — it only works for integers.
  • Writing wrong complexity for Count Sort as O(n) — it is O(n + k).
