  1. Start here · Unit 3: Searching

    Why first? A short trace shows why the array must be sorted and how each step halves the search interval.

    What’s important

    • Check that the array is sorted. Show the midpoint and remaining interval, including a missing key.
    • Trace a hash collision before comparing chaining and probing. Practise one BST update separately.

    What to read first

    1. Binary search — follow the midpoint and boundary updates on a sorted array.
    2. Collision resolution — compare what happens to keys that map to the same slot.

    Try it

    Find 7 in [1, 3, 5, 7, 9]. Record each midpoint and the remaining interval. Then repeat for a missing key: 6.

    From the papers

    • January 2024 · Q6 · 8 marks total Write recursive binary search and explain why the input must be sorted.
    • March 2023 · Q8 · 8 marks total Explain hashing and compare collision-resolution techniques.

  2. Rank 2 · Unit 2: Sorting

    Why here? Simple sorts are quick to trace and well represented in the archive. Start with one array and reuse it before moving to pivot selection and non-comparison methods.

    What’s important

    • Trace bubble, selection and insertion passes. Mark what part of the array is already sorted.
    • Keep quicksort’s partition and merge sort’s merge separate. Explain why least-significant-digit radix sort needs stable digit passes.

    What to read first

    1. Elementary sorts — trace bubble, selection and insertion on the same small array.
    2. Merge, quick and heap sort — compare the intermediate steps and which bounds apply.

    Try it

    Bubble-sort [4, 3, 2, 1]. Write the array after each pass and underline the sorted suffix. Try selection sort on the same input.

    From the papers

    • January 2026 · Q4 · 8 marks total Write bubble sort and show the array after each pass.
    • January 2024 · Q3 · 8 marks total Trace selection sort and state its worst-case time complexity.
    Unit notes Practice questions

  3. Rank 3 · Unit 1: Fundamentals of Algorithms

    Why here? The definitions are quick, but search and sort traces give you more chances to practise a complete procedure. If you get stuck on the notation, use this unit as a warm-up.

    What’s important

    • State what the algorithm receives and produces. Distinguish time from extra space.
    • Name the input size and case before using Big O, Omega or Theta.

    What to read first

    1. Asymptotic notation — compare upper, lower and tight bounds on one function.
    2. Time and space complexity — count the loop steps before choosing a growth class.

    Try it

    With n = 20, count how often a loop runs if i starts at 1 and doubles while i ≤ n. Then count a loop that adds 1 instead. Name each growth rate.

    From the papers

    • December 2024 · Q2 · 8 marks total Explain algorithm characteristics and common asymptotic notations.
    • March 2023 · Q3 · 8 marks total Count iterations in a loop whose index doubles.
    Unit notes Practice questions

  4. Rank 4 · Unit 4: Graphs and Graph Algorithms

    Why here? Graph questions provide written practice, but shortest paths, minimum spanning trees and topological order solve different problems. Keep a separate trace for each.

    What’s important

    • State whether the goal is a spanning tree, a shortest path or a topological order.
    • Check edge assumptions before tracing. Record distance relaxations separately from MST edge choices.

    What to read first

    1. Minimum spanning trees — write down the edge choices in Prim or Kruskal and why each edge is allowed.
    2. Shortest paths — compare Dijkstra, Bellman–Ford and Floyd–Warshall by the problem they solve.

    Try it

    Use an undirected triangle with edge weights A–B = 3, B–C = 4 and A–C = 5. Trace Prim and Dijkstra from A. Compare the spanning-tree weight with the shortest A-to-C distance.

    From the papers

    • January 2024 · Q4 · 8 marks total Explain and trace Prim’s algorithm for a minimum spanning tree.
    • March 2023 · Q9 · 8 marks total Write Dijkstra’s algorithm and demonstrate the distance updates.

Last-minute checklist

Close your notes and check that you can do each of these.

  • Name the input size and case before writing a time bound.
  • Show passes for a sort, and test a binary search with an absent key.
  • Trace a BST update or a hash collision without notes.
  • Name the graph goal and edge assumptions before starting the trace.
